# 注释卫生

## 注释写什么

**注释只写代码作用与需要说明的东西：约束、不变量、语义、平台差、同步关系。** 不写来历与出处（这份代码从哪来、借鉴于哪），修复史归 git。

正例是「改这里要注意什么」：为什么必须在写锁内读、这个参数不能为空的原因、这份实现与平台 A 的差异、改了这里必须同步改哪里。反例是「这里以前是什么样」：某天改了什么、第几轮评审的决定、当时为什么先这样写。

修复史一旦住进注释就会漂移：行号失效、路径悬空、状态过期，而读注释的人无法分辨哪半截还成立。要判断一段话属于哪一类，问一句：**这句话会因为代码改变而撒谎吗？** 会，它是约束（随代码一起改）；不会，它是史（本该住在 git 与决策记录里）。

## 两族判据，缺一不可

**标签形态**：写进注释的编年史——日期戳、评审轮次、批次括注、修复批名。机器可判。

**切除后残形**：标签被删掉之后剩下的半截结构——括注被切空只剩破折号、序号与左括之间悬着破折号。只做标签族时，清理器把标签连同依附的括注一起删掉，残形不含任何标签，门会判定「干净」——历史上真实漏过两批（一批四十几处、一批五处）。所以要同时判「还写着标签」与「标签被切走后的残痕」：一族抓没清理的，一族抓清理坏的。

## 形态表的边界是实测出来的

哪些字符串算标签，不能靠推理定，要拿真实语料量：技术术语与标签同形是常态（引擎名、云产品名、数学记号、字体名里的十六进制串都撞过形）。任何「这种形态大概不会撞」的假设，都会在第一次全量扫描时被证伪。

撞形的真实术语进**显式例外表**，每条带理由；**不靠收窄判据面绕过**——判据面窄的代价是漏检，宽判据 + 例外表的代价是一次性登记。残形表同理：每一条都要有零误报边界。半角 `()` 不进残形表，因为注释里引用代码样例（`run()`）是内容不是残形；全角 `（）` 被切空才判。

## 字面量是红线

扫描器是逐字符状态机，**只读注释面**：字符串、模板串、正则字面量里的 `//` 与标签样文本一律不进判定。模板串里 `${}` 内的代码面是例外——那里又是代码，其中的注释照扫。

这条是红线不是洁癖：清理工具误删生产字面量是真实发生过的事故。门必须先保证「像标签的字面量永远不报」，否则第一次误报就会让人把门关掉。

**诚实边界**：正则字面量的识别靠前一个有效字符的启发式（表达式位置还是除法位置）。判错的后果是把该字面量当代码扫，最坏是漏报，不会误报；漏报由例外表与人工清理兜底。

## 例外与承重锚注

**例外表**：真实术语与形态撞形时登记 `match` + `reason`。理由必填——没有理由的豁免不是决策，是掩盖。

**承重锚注**（`anchors`）：某条注释被测试钉住（测试 `readFileSync` 源码、断言这条注释），删改即测试红。这类注释不进例外表而进锚注：登记「文件 + 行内容子串 + 钉住它的测试」，`pinnedBy` 必填。发现方法是反查测试面里 `readFileSync` 读源码的断言字面量，起步通常为零——机制在位即可。锚定之后改注释等于改契约：同步改测试，或承认这是债。

**两者都会陈旧**：例外不再命中、锚注不再被需要时，门每次运行都会报告并催你删掉。登记表只增不减，就会变成第二份注释史——它治的就是这个病。

## fail-closed：扫描面不可信就报红

扫描根不存在、根下零个可扫文件、目录不可读——都算错误并以退出码 1 收口，**且不得入债务台账**：台账记的是「内容违规」，不是「根本没看」。

「扫了 0 个文件仍通过」是假绿。一个什么都看不见的门比没有门更危险，因为它提供错误的安心。这条判据同样适用于其他扫描型门禁：拿不准就红。

## 与台账、与扫描面的配合

**内容违规（命中）是历史积累，走债务台账**：`bootstrap --adopt` 把既有命中记为已接受，门从此只拦新增；台账默认拒绝扩张。存量注释的清理因此可以是渐进的，而不是开门第一天就全红。

**扫描面是仓库数据**：写在 `scripts/harness/comment-hygiene.manifest.json`——`scan`（目录或文件）、`extensions`（可选，默认 JS/TS 家族）、`labels`、`residue`、`exceptions`、`anchors`；`{}` 表示本仓不带此门，manifest 缺失才是配置漏项。

**扫描面取「生产面 + 工具链面」**：门与清理器自身也在叙述面上；把 `scripts/` 排除在外时，该目录的注释密度长期无人对账。测试面按测试纪律族单独管（见 [test-reliability.md](test-reliability.md)），不放进默认表——两处同时管一个面，两边都会以为对方在看。
