## 一个事实一个家

每条规则、每个事实只在一个文件里定义，其他地方链接过去。重复的文本会分叉，分叉之后没人知道该信哪个。

写下一段话前先问：「这个事实已经住在哪了」。答案在别处就改写那里的原文，然后链接过来。

## 层级

| 层级 | 职责 | 不属于这里 |
|---|---|---|
| 根 `AGENTS.md` | 每次会话都需要在上下文里的标准指令，一条一到三行 | 故事、worked example、情境流程 |
| `<子树>/AGENTS.md` | 该子树的局部强制规则 | 全仓通用规则（链到根） |
| `docs/architecture.md` | 系统怎么组装、模块边界、运行时词汇 | 具体 API 签名（链到源码） |
| `docs/subsystems/` | 一个子系统的机制与生命周期 | 跨子系统的编排 |
| `.agents/notes/` | 为什么这么选、放弃了什么 | 迁移计划、验收清单（交付后） |
| `docs/cookbook/` | 怎么做一件具体的事 | 为什么这么设计 |
| `<包>/README.md` | 该包的职责、配置、公开行为、已知限制 | 全仓架构 |

## 字数预算

```sh
node scripts/harness/verify-doc-budgets.ts
node scripts/harness/verify-doc-budgets.ts --list
```

清单在 `scripts/harness/doc-budgets.manifest.json`。计数口径：空白分词，每个汉字另计一词——中文没有词边界，只数空白分词会让任何长度的中文文档都通过英文尺度的上限。

**超限的处理顺序是 迁移 → 精简 → 提高上限**，提高上限必须在同一个改动里给出理由。

上限是护栏不是削减目标：目标以内保留至少 5% 余量；已在目标以上就冻结上限。**上限过低是 bug。**

## 格式

**一段一个物理行。** 代码块、表格、列表保持自己的格式。

围栏代码块要能通过类型检查；粘贴的类型声明用 `ts type-equiv` 标记并注册。

## 不写什么

- 重复的规则（同一条出现在两处）
- 越界的沿革（「原先是 A 后来改成 B」→ 属于决策记录）
- 实现状态标注（「已实现！」「未来计划……」）
- 手抄的目录（常量、测试清单、函数签名）
- 推理转录（「我先看了 A 又看了 B」）
- 兄弟方法旁的重复理由
- 段落墙
- 强调膨胀（处处加粗等于没有重点）
