# Reveric —— 可借鉴机制与本仓对照（外部调研）

- 定位：外部写作类 AI 产品 `reveric`（`https://github.com/looplj/reveric`，本地副本 `Dev/参考项目/reveric`，HEAD `eaa5258` / 2026-10-22 / AGPLv3）的机制盘点与对本仓的可行性判断。调研范围 = 顶层文档全量（README / PRODUCT / DESIGN / AGENTS / CONTEXT）+ 四模块定向源码阅读（agent 核心运行时、多 provider 客户端、数据层与 AI 变更审查、技能与 Workflow 系统）+ 工程治理面抽查（`.agents/rules` 44 份、`docs/solutions` 43 份、`docs/adr` 48 份、提示词回归评估方案）；**未运行该项目、未安装依赖、未调用模型**。不属于本档：任何实施决策与批次排期（建议见 §五，均未排期，与 Openwrite 调研批次衔接）；本仓现有机制的认定以仓库实文为准。
- 阅读边界声明：本报告是机制层对照，不是逐行代码审计；对方自述的测试与性能数字只作其文档记录转述，不作本仓基线。**许可证注意**：reveric 是 AGPLv3，本报告只借判据与机制思想，不得复制其代码。

## 一、它是什么，以及为什么值得看

reveric（幻界）是 Flutter 3.8+ 的本地优先（SQLite + Drift）AI 创作工作台，覆盖小说 → 剧本改编 → 分镜画布 → 3D 导演台 → 多轨剪辑全流程；模型接入 BYOK，支持 Anthropic / OpenAI / Responses / Gemini / Codex / OpenRouter 六协议。自研代码约 63.4 万行 Dart（不含生成文件）、733 个单测档 + 26 个集成测试档；开源仓库只有 3 个提交（裁剪后发布，工程历史不可考）。

它与本仓同域（AI 辅助长篇写作）但形态不同：Flutter 桌面 + 移动跨平台 vs 本仓 Electron 单体；产品重心在「智能体直接操作所有工作区模块」，本仓在「写作链路 + 知识层 + 事件记录」。值得看的不是它的功能面（画布 / 3D / 剪辑与本仓方向不同），而是三块：**AI 变更如何安全进入正文的状态机**、**agent 运行时的失控防护**、**提示词与工程治理的可回归性**。

它有三份文档密度罕见：`CONTEXT.md`（783 行领域术语表：每术语 = 定义 + `_Avoid_` 反例 + 专家问答）、`AGENTS.md`（150 行开发契约）、`docs/adr` 48 份决策记录（带 `status` frontmatter，明写「记录的是已同意的决策，不是已实现的能力」）。

## 二、它正面解决的六类失效

把机制按「防住什么失败」归并（判断是否值得迁移的唯一标准）：

1. **AI 改稿与作者编辑互相踩踏**——AI 未接受的改动与作者手动保存竞态，驳回恢复旧快照时抹掉作者刚写的内容。
2. **模型在工具循环里空转**——同一调用机械重复或轮间振荡，烧 token 不产出。
3. **上下文溢出与压缩破坏配对**——压缩切点落在 tool_use/tool_result 配对中间，或摘要丢失关键交接。
4. **持久化历史回放与流中断**——历史落库破损被 provider 400 且报错难懂；流式截断的半截参数被当成功执行。
5. **提示词与工具面漂移不可验证**——改 prompt / 工具描述后无回归手段，只能人工试。
6. **领域语言漂移与决策遗忘**——同一术语多义、同一决定反复重议。

## 三、可借鉴机制清单

### A. 变更安全：AI 改稿如何活在正文里（对应失效 1）

**A1 apply-on-stage + 拒绝=恢复。** AI 文本变更**立即写正文本体**，同时落 `working_changes` 行（`oldText` 首次 INSERT 即冻结、`newText` 实时读库现值）；审查是可逆状态而非暂存区——接受 = 确认现值，拒绝 = 把 `oldText` 写回本体（`lib/shared/services/ai/working_overlay.dart:92-95`、ADR 0022/0023 明示取舍：代价是未接受文本先可见）。两种流派（它 vs Openwrite 的 preview token 暂存区）解决同一问题，本仓需按自身形态取判据而非照搬。

**A2 同轮合并的严格条件。** 同 `source+session+turn` 且现值恰好等于 `newText` 才 coalesce 成一行，否则新起记录——保证审查卡永远显示真基线（`working_overlay.dart:335-407`）。

**A3 写入乐观校验 + 整篇覆盖字段会话互斥。** `expectedCurrentText` 比对后才落；整篇覆盖型字段加 AI 会话互斥锁，源码注释直接推演失效场景「B 叠 A、驳回 A 抹掉 B」（`working_overlay.dart:526-586`、`:961-999`）。

**A4 Superseding Manual Save。** 用户手动保存成功 = 先自动接受该作用域内全部活跃 AI 变更、再记用户编辑——不加确认、不做三向合并，防「驳回恢复旧快照抹掉用户刚写的」（`working_overlay.dart:746-768`、`:880-900`；剧本侧单事务版 `screenplay_edit_orchestrator.dart:45-98`；ADR 0023）。

**A5 commit 冗余快照。** 每次提交在 `change_commit_items` 里存完整 old/new——历史自包含，`working_changes` 可按保留期清理而历史不破洞（`novel_content_database.dart:870-894`）。

**A6 按轮次回退 + 行级部分回退。** 回滚某条用户消息时恢复 B 而非 C；行级回退用冻结 old/new 合成目标文本（`working_overlay.dart:1826-1953`、`:2216-2317`；ADR 0036 的 T0 节）。

**A7 AI 创建的拒绝 = 删资源。** AI 提议创建的场景被拒绝时整个删除，不留空壳（ADR 0017；`working_overlay.dart:2658-2708`）。

**A8 数据面分界判据。** 双库制（全局 33 表 + 每作品 33 表内容库，按路径缓存 + 引用计数，`novel_content_database.dart:1588-1660`）；schema 纪律「默认只用列和索引」——理由是 SQLite 无法 `ALTER` 约束，取值校验放 Dart 侧单一来源（其 `AGENTS.md:41-47`）；软删除统一 `deleted_at` epoch 0 哨兵；删除前置校验抛 `entity_in_use` 阻删（`novel_content.dart:1288-1299`）。

**A9 关系历史「列存当前态 + 行内 JSON 快照」单表双形态。** 当前态是普通列参与查询，历史是行内结构化快照数组只做回溯——判据：**历史要不要参与查询决定存储形态**（ADR 0037/0039；`entity_relations_service.dart:316-399`）。

### B. agent 运行时：失控防护（对应失效 2）

**B1 无 maxIterations 硬上限，收敛靠显式分层的兜底。** 退出 = 本轮无 tool_calls 且三条注入队列全空；兜底三层：thinking-only 连续 5 轮、截断续写连续 5 轮、LoopDetector abort——且**优先级显式设计**（thinking-only 计数必须先于振荡检测终止，否则产出「静默空成功」，`lib/shared/agent/agent.dart:54-65`、`:1162-1166`）。

**B2 两层循环检测。** Layer 1 = `toolName:jsonEncode(args)` 签名连续相同（≥3 软循环 hint / ≥5 硬循环 abort）；Layer 2 = 轮签名（文本前 64 字 + 调用 + 结果摘要）5 轮窗口全同 = 振荡 abort。**hint 不执行该工具**，写 `skipped:true` 占位 tool_result 保上下文闭合 + 注入提示给一次纠正机会；abort 补齐占位后硬结束（`loop_detector.dart:53-139`、`agent.dart:1343-1419`）。

**B3 三条注入队列语义分明。** steer 插队下轮生效 / followUp 在准备退出时拼接续跑 / nextTurn 排到下次请求前——「用户插话」「系统提醒」「续跑指令」不混一个通道（`agent.dart:277-295`）。

**B4 流重试不写上下文。** 瞬态错误重发同一轮（roundIndex 不变），上限 4 次——失败轮不污染历史（`agent.dart:615`）。

**B5 hook 体系 14 挂点。** onStart/beforeLLM/afterLLM/beforeToolCall/afterToolCall/beforeDone/onLLMError 等；`verification_hook` 在 beforeDone 注入一次自审指令（最多一轮）；`todo_continuation_hook` 查未完成 todo 注入提醒、最终回复以问号结尾视为等用户不续跑（`agent_hook.dart:144-207`、hooks/）。

**B6 工具审批的动作白名单 + TOCTOU 双检。** 审批对象是高成本动作（媒体生成 / 文件读删），发生层在工具执行前；用户批准后**重验冻结目标 + 重查最新规则**再执行；拒绝文案明写「用户决定而非故障，不得重试或绕过」（`tool_permission_gate.dart:24-126`）。

**B7 工具描述的契约级判据。** 「删掉这句，模型这次调用会不会做出不同选择——不会就删」；description 禁止复述 schema 已有的参数说明（参数说明跟着参数走）；tool schema 保持静态以保 provider 工具定义缓存（`.agents/rules/ai-calling.md:20-28`）。

**B8 半截工具调用拦截。** 流结束时仍 partial 的工具调用 yield Incomplete 而不执行；StreamError 也保留已累积产出（`round_assembler.dart:105-132`）。

### C. 上下文管理（对应失效 3）

**C1 真实 usage 优先、估算兜底。** 压缩触发优先用上一轮真实 `usage.inputTokens`（仅压缩后生成的才有效，防过期基线重复触发），无 usage 才全量估算；估算刻意偏高（CJK 1 字 = 1 token）——宁可早压缩不可晚报错（`agent_context_manager.dart:419-434`、`token_estimator.dart:11-28`）。

**C2 切点选择 + 配对完整性。** 阈值 = 窗口 × 0.8；切点优先 user 回合边界、从最老候选选 retained ≤ 0.35×阈值 者；fallback 到 assistant 边界时做 tool_use/tool_result 配对校验（孤儿 result 后移切点），retained 头部重插用户当前指令原文（`agent_context_manager.dart:647-737`、`:535-544`）。

**C3 摘要 = LLM 全量交接 + 溢出清单。** 摘要含溢出区与保留段的交接说明 + 溢出区原始用户消息清单（≤2048 token）；压缩失败本 turn 退避不再试；压缩子 agent 开 `rejectToolCalls` 模式（保留相同工具定义命中 provider prefix cache，误产 tool call 即终止）（`agent_context_manager.dart:199-206`、`:572`；`agent.dart:203-207`）。

### D. provider 客户端健壮性（对应失效 4）

**D1 发送前历史结构 preflight。** 四个 client 的消息转换入口统一校验历史六类损坏（空 callId / 重复 callId / 孤儿 tool result / 缺 result / result 不连续等），fail-fast 抛带 `message_index/block_index` 精确定位的本地异常——防持久化历史回放被 provider 400 且报错难懂；重复 callId 附对照信息（sameToolName/sameArguments）供排查（`provider_history_preflight.dart:114-245`）。

**D2 「只恢复能证明完整的」。** EOF / 缺终态事件时仅当严格判定完整 JSON 才 finalize；半截永远留 partial 交上层拒绝执行——容错不越权（`anthropic_client.dart:504-545` 等）。

**D3 失败分类异常不带正文。** `IncompleteModelResponseException` 五分类只带字符数不带正文，「确保日志和匿名上报安全」（`client.dart:229-280`）。

**D4 重试职责分界。** 非流式走 RetryDecorator（指数退避），流式重试归 agent 层，共用同一瞬态判定函数防两处漂移（`client.dart:379-417`）。

**D5 边界字节与特例容错。** 孤立 UTF-16 surrogate 出站点统一替换 U+FFFD（防 HTTP 层编码崩）；流式半截 JSON 修补解析（UI 实时展示已到字段）；OpenRouter 推理链复用 signature 通道持久化；终态严格性开关（同一 adapter 适配不同可信度上游）（`_sanitize.dart:8-34`、`_partial_json.dart:14-74`、`openrouter_reasoning.dart:30-68`）。

### E. 提示词回归评估（对应失效 5）

**E1 开发期评估链：固定场景 + 真实模型 + 独立 Judge + 基线对比。** `tool/evaluation/` 不进 lib 不进 CI：场景 JSON fixture 驱动、真实 provider 配置、确定性规则 + 独立 Judge Agent 双判定、机器可读报告 + 与基线 jsonl 对比回归。判据硬规则：**Judge 不得是被测 agent**；prompt 级改动跑场景回归、工具行为改动才跑全 workflow 评估；不自动优化 prompt、不提交运行结果（`docs/solutions/prompt-regression-evaluation.md`；CONTEXT.md 的 Prompt Regression Evaluation / Judge Agent 词条）。

### F. 技能与 Workflow（对应失效 6 的另一半）

**F1 技能四源模型。** bundled control（恰 6 个、用户不可编辑）/ official catalog（版本 + 安装快照）/ marketplace（预留未连接，UI 显 not-connected 态）/ private library——**安装 = 内容快照**（源变更不影响已安装），升级是显式动作且保留本地调用名与启用态（CONTEXT.md Skill Marketplace 节；`official_skill_sync_providers.dart`：启动同步安装/升级/退役，`app_states` 记 handled 身份幂等）。

**F2 Workflow 是术语先行、代码未实现。** CONTEXT.md 已定义完整工作图语言（Agent/Split/Loop Node、图快照、waiting/blocked 语义、每书单活跃 run），ADR 已存档边界决策，但 `lib/shared` 无任何 workflow 实现、数据库无表——**借的是「语言先于实现立约 + ADR 明标未实现」的实践**，不是运行时设计。

**F3 官方技能 = 面向作者的方法论资产。** `assets/official_skills/` 是十余份中文写作方法论（黄金三章 / 去AI味 / 长篇连续性 / 角色一致性），frontmatter 带 `when_to_use` 触发词 + 分类——产品内容资产与开发侧技能（`.agents/skills/` + `skills-lock.json` 锁 GitHub source + hash）分置两处不混。

### G. 工程治理与文档（对应失效 6）

**G1 领域术语表（CONTEXT.md）。** 每术语 = 定义 + `_Avoid_` 反例清单 + Example Dialogue 专家问答（如「Session Handoff 不是换 agent」「用户拖章节进聊天是 Context Reference 不是 handoff」）——术语漂移的防线，配套 `.agents/skills/domain-modeling` 技能（GLOSSARY-FORMAT + ADR-FORMAT）。

**G2 ADR 的诚实边界。** 48 份带 `status` frontmatter；明写「记录已同意的决策，不是已实现的能力或实施批准」；外部调研附录带源码锚（ADR 0036 附 Codex CLI / Claude Code / OpenCode / DSH 四家 cancellation 语义对照，逐条带 GitHub 行号链接）。

**G3 规则路由表 + 坑记录。** `AGENTS.md` 的 Rule 路由表按「触发场景 → 必读规则」组织（44 份规则）；`.agents/rules/` 大量记录工具坑与判死方法（build_runner 锁残留、`--build-filter` 会删范围外生成文件、「挂钟长而 CPU 不涨 = 卡死不是慢」、不 pipe 给 grep 的块缓冲假死、Flutter 测试必须串行）。

**G4 提示词与错误的分界纪律。** 提示词不做 i18n（一份共用文本，不随界面语言切换）；错误信息区分用户与 Agent——UI 转可读文案，工具结果保留错误码与诊断供模型自纠，凭据仍脱敏（其 `AGENTS.md:51-58`）。

**G5 版本发布状态判据。** migration 与打包技能的「是否已发布」只核对本地最新正式 tag 及其代码，不凭源码注释 / 分支 / 版本号；未发布 schema 合并进现有 migration 保持版本号不加兼容层（其 `AGENTS.md:45-48`）。

### 4.2 真实缺口，建议逐批补（判据可判红）

| # | 缺口 | 对方现成判据 | 为什么值得补 |
|---|---|---|---|
| 1 | **无循环检测**：模型重复同一工具调用或轮间振荡时只能烧到 MAX_AGENT_TURNS 硬闸 | B2 两层签名（调用重复 ≥3 hint/≥5 abort；轮签名 5 窗口振荡）；hint = 不执行 + 占位 tool_result + 一次纠正 | 硬闸打断的不只无效轮，还有正当的长任务；hint 机制把浪费截在第一次重复 |
| 2 | **退出兜底未分层**：MAX_AGENT_TURNS 20 单一硬上限，无「thinking-only 连续 N 轮」「截断续写连续 N 轮」的软兜底与优先级 | B1 三层兜底 + 优先级显式（thinking-only 先于振荡检测） | 思考空转和正常长任务在硬闸下同死；分层能在不打断正当任务的前提下早停空转 |
| 3 | **AI 改稿审查面不完整**：`rewrite.ts` 有 preview，但无 oldText 冻结、同轮合并条件、按轮回退、用户保存接管（与 Openwrite 批 1 同一缺口的另一半视角） | A1-A7（尤其 A4 Superseding Save、A6 按轮回退） | 本仓「预览→应用」流派可借其状态机判据：基线冻结时机、保存即接受、回退以轮为粒度 |
| 4 | **历史结构校验覆盖面未比对**：本仓有 sanitizeHistory（剔悬空前缀），但重复 callId / 孤儿 result / result 不连续等是否全防未逐条核过 | D1 六类损坏清单 + 精确定位异常 | 续聊回放被 provider 400 的排查成本极高；比对是一次性小刀 |
| 5 | **无提示词回归评估**：改 prompt / persona 后无固定场景 + 独立 Judge 的回归手段 | E1（开发期工具、不进 CI、Judge 独立于被测、基线对比） | 本仓 AI 链路改动的验收目前靠人工试；评估链让「改提示词」也可判红 |
| 6 | **工具描述无契约级判据**：工具 description 写什么、schema 与描述怎么分工无成文纪律 | B7（三判据：改变模型选择才留 / 不复述 schema / schema 静态保缓存） | 工具面只会增长；判据先立，工具描述才不烂 |

### 4.3 不建议照搬

- **Flutter / Riverpod / Drift 技术栈与双库制**：跨平台目标与运行时不同，形态无迁移价值。
- **apply-on-stage 流派本身**：本仓是「预览→应用」（Openwrite 报告批 1 的 preview token 更贴本仓形态）；借 A4/A6 的判据，不换流派。
- **Workflow 图运行时**：对方自己都未实现；借 F2 的「语言先行 + 诚实标注」实践。
- **画布 / 3D 导演台 / 剪辑多模态制片链、微信远程通道、技能市场**：产品方向差异，不是当前质量瓶颈。
- **其 hooks API 57 份文档、baoyu-design 等第三方技能生态**：开发侧 agent 配套，与本仓 harness 域不同。

## 五、建议的落地批次（均未排期）

按「防烧钱 > 防毁稿 > 可回归」排序；每批给回退即变红的验收判据。批 1 与 Openwrite 调研的批次（见 `04-调研/Openwrite-调研-可借鉴机制-2026-10-21.md` §五）互补不重复。

### 批 1：运行时治理（循环检测 + 退出兜底分层）

- 两层循环检测：调用签名连续重复（≥3 hint / ≥5 abort）+ 轮签名 5 窗口振荡；hint = 拒执行 + 写占位 tool_result + 注入一次纠正提示（缺口 1）。
- 退出兜底分层：thinking-only 连续 N 轮 / 截断续写连续 N 轮软兜底，优先级显式（先于振荡终止）；MAX_AGENT_TURNS 保留为最后硬闸（缺口 2）。
- **验收判据**：构造连续同参调用的会话，第 3 次必须收到 skipped 占位而非真执行；回退后同会话必须烧满硬闸才停。构造 thinking-only 空转，必须在硬闸前软停。

### 批 2：变更审查状态机判据（并入 Openwrite 批 1 的实施参考）

- oldText 基线冻结时机（首次落库即冻结，后续同轮合并须现值==newText）；用户保存 = 先接受该作用域活跃 AI 变更再记用户编辑；回退以轮为粒度合成目标文本（缺口 3）。
- **验收判据**：同轮两次改同字段只产生一条审查记录；用户在 AI 改动未决时手动保存，驳回通道不得再恢复 AI 改动前的旧值。

### 批 3：可回归性

- 提示词回归评估链：固定场景 fixture + 真实 provider + 独立 Judge + 基线 jsonl 对比；开发期工具不进 CI（缺口 5）。
- 工具描述三判据入规范（缺口 6）；sanitizeHistory 覆盖面与六类损坏清单比对（缺口 4，小刀）。
- **验收判据**：对任一 persona prompt 跑两次评估，报告可 diff 且稳定；把一条已删工具描述写回去，评估报告必须显示行为变化。比对 sanitizeHistory 后给出「缺哪类防」的逐条结论。

## 六、风险与诚实边界

- **未运行对象项目**：全部机制结论来自源码与文档阅读；落地任一条前需在其源码复核实现细节（尤其并发与回退路径）。
- **开源仓库仅 3 个提交**：其治理文档（48 ADR / 44 rules / 43 solutions）的实践成熟度无法从 git 历史验证——文档可能显著超前于实践，包括 `.agents/postmortem/index.md` 是空占位。
- **Workflow 未实现**：CONTEXT.md 的工作图语言不能当作已验证的运行时设计引用。
- **对方测试与性能数字未复核**：本报告未引用其自述数字作依据。
- **本仓现状认定的边界**：sanitizeHistory 的六类覆盖面、turns 层与三条注入队列的语义差异未逐行比对，相关缺口条目（4.2 #4）以「未比对」而非「缺失」定性。
- **AGPLv3 传染风险**：只借判据与机制思想；任何代码级借鉴都会引入许可证义务，禁止。
