# 文档链收口（设计方案）

- 定位：把 `docs/` 链（收口时为 `Dev/Docs/`，批 E 起落根 `docs/`）、治理正本与门禁**收口到 `project-harness` / `agent-notes` 两 skill 所体现的项目管理流程**（下称 skill 模型）。本档 = 决策面——问题、口径拍板、方案、验收判据、风险与明确不做。
- 不属于本档：批序、每批靶点与落点展开、验收门命令——正本 = `02-执行/文档链收口-执行方案-2026-10-14.md`。
- 模型来源：skill 正本（批 C 起随副本住 `.agents/skills/`；本批之前的正本 = DSH-Skills 仓 `skills/`）。

## 一、问题与现状

本仓的链已经具备 skill 模型的骨架（八槽位一槽不缺、命名同构、归档三关同义、活账文法实质相同），但与模型逐条对照出五处冲突、六处缺失——冲突处会让同一事实在两个地方各说一遍，缺失处让链的自证不完整。

| # | 冲突 | 本仓现状 | skill 模型 |
|---|---|---|---|
| 1 | 状态双写 | 总览有逐文档「文档 × 角色 × 状态」表，设计档头部又写 `- 状态：` | 状态只住活账；档里写定位行 |
| 2 | 索引越界 | 索引「实态」格内嵌文件名枚举 | 索引只写槽位、职责、篇数 |
| 3 | 归档自述矛盾 | 索引写「不维护清单与索引」，却又有篇数格 | 归档 = 冻结的历史，只读；索引维护其篇数 |
| 4 | 篇幅口径 | 「无体积上限」未说明与 skill 预算门的关系 | skill 要求常驻/索引面有预算 |
| 5 | 镜像文案 | 设计档既写「状态以总览为准」又写状态值 | 一个事实一个家 |

缺失项：每档一行定位；类型词闭合（实存「报告」「专项审查」两类例外）；活账三档状态词与加摘行纪律成文；归档后索引行指针与活账摘行同步；评审三出口的后半（条件与理由入账）；**决策记录层**（本仓目前完全没有——决策理由散在设计档正文与 commit 里）。

## 二、口径拍板

1. **对齐范围**：链规约、链实体、决策记录、门禁形态、agent 纪律五层全对齐；**5 个自建 check 一个不退役**（其判据比 skill 泛化门更强，详见 §五）。
2. **决策记录层启用**：主语言 `zh`、单语不配对；历史只回填 3–5 条最值得检索的样板，不做全量回填。
3. **归档 8 篇不解冻**（skill 自身规定移进归档即冻结）；旧规范被取代时按「失效档」入归档，属新增一件、不是改写旧件。
4. **CI 保留现有 step 粒度**，只加门禁一步与 note 门；「一个聚合门名」由本地 `run-gates` 的 `check-all` 提供，分支保护与失败定位都不动。

## 三、方案（五层）

| 层 | 改动 | 落点 |
|---|---|---|
| 规约 | 链规则按模型重写；旧规范作失效档入 Archive | `05-规范/文档操作链-现行规范-2026-10-14.md` |
| 链实体 | 索引重写、活账收身并改名去日期；存量只补定位行、删状态镜像行、类型词按映射表读 | `README.md`、`00-活账.md`、存量 26 篇（分层处置） |
| 决策记录 | 新建 `.agents/notes/` 语料 + `harness.json`（zh/单语）+ 样板回填 | 批 D |
| 门禁 | 装 skill 副本；新增死链门、折行门、文档链索引门；Archive 篇数从 `check-counts` 摘到 `doc-index`（单点声明） | 批 C |
| agent 纪律 | `AGENTS.md` 加 skill 指针、删重复展开，条目结构不动；「五 check」→「六 check」 | 批 C（副本落地后，指针不留悬空） |

存量 26 篇的处置分三层，判据 = skill 自身对历史与冻结的规定：

- **层 1 还在用的链档**（缺定位行的 7 篇 + 头部带状态行的 5 篇）：补定位行、删状态行。
- **层 2 完成态活档**：只按类型词映射表读（**不改名**——旧档不追改是本仓既有先例，也是模型的「只约束新档」）。
- **层 3 归档 8 篇**：不动。要改就得「解冻 → 改 → 重冻（换锚）」，收益只有观感，代价是全部历史锚失效。

## 四、验收判据

- 批 A：`check:docs` 绿；索引篇数与磁盘一致；diff 只含规约面四份 + 两条链档。
- 批 B：diff 只出现「+ 定位行」与「- 状态行」两类增量，26 篇正文零字改动。
- 批 C：`check:harness` 绿；造一条死链即红（报 path:line）；摘掉一门即红；Archive 篇数只有一处声明点。
- 批 D：骨架错的决策记录即红；`Status:` 与目录不符即红；归档封存后改字节即红。
- 全批收口：`npm test` + 七 check（五自建 + `check:harness` 链面门 + `check:notes` 决策记录门）绿，实测数字记入执行档。

## 五、风险与诚实边界

- **无门的部分**：命名、定位行、活账文法、归档三关、评审三出口、决策记录的「值得写」判据——skill 明说这些靠评审纪律，不新造门。
- **词数预算不适用中文档**：skill 的口径是空格分词，中文档等于「一段算一词」；本仓细口径保持单行长度（`check:docs`）。
- **自建 check 不退役**：`check-comments`（含 `.vue` 注释面、跨行配对、残形与清理器同源）与 `check-counts`（零断言门、pageerror 接线、批号上锚、顺序快照）的判据超出 skill 泛化门，退役即净损失；本次只做一处单点收敛（Archive 篇数）。
- **副本维护成本**：`.agents/skills/` 随上游整体替换，指针句要同批对照更新（规范 §十）。
- **验证面**：本仓有 CI 三 OS 矩阵兜底，改门后跑一次 CI 才算背书。

## 六、明确不做

- 不解冻归档、不重排 26 篇的头部元信息块（实测 15 种字段集变体**不构成违规**——skill 对头部只要求「一行定位」）。
- 不把通用判据抽成第二套本仓副本（判据住 skill，本仓只留结论 + 指针）。
- 不启用双语配对（全中文仓）。
- 不为 5 个自建 check 补 manifest 声明面——它们已是「仓库自己的代码」形态，符合 skill 的核心判据。
