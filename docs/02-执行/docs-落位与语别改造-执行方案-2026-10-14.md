# docs 落位与语别改造（执行方案）

- 定位：批次计划与交付记录——把链从 `Dev/Docs/` 迁到项目根 `docs/`（贴合 skill 默认形态），并把决策记录语料收口为「中文默认、单语；英文按需」。本档管靶点、动作、验收与门命令。
- 不属于本档：规则正本 = `05-规范/文档操作链-现行规范-2026-10-14.md`；本批的决策理由 = `.agents/notes/已实施/流程/2026-10-14-文档链落根.md` 与 `.agents/notes/已实施/流程/2026-10-14-决策记录树随语料语言.md`（纯执行 + 两次位置/形态取舍，不另立设计档）。

## 一、批序

批 E：上游门修复同步 → 链迁移 → 语别收口 → 门面全绿 → 提交与回填。批 E 是文档链收口（批 A–D）之后的独立改造批。

批 F：语别收口的下半段——决策记录树与文件名主干随语料语言（上游 skill 改动 + 门禁 + 本仓迁移）。批 F 只覆盖活跃树；归档树封存路径不改名。

## 二、靶点与动作

- **上游同步**：`project-harness` 的 `verify-md-links` 修复随副本入仓（模式清单可点名点目录，默认遍历照旧跳过），版本 0.1.3——没有它，决策记录活跃树进不了扫描面（点目录被判空）。
- **链迁移**：`git mv Dev/Docs docs`；`scripts/harness/markdown-patterns.json`（`docs/**/*.md` + `.agents/notes/{proposed,implemented,rejected}/**/*.md` 三条）、`doc-index.manifest.json`（`docs/README.md` / `docs`）、`baseline.json`（35 条债务路径随迁）、`scripts/check-docs.mjs`（索引面清单、提示语）、`eslint.config.js` 与 `.prettierignore`（注释随实况，忽略面 `Dev/**` 保留给参考项目）。
- **活面引用**：根 `AGENTS.md`（两处指针）、`docs/README.md`（标题与入口链）、规范 §七/§八/§十、设计档定位行、`test/e2e/multi-instance.spec.ts` 注释指针、被否记录里的路径提法；规范 §九 的跨层链接随层级同步。历史记录与 `Archive/` 的旧称不改写。
- **子树档**：新增 `docs/AGENTS.md`——薄档：定位 + 三条进门纪律（一个事实一个家 / 历史正文不改写 / 格式门在此生效）+ 「不属于这里」。
- **语别**：`.agents/notes/harness.json` 已是 `zh` + 单语（批 D）；本批把归档树说明书 `.agents/notes/archived/AGENTS.md` 中文化（该档只受「存在」约束，内容属本仓数据）。英文按需的开法 = `pairedDocuments: true` + 主文件加 `.en.md` 对侧并在同批更新 `.i18n.yaml` 分节记录（契约见 skill 的 `references/bilingual.md`）。

### 批 F

- **上游**：`agent-notes` / `project-harness` 升 0.1.4，两 skill 同号——主语言声明从文件级扩到树级（lifecycle / class 目录名、归档容器、文件名主干用语），槽表住 `aliases.ts`；`agent-note-tree.ts` 与 `verify-archived-agent-notes.ts` 按声明判名（另一语言拼写逐条点名并指出那是另一种说法），`archived-agent-notes.ts` 对归档只认「一件无 tier 正文件 + 一件带 tier 对照 + 记录」的形态（tier 按文件自身读，不拿当前声明核对封存过的字节）；`bootstrap.ts` 增 `--notes-language en|zh`（缺省 `en`，只在首次铺树生效，与既有声明冲突即报错退出），按语言铺目录、`harness.json` 与归档说明书。门禁文案、SKILL.md 与四份 references、bootstrap 文档同批。
- **本仓迁移**：`git mv` 三个 lifecycle 容器 + 归档容器 + 二十四个类目录 + 五篇文件名；`markdown-patterns.json` 的三条 glob 随迁；活面引用 = 规范 §七（散文一段一行面）、§九（决策记录路径与那篇被引记录）、本档定位行、「文档链落根」那篇记录里的模式清单引用。批 A–D 的历史记录与历史散文里的旧路径不回改，对照表见批 F 执行记录。

## 三、验收

- **批 E**：迁移后 `check:harness` 绿，扫描面覆盖链档 + 链根常驻档 + 决策记录活跃树（含本批新增的决策记录与本执行档，实测 39 篇）；`markdown-wrap` 台账仍是同一 35 条——路径随迁、零新增、零陈旧；`check:docs` / `check:counts` / `check:notes` / `check:knowledge` 绿；`npm test` 全量绿；活面（工具、常驻档、链档正文）不再有 `Dev/Docs` 的现况引用。
- **批 F**：`check:notes` 绿且树为中文拼写（6 篇）；`check:harness` 绿且扫描面随迁；活面（工具、patterns、规范、活账、本档）不再有英文目录拼写；上游两 skill 逐字节一致、版本 0.1.4；负向对照：把「目录随语言」「归档容器随声明」「封存拼写冻结」「脚手架随旗标」四条各自还原，对应用例逐条转红（README 与执行记录留实测数）。

## 四、门命令

`npm run check:harness`、`npm run check:docs`、`npm run check:counts`、`npm run check:notes`、`npm test`（批 F 另加 `npm run check:comments`、`npm run check:packaging`、`npm run check:knowledge`、`npm run lint`、`npm run typecheck`、`npm run typecheck:web-next`）。
