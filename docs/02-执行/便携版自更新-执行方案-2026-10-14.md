# 便携版自更新（win 便携 zip 覆盖）执行方案

- 定位：执行正本——批序、每批靶点、验收判据、门命令、执行记录（末节回填）。**设计理由与取舍不在本档**，正本 = `03-设计/便携版自更新-设计方案-2026-10-11.md`（下称设计档，引用记「§N」）；状态住活账；前置验证的可行性结论归 `04-调研/`。
- 范围：只做 win（设计档 §九 D5）——mac 双 arch dmg 零改动；浏览器模式保持「复制链接」降级。功能可见性 = 桌面桥方法存在性（win32 + 打包态才暴露）。
- 两道开工闸：① 批 0 四项前置验证过（不过则退回设计档改口径，不动工）；② 本档 §六决策点（已闭项，结果已同步设计档 §九）。

## 一、总序

**批 0（前置验证，go/no-go）→ 批 A（元数据与下载链）→ 批 B（助手模式与目录交换）→ 批 C（IPC 与前端）→ 批 D（收口与真机验收）**，严格顺序：B 依赖 A 的缓存件与校验件，C 依赖 B 的 IPC 契约，D 收全链。

批 A 是纯逻辑（网络注入可测、零 UI 改动），先落可把「下载 / 校验 / 缓存」从整链剥离独立验证；批 B 的交换序列是风险核（其机制面前提在批 0 已实证）；批 C 最薄但要动三处桥文件（`ipc.ts` / `preload.ts` / `desktop.d.ts` 三同改）。

量级参照设计档 §十（约 8 人日，不含签名）；批 0 约半天（多数是环境等待）。

- 实施环境（现状：开发机 = macOS / `mac` 支，而功能 win-only）：**验证面三分**——macOS 本机可做可测 = 批 A、批 C 全量与批 B 的逻辑面（fs 注入），另建 macOS 夹具（假目标目录 + 本地供件 + 假重启目标）把「下载 → 校验 → 交换 → 清理」整链真跑（证算法，不证 Windows 锁语义）；CI win 腿（windows-latest；存量基建 = 打包态多实例冒烟 `desktop.yml:459-471`）= 批 0 机制项（3、4）脚本化实跑；Windows 真机（作者侧）= 批 0 环境项（1、2）与批 D 真机验收（CI 无国内杀软、无真代理环境）。
- 动工序（§六 D-i）：批 0 四项可在 Windows 机上一次跑完；机制两项如需提前，可走 CI win 腿（批 B 落码前有结论即可）——均不阻塞在 mac 上落批 A / B / C。

## 三、批 A：元数据与下载链

### A1 检查链扩资产面

- 靶点：`src/update/check.ts`（现状 `:25-152`：releases 列表查询、5s 超时、进程内存态、`assets[]` 未读）；抽纯解析 `src/update/asset.ts`（新增）——`fetchLatestStable({fetchImpl, timeoutMs})` 与 `pickWinAsset(assets)`（按名匹配 `CLWriting-<版本>-x64.zip`，产出 `{name, url, size, sha256}`；sha256 来源按 §六 D-b）。
- 语义不动：进程内一次 + 延迟一发 + 失败静默（`check.ts:26-34` 口径原样），`runUpdateCheckOnce` 改调纯解析。
- 端点：`src/studio/server/api/app-info.ts:17-25` 的 `update` 扩 `asset: {name, size, url} | null`（设计档 §4.6：无资产回退「去下载」）；前端类型 `src/studio/web-next/src/api/app-info.ts:6-16` 同批。
- 验收：`test/update/check.test.ts` 增例（无 assets / 无 win 资产 / 多候选取对应件）；`test/studio/server/app-info.test.ts` 三态扩 asset 面。

### A2 下载器

- 靶点：`src/update/download.ts`（新增）；缓存根 = `<home>/更新缓存/<版本>/`（`appDataHomeDir()` 共享根，多实例共用一份——设计档 §4.1 的 userData 语义按共享根落，先例：`ipc.ts:388-394` 诊断包用共享根）。
- 契约：`downloadAsset({url, size, sha256, destDir, signal, onProgress})`；流式写 `.part` 后缀 → 完成即校验 sha256 → 原子改名成正式名；失败 / 取消 / 断流一律删半成品、回人话原因枚举（网络 / 校验 / 磁盘）。
- 出站通道按批 0 结论（Electron `net` 或 fetch）。
- 验收：`test/update/download.test.ts` 新增——本地 http server 供字节：正常 + 进度序 / 校验失败删件 / 取消删件 / 断流无残留。
- 缓存保留策略（一行）：启动清理「版本 ≤ 当前」的缓存目录；失败件即时删。

## 四、批 B：助手模式与目录交换

### B1 argv 极早分支 + 助手例程

- 靶点：`src/desktop/main.ts` 顶部（import 块后、`const homeDir`（`:96`）之前）插 `--apply-update` 分支——必须先于 `app.setPath`（`:99`）、日志 init（`:107`）、单实例锁（`:114`）、server fork（`:423`）、建窗（`:454`）；支内跑完即退（设计档 §4.2 / R7）。
- 助手例程 `src/desktop/update-helper.ts`（新增）：argv 解析（循 `startup-instance.ts:32-42` 的 `--flag value` / `--flag=value` 双形态扫描惯例；payload / target / pid / 库目录等路径参数由主进程显式下发，助手不猜）；等 pid 退出（`isProcessAlive`，超时 120s）；预检（zip 重校验 / 目标目录可写 / 空间 / 其他实例锁扫描 = `queryLockHeld` × `<home>/instances/*/app-instance.lock`，先例 `diagnostics/index.ts:434-444`）；恢复检查（R4：`<target>` 缺且 `.old-*` 在 → 改名回）；解压 `<target>-new-<版本>`（同卷）；交换（→ `.old-<旧版本>` → 新改名成正式名）；重启新 exe（`new-instance.ts:32-71` 的 detached spawn 形状，带原库目录 `--dir`）；失败回滚 + 写留痕。
- 解压能力按 §六 D-e（依赖方案须同批入 `tsup.config.ts:58` noExternal，否则 `check:packaging`（`scripts/check-packaging.mjs:179-195`）裸包门红）。
- 验收：`test/desktop/update-helper.test.ts`（fs 注入：交换序 / 各步失败回滚 / 恢复检查 / 预检判定）；助手隔离并入 `test/desktop/main.test.ts`（harness 在位：`vi.mock('electron')` + 动态 import）——`--apply-update` argv 下不建窗 / 不起 server / 不抢锁，撤分支即红。
- macOS 夹具端到端（本机可跑）：假目标目录（含假 exe）+ 本地供件 + 假重启目标，整链真跑交换序与回滚中断——钉算法；Windows 语义面（锁、杀软）归批 0 与批 D。

### B2 退出链挂点

- 靶点：镜像 `workdir-controller.ts:581-596` 的 pendingRelaunch 三件（旗 / 兑现 / 触发）——新增 pendingUpdate：`lifecycle.ts:674` 同处 `armPendingUpdateIfAny()` spawn detached 助手；flush 取消路径（`lifecycle.ts:661-663`）同步 `discardPendingUpdate()`；硬退两路（`main.ts:800-828` 等）不经此点——助手超时自兜底，不阻断退出。
- 触发口：批 C 的 IPC；本批先以测试注入（撤兑现 → 退出链用例红）。

### B3 启动清理与留痕展示

## 五、批 C：IPC 与前端状态机

### C1 桌面桥

- 靶点三处同改：`src/desktop/ipc.ts`（`handleTrusted` 惯例 `:163-170`）+ `src/desktop/preload.ts`（`:73` 同款）+ `src/studio/web-next/src/desktop.d.ts`（`:33` 同款）；方法集：`updateDownload(version)` / `updateCancel()` / `updateApply()` / 订阅 `onUpdateProgress`（订阅先例 `preload.ts:78-84`）。
