## 一、P1-01 定稿链补前置落盘（出口条件）

- **现象**：`doc.finalize()` 直接发请求，函数内无任何冲刷前置；服务端按**盘上字节**算定稿基线指纹并留 pinned 版本，而编辑器正文回写有 200ms 合并窗、窗尾到 autosave 落盘最多隔一个节拍。窗内点定稿 → 定稿版本缺最后一段键入，随后 autosave 落盘 → 章状态静默由 `final` 降级为 `revision`（作者收到「已定稿」，树里回到待定稿）。三个入口（编辑器按钮、树菜单、批量定稿）同样不冲刷。
- **改法**：`src/studio/web-next/src/stores/doc.ts` 新增单源 `flushBeforeSettle(docId)`——`flushBodyWriteback()` → `await waitInflightSave(docId)` → 条目不存在放行、`conflict` 拒绝、`dirty` 则 `save(docId,'autosave')` 后复查脏位；随 store 导出。`finalize()` 顶部调用它（前置段包异常信封，维持「失败走 toast 不外抛」的既有承诺），落不下去即 toast 中止且零请求（并复检书名，落盘在途切书不发跨书定稿）。`src/studio/web-next/src/composables/useChapterTreeActions.ts` 的 `doBatchFinalize()` 对在缓存的 `docIds` 逐个前置，任一章失败即整批中止且零批量请求。`src/studio/web-next/src/shared/body-writeback.ts` 的不变量 2b「决策点调用点」清单补定稿族。
- **判据**（并入 `test/studio/webnext/dom/body-writeback-before-dirty-gate.test.ts`，六例）：单章「窗内键入 → 定稿」落盘 payload 含窗内正文且调用序先于 `finalizeDoc`；批量同序；冲突未决与保存失败两态零定稿请求 + error toast；批量任一章落不下去则零批量请求；落盘链自身抛错就地吸收（`finalize` 对外承诺失败走 toast 不外抛）。
- **回退即红**：撤掉两处前置调用后，前五例全红、其余四例（既有决策点）不受影响；撤掉前置段的异常信封后第六例红。

## 二、P2-01 UNC 与 `\\?\` 绝对路径补进脱敏面

- **现象**：`src/log/path-scrub.ts` 两层正则只认「POSIX 拉丁首段」与盘符形，UNC（`\\NAS-SERVER\共享盘\…`）原样输出、`\\?\D:\…` 只剥成 `\\?\<路径>`。消费面三处（日志行 / API 错误信封 / 外发诊断包）都保留服务器名与共享名，与模块头注「其余绝对路径一律替换」相违。
- **改法**：增两条判据——设备命名空间形（`\\?\`、`\\?\UNC\`）与 UNC 形，均**整条**替换（前缀本身就是可识别信息，只剥前缀会留残形）；两层的左视与字符类排除 `?`、Windows 非法文件名字符与分隔符，避免吃进代码里的转义串；替换次序压在家目录层之后、盘符/POSIX 层之前。`\\{2,}` 口径同时覆盖日志里成对转义的 JSON 值。
- **判据**（并入 `test/studio/server/error-envelope.test.ts` 一层）：UNC、`\\?\`、`\\?\UNC\`、成对转义四种形态各落到 `<路径>`，服务器名/共享名/`\\?\` 零残留；既有「家目录 / 家目录外 / 盘符」三形态与原「相对路径与中文人话逐字保留」对照全绿。
- **回退即红**：摘掉新增两层后该用例红（四段路径只消掉两段）。

## 三、P2-02 `PUT /config` 改 `budget.chat_max_calls` 真落盘

- **现象**：该键在 schema 表里刻意无 `get`（自注「不入 PATCH 白名单」），而补丁叶由有 `get` 的键行派生 → 补丁面整键丢弃；端点却把它列入数值校验并无条件回 `{ok:true, revision}`。契约面静默失败：改键得到成功响应而盘上不变。
- **改法**：取「补 `get` 入白名单」而非「拒收该键」——前端 GET→PUT 整体回传的链路会被拒收打断。`src/format/yaml-spec.ts` 给该键补 `get` 并把注释改写为「入 PATCH 白名单 / 坏值 fail-closed 归 0 的语义在 parse 面」。
- **判据**：`test/format/yaml-schema-snapshot.test.ts`（PATCH 白名单清单锁）基线补 `chat_max_calls: 20` 键行、增一锚、总数 51→52、叶键计数 47→48；`test/studio/api/cov-server-config-draft-branches.test.ts` 补端点级一例——同请求改该键与对照组键，盘上原文两键都改到、GET 回读一致。
- **回退即红**：去掉 `get` 后清单锁与端点用例同时红。

## 四、P2-03 `patchFlatFm` 块标量改值保留作者注释与空行

- **现象**：块标量键改值时整段 `span` 被丢弃，段内作者手写注释行与空行一并消失；同档承诺「其余行逐字节保留」。
- **改法**：`src/format/frontmatter.ts` 块标量分支只丢属于旧值的嵌套内容行（缩进行、`- ` 列表行），空行与注释行（`trimStart()` 以 `#` 开头）保留在新键行之后。普通键分支、`hasNested` 拒绝分支与全文规范化不变。
- **判据**（并入 `test/format/frontmatter.test.ts`，两例）：块标量改单行值后旧内容行消失、注释与空行保留、段内其余键逐字在位；新值仍为多行时同样保留注释。
- **回退即红**：恢复整段丢弃后两例全红。

## 八、波次二：P3-08 / P3-11 / P3-12 / P3-13 / P3-15 / P3-18 / P3-04

- **P3-08 断流结局归类**：`src/ai/runner.ts` 的 `stepEndReasonFor` 原按「非 `max_tokens` 即 `completed`」，把 `unknown`（流未收到 done 的归类值，产出可能半截）也记成正常收尾。现按 `interrupted` 落账；服务端给出确定结局的值照旧 `completed`。同批两处成功路径用例的桩原返回裸字符串（无 `stopReason` = `unknown`），已改为给出确定结局。
- **P3-11 语料编码失真**：`src/knowledge/corpus.ts` 的读入面新判两条确定证据——含 BOM、含 `U+FFFD` 替换符，命中即跳过该篇并留痕。书级知识层是作者可改且常放同步盘的文件，GBK/UTF-16 存盘或半写会让乱码整段进 prompt 而作者零感知；不猜编码去转码（猜错比跳过更坏）。跳过后仍走既有两级回落。
- **P3-12 RAG 增强面反噬主链**：`src/process/materials.ts` 的 `resolveRag`（内读 `.clwriting/rag.secret`）与命中后的片段取件两处在备料主链裸奔，密钥文件不可读或读正文失败即一次 500。两处各自兜底为「未配 RAG / 无命中」并留痕带病因，与同函数内写稿档位、摘要补漏的既有降级口径一致。
- **P3-13 资源根穿透**：`src/knowledge/inject.ts` 的首次抽查与逐篇解析都经 `bundledResource` → `resourcesRoot()`（缺失即按设计抛错）。本模块产出是拼进三面 prompt 的段落，抛在此即整章失败。现首次抽查失败 → 整轮空注入并留痕；逐篇解析失败 → 该篇记 `missing` 跳过。暴露面交打包门与日志。
- **P3-15 校验值解析前置**：`src/update/download.ts` 的期望校验值原在包体落盘后才解析——发布方没给值、清单拉不到、清单无此行三种注定失败的情形，作者要等整个包下完才见到报错。现先解析且失败即在下包体之前返回，清单请求相应前移至包体之前。
- **P3-18 诊断包两处**：`src/diagnostics/index.ts` 多卷写到中途失败会留「一套缺卷的包」，现按已写入卷名单回滚（不按模式扫目录，同目录还可能有先前生成的包），清不掉的写进错误文案；时刻段只到秒，同秒重入落到同名文件即覆盖前包，现撞名依次试 `-2`/`-3`。
- **P3-04 段末注释丢失**：`src/format/yaml-patch.ts` 的 `patchTopSection` 只留段尾空行 run，段末纯注释行随旧段丢弃——作者写在段末的说明不对应任何被替换的键值却被无声删掉。现把尾部连续的「空行 + 纯注释行」整块原样接在新段体之后；夹在键之间的注释仍随被替换的键消失（那些注释与键一一对应，留着会张冠李戴）。同档 `writeBookConfig` 无锁一项经查只有一个调用点且受 `existsSync` 守卫（仅建书期），不构成并发写面，不加锁。
