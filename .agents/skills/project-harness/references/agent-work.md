# Agent 工作纪律

给 agent 派活、以及 agent 自己动手时的纪律。这些判据不属于任何单一工具链，所以大多以文字存在而不是门禁——**能机器判定的部分一律落在别处**：注释面见 [comment-hygiene.md](comment-hygiene.md)，测试面见 [test-reliability.md](test-reliability.md)，宣称值见 [gates.md](gates.md)。

## 任务书三件

派发任务（主控 → 子 agent，或人对 agent）必须带齐三件，**缺件先问再动**：

| | 内容 | 缺了会怎样 |
|---|---|---|
| **靶点** | 文件 / 符号 / 现象——哪一处、什么表现 | agent 从自己猜的地方开始改 |
| **验收判据** | 什么算做完：哪条命令、哪个观察面 | 「做完了」变成自述，验收退化成复述 |
| **不读面** | 哪些不必读、哪些不要碰 | 上下文被无关内容吃掉，改动面被顺手扩大 |

**为什么「不读面」也算三件之一。** agent 的真实成本不是输入贵，而是**范围无界**：不给边界，它会先去读整个目录「建立理解」，然后基于自己建立的理解，改一处它没被要求改的东西。声明不读面就是声明可信的边界——它把「你可以相信我按你指的地方走」从一句期望，变成派发时就能给出的东西。

## 先定位后阅读

**检索定靶 → 只读命中文件与其一跳调用方。** 结论锚在 `file:line` 上，不写阅读流水账。

「我读了这些文件」不是交付物。一条结论必须能指到具体位置，否则它既不能被复核，也不能在它过期时被定点修正。反过来，把读过的文件逐个列出来，是把 agent 的过程当结果交给读者——读者要的是结论。

**确需通读整档时，先报范围与理由。** 通读不是被禁止，是需要被声明：为什么这次会话成本要花在这里，读完预期得到什么。声明之后它成为一个可被否决的请求，而不是一件已经发生的事。

## 通读即专项

「通读全文找问题」只在**作者明示的审计任务**下成立，且必须声明域（看哪一类问题）、深度（读到什么粒度）、预算（花多少）。审计的产出**只有报告**，修复另开靶向任务。

把两者合在一起会互相污染：「发现了什么」与「改了什么」不再独立——修复掩盖了报告里没写清的部分，而报告开始为已经做出的修复找理由。分开之后，报告的完整性与修复的正确性各自可以被检查。

## 子 agent 并发上限

**单波 ≤ 4（在途 ≤ 4）**，超量拆多波顺序派发。

这个上限不是性能参数，而是**注意力参数**：并发越多，主控用于合并与复核每个结果的能力越薄。四个结果还能逐个看；十个结果只能被批量采信，而批量采信等于没有复核。**上限跟复核能力绑定，不跟机器核数绑定。**

## 一个批一个主题

挂账项与待拍板**各自成批**；一批只做一件事。夹带的东西——包括「顺手修的」和「刚好看到的」——另开批。

主题纯度让「这一批改了什么」可以用一句话回答，也让回退有单位可操作。发版批的对应形态（只做版号与出包）见 [governance-model.md](governance-model.md)。

## 提交说明与对外文案

**不引作者指令原文，决策以结论转述。** 提交信息、PR 描述、对外说明里写的是「决定了什么、为什么」，而不是「谁在什么时候怎么说的」。引原文会让读者去解读转述口径，也把一条可复核的结论降级成一次传达。

## 注释只写约束

代码注释只写作用、约束、不变量、语义、平台差与同步关系；**修复史与来历归 git**。

这条在 agent 手上格外容易破，因为 agent 天然想解释「我为什么这样改」。判断标准很简单：这段话在改动被回退之后是否还有意义——没有意义的，就是修复史。形态判据与机器形态见 [comment-hygiene.md](comment-hygiene.md)。

## 已知的诚实边界

上面每一条都能被绕开，而且绕开时通常看起来更勤快：不读面声明了也可以「顺便」看一眼，靶向任务也可以顺手改掉旁边那处，审计也可以边看边修。**这些纪律没有门禁兜底**，它们的价值在于让越界成为一件需要解释的事——评审看到的是一个可以被指认的偏离，而不是一片无从追究的「做得多」。
