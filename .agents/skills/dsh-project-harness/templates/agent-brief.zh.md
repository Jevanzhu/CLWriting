# 派发任务书（agent-brief）

<!--

复制后逐格填，缺格先问再动；交出前删掉本注释与占位提示。
-->

## 靶点

- <文件 / 符号 / 现象：哪一处、什么表现；能指到 `file:line` 就指到行。>

## 验收判据

- <哪条命令、哪个观察面算做完：给可执行的命令，不写「做完了」。>
- <一条命令覆盖不了就逐条列，并注明本次要求哪几条绿。>

## 不读面

- <哪些不必读：靶点已定位，就不要先通读目录来建立理解。>
- <哪些不要碰：列出写作用域之外的文件或目录，越界即偏离。>

## 交付面

- <产物落哪个槽位、哪个路径：按仓库文档链的槽位写具体路径，不写「某处」。>
- <索引与活账是否同批更新：是则写明哪一份；否则写明不同批及其理由。>
- <禁止落到仓根、临时目录或工作区之外；产物只认落在槽位里的文件。>

## 技能前置

- <开工前先加载哪个技能：写技能名，以及加载后先读哪几份 references。>
- <技能正文与 references 只进派发者自己的上下文，不会继承给子 agent。>

## 禁止

- <不改写作用域之外的文件；不 git add、commit、push。>
- <不跑验收判据没点名的命令：全量测试、发布脚本、会改共享状态的命令。>

## 报告格式

- <改了哪些文件：逐条列路径与一句改动摘要。>
- <自查命令的实际输出：贴命令本身、关键行与退出状态。>
- <遗留风险与未覆盖面：写清哪条判据没验、为什么。>
