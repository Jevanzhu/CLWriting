# 归档

活跃的决策语料会无限增长，最终没人敢改动它。归档是熵减：把仍有历史价值、但不太可能再指导未来工作的笔记移出维护面，让活跃树保持可读。

## 判据是语义，不是字数或年龄

上游客量最大的语料里，归档校准过一批例子，值得记住其中的反差：

- **删除**：一篇 533 词的「折叠侧栏控制条」笔记——纯局部 UI 调整。
- **保留**：一篇 248 词的「事件溯源会话」笔记——短，但承载了持久的架构边界。

短不等于可以删，长不等于必须留。也不要为了达成某个数量目标而归档——`Do not archive toward a quota.`

四类处置：

| 现状 | 处置 |
|---|---|
| implemented，且只描述局部 UI 调整或纯机械改动 | **删除**（连同对照文件一起） |
| implemented，理由/备选/负面保证/持久化或协议语义/所有权边界/安全规则/重新引入条件仍有指导价值 | **保留在活跃树**，与年龄和字数无关 |
| implemented，决策已完成、理由不太可能指导未来工作、但仍有历史决策价值 | **归档** |
| proposed | **永不归档**。不再值得做就改成 rejected。 |
| rejected | 只在它的理由能防止一个仍然诱人的错误时保留，否则删除 |

## 归档一个笔记

路径变成 `archived/{class}/yyyy-mm-dd-topic-title.md`——注意 `implemented` 这一层被去掉了，因为只有已交付的笔记能进归档。

1. 移动完整的三件套（正文件 `foo.md`、对照文件 `foo.{zh,en}.md`、一致性记录 `foo.i18n.yaml`）。对照文件的语言由 `.agents/notes/harness.json` 的 `primaryLanguage` 决定，见 [bilingual.md](bilingual.md)；未配对的笔记只有正文件一件。
2. 在**两侧**的 `Status: implemented` 行**正下方**各插入一行完全相同的 `Archived: YYYY-MM-DD`。
3. 机械地重录 sidecar：活跃树的分节记录在这里改写成整文件 Git blob 形态（`foo.md: <40 位>` 两行）——归档门禁校验的是后者，原文带着走、只重算哈希。
4. 修理或删除指向它的入站链接。
5. 运行 `node scripts/verify-archived-agent-notes.ts --write` 封存。

归档日期不得早于文件名里的日期。以上是归档过程**唯一允许的内容改动**——标题标点、空行布局、语言切换器的措辞都不许顺手改，原文带着走。

## 封存之后不可变

一旦写入 `manifest.json`，整个三件套就永久冻结：不许编辑、翻译、重排格式、修复链接、移动或删除。

`manifest.json` 是一份内容哈希清单，只增不改。写入时它会先逐条证明**每一个既有封存都没变**，再只为新增文件追加哈希。这意味着：

- 改动已封存字节 → 门禁报 `sealed content hash changed`，**即使带 `--write` 也拒绝**。
- 删掉已封存文件 → 报 `sealed artifact is missing`。
- 新增归档却忘记封存 → 报 `archived artifact is not sealed in manifest.json`。

**为什么这么严**：归档笔记的内容本身不受常规门禁检查（门禁跳过归档源），唯一能证明「历史没被偷偷改写」的就是这份哈希清单。如果它能被随手更新，保证就归零了。上游语料里 2772 条封存记录只开过**一次**例外——移除三个文件里的失效外链——而且是硬编码精确 before/after 哈希、在源码里留了注释说明的。默认答案是「不许改」，例外需要同等量级的论证。

**归档目录对链接检查是单向的**：指向归档笔记的链接会被校验，但归档笔记自己发出的链接不检查（它们按设计可能已经过时）。

## 合并已完全被取代的笔记

一篇 implemented 笔记如果已被后来的决策完全取代，可以并入当前 owner 并删除。删除前必须保存下每一条独特的理由、备选方案、后果、必需的验证方式，以及明确点名的覆盖缺口；修好所有入站链接；对照文件与 sidecar 在同一个改动里一起删。

**部分取代不算**：那种情况保留两篇并交叉链接，把仍然成立的事实更新到最新。

功能新增笔记并入其移除笔记，需要更严的条件：该功能必须在生产代码、配置、schema、持久化或协议格式、迁移、兼容行为里**完全不存在**，没有现行文档把它当作可用能力，也没有测试把它当作受支持行为。移除方要保留最初的动机、为什么它不再成立、完全不删的替代方案、放弃掉的能力、重新引入的条件，以及「确实已彻底移除」的验证证据。

## 与常规门禁的关系

归档笔记免于常规文档门禁（字数预算、单行段落、配对、链接检查都会跳过它），但归档树自己有一套门禁。归档目录另有几点结构要求：六个 class 目录必须**全部存在**（哪怕为空），根目录只接受 `AGENTS.md`、`manifest.json` 与 `harness.json`，class 目录内只允许普通文件。

CI 请用 `HARNESS_ARCHIVE_BASE_REF` 传入受信基线提交（PR 的 base SHA）。本地写入默认与已提交的 `HEAD` 比对；在尚未有任何提交的新仓库里，比对会降级为一条警告而不是失败，这样第一次封存能正常进行。而**当 CI 显式提供了 ref 却读不到时，那是硬错误**——浅检出绝不能变成静默跳过。
