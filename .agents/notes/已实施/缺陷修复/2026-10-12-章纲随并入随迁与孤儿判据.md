# Agent Note: 章纲随并入随迁与孤儿纲判据（并入 ∪ 回收站）

Status: implemented

## 问题

合并把源章正文软删进回收站后，源章纲仍留在 `大纲/章纲/`——章纲是 `trash:false` 的系统文档（`layout.ts`），既删不掉，也没有任何机检或结构报表覆盖它（`piece-list-outline-missing` 是「正文缺纲」反方向，短篇专属）。孤儿纲由此静默积累。

第二个缺口在章号复用：取号按正文盘面 max+1，被删章号自然腾出、可被新章复用；而章纲定位三口径之一是「目录内按 fm 章号匹配」（`locateChapterOutline`），复号后的新章会静默认领盘上旧纲——没有任何提示作者那可能是上一章留下的。

## 决策

**随迁（合并写侧）。** 合并收尾段新增 ②b：正文软删落定后，源章纲经同一条 `svc.trashDocument` 管线入回收站，成为独立 `TrashEntry`（`role='chapter-outline'`，docId = 清单按路径反查 ?? `legacyId` 收养链），事件 `structure.merge` 携可选字段 `outlineTrashEntryId`。失败与正文软删同款 fail-loud（「重试将自动续跑收尾，或撤销合并回退」）；幂等判据 = 纲不在盘即跳过，②b 前崩溃重跑自动补搬。

**对称还原（撤销写侧）。** `finishUndo` 新增 ②b：按事件 id 还原纲；旧载荷/载纲后崩溃形态缺 id 时按章号扫回收站兜底（同名优先 + 择最新）。best-effort——还原失败仅 warn 留痕（条目仍在回收站，可手工还原），不阻断撤销主承诺。干跑视图增 `sourceOutlinePath`，前端确认弹窗据此提示随迁。

**判据单源。** `src/document/outline-orphan.ts` 是四处消费面（合并随迁的可删例外、机检黄项、结构报表、撤销兜底定位）的唯一判定：证据 = 章纲章号 ∈ 并入引用（`mergedIntoMap`）∪ 回收站 `role='chapter'` 条目章号集；守卫 = 无存活同号正文（保守 union：文件名号 ∪ fm 号）。计划前置、章未写的纲无任何证据，恒判非孤儿。结论分两 kind：`orphan`（无存活宿主）与 `reused`（复号有宿主）。

**可见与清理。** 机检新增「章纲一致性」section：`orphan+merged` 挂合并目标章（`merged-outline-orphan`，含删除指引）；`reused` 挂同号存活章（`reused-chapter-stale-outline`，可误报灰显）。healthCheck 新增 `outlineOrphan` 项收「删章留纲」（无宿主、也无合并去向）。清理口 = 回收站能力例外：仅无主纲（证据在场且无存活同号正文）放行软删，存活章纲与其余系统文档维持 `CAPABILITY_DENIED`。

**删章路径不级联。** 软删正文时不搬纲：原章还原后纲自动归位（配对复原）；作废不还原的，由 health 报表 + 删除口收口。

## 曾考虑的替代方案

**TrashEntry 加伴随字段（纲路径记在正文条目上）。** 一条回收站条目携带多个路径，还原/清理/展示全要按字段分支，schema 与语义双膨胀。落选：独立条目复用既有管线，零 schema 变更，撤销时两条目各自独立幂等。

**回收站内部旁路（绕过 `svc.trashDocument` 直接移文件）。** 会绕开能力闸、留底快照、清单同步、回收站登记四处簿记，回收站「登记先于移文件」的纪律出现例外口。落选：②b 执行时目标章 fm `并入` 已登记（证据在场），走正常管线即可通过例外判据，无需旁路。

**删章时级联删纲。** 删章语义是作废、可还原；纲随删会让「还原章」回来后失去规划资产，还原对称性变成双倍簿记。落选：保持纲原位零簿记，无主态交给报表。

**取号面加闸（被删章号不复用）。** 改的是全书写号语义（多数书正常续写路径也随之变），且解决不了存量孤儿。落选：本批只做「可见 + 可清」，不动取号。

**复号旧纲自动删除/自动改名。** 复号提示本身允许误报（作者确为新章写了新纲）；自动处置会误删作者资产。落选：黄项 + 误报灰显，处置权交作者。

## 后果

换来：章纲去向与正文同构——合并时跟随、撤销时还原、无主时可删；三形态（合并孤儿、删章无主纲、复号旧纲）在机检与进门体检上全覆盖；能力例外不新增闸面，判据单源一处，正反例均有测试钉住。

付出：合并收尾段多一段 fail-loud 的 ②b——纲目录读失败或纲软删失败会拦下本次合并成功返回（盘面已一致，重试续跑即收），合并成功路径的噪音面略增；撤销的纲还原是 best-effort，失败只留痕、需手工从回收站还原；语料门的 checkId 快照需随两个新 checkId 同步维护；回收站 UI 开始出现 `chapter-outline` 条目（沿用既有 role 呈现，无新界面）。

## 已知上限与重访条件

这次收窄的上限是「可见不阻止」：取号面不动，被删章号仍可复用，`reused` 只提示、不阻止，提示本身也允许误报。作者忽略黄项时，旧纲仍会被新章默认领走。

重访条件：复号在同一本书里反复出现且经查多为真命中（旧纲确被误领，不是误报），或存量孤儿在「可见 + 可清」落地后仍持续积累——那时回头评估取号面加闸，它与全书写号语义同批改，属独立一批。
