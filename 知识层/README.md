# 知识层

本目录存放写稿、三审与对话可读取的正式知识素材。

素材以「精选速查版」改写自外部 MIT 项目（主要是 oh-story-claudecode），
保留来源、来源 ref、许可证和文件哈希，记录在 `_manifest.json`。CI 只信本目录，
不把 ignored 的 `Dev/` 参考仓当隐式输入。

改写原则：
- **速查而非全文**：每篇提炼决策路由 + 法则清单 + 自检清单 + 来源注，避免知识层臃肿；真模型按需读。
- **只收判断类**：角度 / 取舍 / 法则 / 判据入库；时效数据（榜单数值、样本统计）丢弃，
  可判定项（阈值 / 枚举词表）分流进代码。
- **MIT 署名随改写**：每篇 front matter 带 source/source_ref/license，许可全文见 `许可/`。
- **GPL 不平移**：GPL 项目（如 webnovel-writer）仅作结构参考，不搬代码或文本。

## 目录结构

分类轴 = **体裁档**（一篇只属一档，与写稿面 `kind` 判据对齐）；
注入面（写稿 / 三审 / 对话）不进目录名，由 `src/knowledge/catalog.ts` 的 `faces` 承载。

| 类目 | 内容 | 篇数 |
|---|---|---|
| 通用 | 跨体裁通用的写作方法（情节 / 冲突 / 人物 / 关系 / 对话 / 情绪 / 技法 / 读者 / 质量） | 9 |
| 长篇 | 连载专属：钩子、反转、悬念、节奏与升级、情绪引擎、核心梗、开篇、大纲、题材框架、质量清单 | 10 |
| 短篇 | 单篇闭口专属：章节/段落钩子、反转、悬念、情绪释放、题材公式、质量清单 | 7 |
| 去味 | 去 AI 味的判断面（判定面归代码） | 待建 |
| 题材 | 题材卡：一类一张，写稿面按书题材命中召回（≤2 张） | 32 |
| 许可 | MIT 许可全文与署名件 | 1 |

**类目 = 体裁档，不是题材**：题材（仙侠/悬疑/都市等）由 `题材/` 的卡承载——
卡只校准题材味，不另开体裁档目录。篇目与消费面一律以 `src/knowledge/catalog.ts` 为准。

题材卡按书题材召回：判据 = 卡 front matter 的 `aliases` 命中书级 `book.yaml` 的
`book.genre`（全等优先于包含，至多 2 张；未设题材不召回）。建书只把命中的卡播进书根，
未命中卡仍可随包读取；召回规则与卡清单见 `题材/README.md`。

长短两档在「钩子落在哪、反转何时闭口」上口径相反，故同名篇目各档一份、
互不引用，注入时按书 `kind` 只取本档篇。

对话面的作业包（`resources/skills/*.md`）可经 front matter `references` 单向引用本目录篇目，
取用时按书档只嵌本档那篇（`通用/` 等跨档类目两档共用）；引用不复制正文，改语料只需改本目录。

校验：知识层为纯文档（AI 运行时按本索引读取），manifest 对账有正式门——
`npm run check:knowledge`（scripts/check-knowledge.ts：_manifest.json 与实际文件
sha256/路径任一失配、盘上存在未登记资产、随包语料与 `知识层/` 原稿不一致、
catalog 声明注入面的篇目随包缺件、署名键缺失、作业包 `references` 指向的篇缺件、
题材卡别名声明缺失，
均即红，已入 CI 与 tag 发布门）；
内容错漏直接改对应 md，并同步 _manifest.json 的登记与 sha256。
