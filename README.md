# CLWriting

写给中文网文作者的桌面写作软件，长篇和短篇集都能写。

[![Node](https://img.shields.io/badge/Node-%E2%89%A524-339933?logo=node.js&logoColor=white)](https://nodejs.org)
[![Test](https://img.shields.io/badge/tests-8137%20all%20green-4FC08D?logo=vitest&logoColor=white)](#技术栈)
[![License](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

先说清楚一件事：这是写作软件，不是 AI 工具。建书、大纲、设定、正文、审稿、定稿，整套流程都在这个应用里。AI 只是其中一环——起草、改写、分析它可以代劳，读稿和拍板永远是你自己。

## 怎么用

打开应用就是书架。建书只要填书名和题材，选长篇还是短篇集，目录结构自己生成。

设定花的时间最多，也最值得。大纲、角色、世界观、物品都有表单；长篇的大纲分总纲、卷纲、章纲三层，短篇没有卷纲，章纲里带反转线索表和情绪曲线。这块写得越细，后面机器能帮你核对的就越多。

正文自己写，或者点「全自动写章」。AI 起草之后，程序会把稿子过一遍体检：复读、句式、禁词、比喻密度，这类有明确标准的问题不过关就打回重写，全过了才交给你。重写有次数上限，到顶了会停下来把问题摊给你，不会自己烧钱。

改稿走三审。长篇三个视角：读者、编辑、设定校对；短篇看钩子、情绪反转、收尾。AI 给意见，改不改你说了算。最后定稿一章一章确认，定稿前程序再核一遍：设定里写过的，正文里到底写了没有，对不上先拦下来。

## 长篇和短篇是两套结构

| | 长篇 | 短篇集 |
|---|---|---|
| 大纲 | 总纲 → 卷纲 → 章纲 | 只有章纲 |
| 章纲里带什么 | 账本推进声明 | 反转线索表、情绪曲线 |
| 审稿视角 | 读者、编辑、设定校对 | 钩子、情绪反转、收尾 |
| 账本 | 六类线索，逐章推进收束 | 没有，按清单逐条核 |

长篇的核心是那本账。悬念、感情线、布局线、设定线、成长线、关系线，六类线索各有各的目录和格式，哪条线在哪章埋、哪章推、哪章收，都记在账上。设定和正文对不上，是长篇最常见的死法，这本账就是给机器核对的，不靠你记。

## 顺手工具

伏笔填上关联词，程序会扫正文，告诉你它在哪章埋的、最近一次提到是哪章，悬久了标风险。纯本地搜索，不花 AI 的钱。字数按天记账，实际进度和规划一对照，节奏跑偏提前提醒。文风库管禁词、铁律和手法条目，机器体检和 AI 写作共用一套。

关系图（Beta）看角色关系，文风收割（Beta）从你写好的正文里提取风格条目。AI 的每次生成、每次改写都记在事件审计里，查得到。选中一段文字，可以让 AI 改写或分析。工作台里有个对话助手，查资料、改文件都能代劳，有风险的动作会先问你。

顺带说体检：那套检查全是脚本判定，断网照跑，不烧 token。front matter 格式、禁词、字数、复读、句式、意象密度、专名、信息差，该查的都查。红项直接打回重写；黄项不拦流程，跟着稿子进审稿报告。

## AI 怎么接

AI 服务自己配，Anthropic、OpenAI Chat、OpenAI Responses 三种协议，官方接口和中转站都能接。

Key 存在本机应用数据目录，目前只做混淆级保护——不是加密存储，请勿把该目录放进同步盘或公开备份。Key 不进 git，也不进日志。所有请求走同一个入口，超时、重试、用量和花费都在这一处记账；单章有预算上限，写章循环烧到线就停。没有遥测，除了你自己配的 AI 服务，不向任何第三方发请求。

## 你的书就是一个文件夹

书就是一个普通文件夹，里面全是 Markdown 和 YAML。备份、换电脑、用别的软件打开，都随你。

```
我的小说/
├── 写作/          # 正文，按卷分目录，一章一个 .md
├── 大纲/          # 总纲、卷纲、章纲
├── 设定/          # 世界观、境界体系、人物名册、伏笔
├── 布线/          # 账本六类线索，每线一个 .md
├── 文风/          # 文风铁律、禁词与手法条目
├── 素材/ 笔记/ 废稿/
└── 项目/ 工作区/   # 文档清单、字数日记 / 版本快照、回收站、导出产物
```

正文是带 YAML front matter 的 Markdown，设定和账本也是，直接拿编辑器改没问题，回来照常用。

它想解决的就一件事：长篇写到两百万字，设定不崩、不吃书。不指望 AI 自觉，靠账本核对、伏笔追踪、版本快照兜底。

## 下载与安装

去 [GitHub Releases](https://github.com/Jevanzhu/CLWriting/releases) 下载对应平台的包，每个版本都附 SHA256SUMS.txt，可以校验下载没被动过手脚。

安装包没有做正式的代码签名，首次运行被系统拦一下是正常现象，不是文件坏了；也不自动下载、不自动安装——启动时只会静默检查一次新版本（仅访问 GitHub 的公开接口，不发送任何本机信息），有新版本会在界面上提一句并给出下载页链接，升级仍是手动：下载新包、退出应用后覆盖即可——书稿都在书库文件夹里，怎么升级都动不到它们。

**Windows**（便携 zip，Win10/11 64 位）

解压到任意目录，双击 `CLWriting.exe` 就能用。首次运行 SmartScreen 提示「已保护你的电脑」时，点「更多信息 → 仍要运行」。

**macOS**（dmg，需 macOS 13 及以上）

M 系芯片下 arm64 版，Intel 机型下 x64 版，拖进「应用程序」。首次打开被拦时，到「系统设置 → 隐私与安全性」点「仍要打开」；若提示「已损坏」，在终端执行 `xattr -cr /Applications/CLWriting.app` 后再打开。

另外，书库路径建议控制在 200 字符以内，避开系统的路径长度限制。

## 技术栈

Node 24+，TypeScript strict。界面 Vue 3 + Pinia + Vite，编辑器 CodeMirror 6，桌面壳 Electron；数据是 node:sqlite（检索索引）加 JSON/YAML 文件；AI 接三个协议（Anthropic、OpenAI Chat、OpenAI Responses），统一走 runTask 编排，重试、超时、用量都在这一层管。测试 vitest（8137 单测）+ Playwright（33 specs / 54 用例）——1309 个测试文件 / 8137 单测全绿是合入门槛，CI 会核对本文件声称的数字，对不上直接红。
