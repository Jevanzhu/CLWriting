## 三、P1 实锤（主审亲核，证据链完整）

**P1-1：utilities.css 全局 `.is-drag` 命中三页根的同名状态标记类——桌面态 Library/Shelf/Welcome 整页变拖拽面。**

- 证据链：
  1. 三页根元素**既有**绑定（HEAD 即如此，本批未动）：`Library.vue:80` / `Shelf.vue:85` / `Welcome.vue:63` 形如 `<div class="library" :class="{ 'has-traffic': isMac, 'is-drag': hasDesktop }">`——此处 `is-drag` 是**「桌面态」状态标记类**，供页内后代选择器 `.library.is-drag .lib-titlebar { -webkit-app-region: drag }`（`Library.vue:177`、`Shelf.vue:283`、`Welcome.vue:172`，均保留）把拖拽限定在页内标题栏行；
  2. HEAD 全局 css **零** `.is-drag` 规则（`git grep '\.is-drag' HEAD -- src/studio/web-next/src/styles/*.css` 空），页根本身从不携带 app-region；
  3. 本批 `styles/utilities.css:17` 新增全局 `.is-drag { -webkit-app-region: drag }` 首次命中**页根自身**；app-region 以继承语义生效（Blink 将其标为继承属性，Electron 文档亦要求交互子件显式 `no-drag` 反制）→ 桌面态三页**全部内容**成为窗口拖拽面；
  4. 三页 scoped 内零 no-drag 反制（`grep app-region` 三页仅标题栏 drag 各两条）→ 书卡/打开书库/新建/最近列表等点击将被窗口拖拽吞掉，桌面端开书主链入口不可用。四壳层消费点（`SidebarLeft.vue:35` `.left-tabs` / `SidebarRight.vue:70` `.right-topbar` / `TabBar.vue:81` `.tabbar` / `ViewHeader.vue:26` `.view-header`）本身即拖拽容器且子件 no-drag 齐备，收敛对它们等价无损——泄漏仅在三个页根。
- 成因：utilities.css 收纳判据 2「模板消费点全数定位」执行不彻底——只定位了 4 个壳层容器（定义同构），漏了 3 个页根的**同名异语义**（标记类）用法；判据 1「全库无同名异体定义」按规则体查成立，但没防住「同名不同用途」这一维。
- 修法建议（待作者指令，本批复核零代码改动）：
  - **方案 a（推荐，根治）**：三页根标记类改名 `is-desktop`（语义本就是桌面态），三页 scoped 后代选择器 `.library.is-drag .lib-titlebar` 等随改 `.library.is-desktop …`（各页 2 处），utilities.css `.is-drag` 保留——全局规则从此只属于真正的拖拽容器；
  - 方案 b（最小回退）：utilities.css 不收 `.is-drag`，四壳层组件复原 scoped 12 行（该类收敛放弃，其余 17 组不受影响）。
