### D. v4 存量迁移——**实施后同日拆除（2026-09-03 二次裁决）**

**裁决**：作者指出「项目还只是 RC，没有真正的使用上，所以没有历史遗留书库和数据，现在的书库只是测试用的」，确认拆除。已删 `src/install/migrate-normalize-v4.ts` 及其 7 个测试用例、`studio/server/index.ts` 启动链挂点。

**理由（裁决时记档）**：v4 的两个角色在当时都没有受众——①一次性存量迁移服务「批一之前的旧书库」，但世上不存在这样的库（唯一测试库实测已全规范，v4 对它零写）；②常驻自愈扫描的独有价值只剩「替再也不会被应用编辑的文件做保洁」（被外部改脏的文件经应用下次保存即自动归一，读侧容忍保证期间功能无损），代价却是启动链里风险等级最高的一类：**开机即对用户数据全文树扫描 + 改写 + 改名 + 清单改账**（定稿基线重算、books.jsonl 改写均为长期复审养护面）。无受众 × 高风险面 → 拆。

**拆除后的保证面（不受影响）**：写路径收口（应用产出生而规范）+ 读侧容忍（外部 CRLF/BOM 照常工作、经保存自愈）+ NFC 创建点（建书/文件名净化）+ 大小写敏感卷探测警告（宿主属性，与迁移无关）。**窄缺口如实记档**：外部引入的非规范文件若永不再经应用保存，将保持原字节形态（功能无损，仅字节不标准）；mac 老系统 NFD 文件名不会自动改名（手工改名即可）。

## 二、批二：流程差异归零——**不实施（2026-09-03 作者拍板）**

**裁决**：作者拍板「AI 对话历史/审计历史的迁移暂时放置不做」。对话史/审计（事件库）定位为**本机记录**——像浏览器历史一样留在各自机器上，旧机器不丢、只是不随身；书库文件夹本身跨机直接复制即可用（批一已达成的承诺，根 README「换电脑时」段已写成用户可见口径）。原拍板 ②迁移包携对话史/审计 ③手写 zip ④两批走 随之搁置。

**理由（裁决时记档）**：批二全套 = 手写 zip 读写器（约 300–400 行安全敏感面，zip-slip/CRC/header 自担）+ 事件库重键（对唯一 append-only 真相源新增改写路径）+ 导出并发编排（checkpoint×task-gate×残包处理）+ 导入向导与前端 UI——成本全部现在付出、每轮复审长期养护；而它服务的「跨机携带对话史」是低频需求，且对话中真正值钱的部分（AI 产出段落、账本记录、定稿）早已物化在书稿文件里。同盘同径两台 Windows 间 session/*.db 手动拷贝即用（哈希按绝对路径键，路径相同即免重键），win↔mac 才需要重键——边角中的边角。

**轻量退路（备案，需求真出现时再议）**：书库传输既然是拷文件夹，缺口只剩「N 个 .db + 重键」——一个几十行的小工具（扫 userData session 库、按书名匹配、`wal_checkpoint(TRUNCATE)` 后拷出、导入侧按新路径重算 bookHash 改名 + `UPDATE sessions SET book=<newHash>`）即可覆盖，不需要 zip、导入向导、前端界面。事件库搬进书库文件夹的方案仍维持排除（破坏纯文本书库定位 + 同步盘 SQLite/WAL 损坏风险 + 键控按路径哈希的手术更深）。
