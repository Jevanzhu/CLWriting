## 四、发现清单

分级：P1 = 用户可见数据污染/功能失效面；P2 = 明确缺陷或规模化退化，应修；P3 = 低危/边角/测试面；观察 = 记档不动。

### P1×1

**R-P1-1（F 域）SSE 断线重连 text 事件重复拼接**（代码内既有登记「批2-C」，本审独立定档 P1）
- 位置：`src/studio/web-next/src/composables/useSse.ts:226-234`（登记注释，四条证据链在案）；消费面 `src/studio/web-next/src/stores/workbench.ts:168`（`textOut.value += e.text` 盲拼接）。
- 机理：事件流无 id/seq、SSE 帧无 `id:` 行、`sync` 无内容水位、前缀对拍不安全——断线重连（含服务重启 `sse.resync()` 断旧连新）后重放的 text 增量与已拼入内容重复 → 对话区文本段落重复。
- 影响：网络抖动/服务重启场景下用户可见内容污染；写作主链路不受影响（正文持久化不依赖该流）。现状兜底：F4 水印。
- 修法需服务端契约变更：事件 seq + 重放锚点（或重连时 `text_reset` + 快照对齐）。**批 1 主项。**

- 机理：大文档编辑期每 2s 一次全量字符串化 + 渲染进程主线程同步写——200 万字设计目标下单次 stringify 可达数十 ms 级 CPU 峰值，叠加输入节拍可感卡顿。属峰值型非泄漏型（§五）。
- 修法：镜像内容增量/摘要化或上限收紧；写侧异步化评估（崩溃恢复语义需保——R55-F-3 取舍在案，改动须对照其回归）。

**R-P2-3（C）lead-finalize ↔ format/leads 四处同步副本漂移风险**
- 位置：`src/document/lead-finalize.ts:371-382`——`KNOWN_FM_KEYS`、`HISTORY_ENTRY_RE`、`bodyBeforeHistory`、`readLeadFromBytes` 四件为 format/leads.ts 内部实现的自我声明「同步副本」。
- 风险：任一侧演进（fm 键增删、历史分隔正则调整）另一侧不随动 → 定稿链与格式链静默分叉。修法：格式模块导出单源，lead-finalize 改引用。

**R-P2-4（C）branch-tree supersede 区间过滤 O(events×slots)**
- 位置：`src/events/branch-tree.ts:161-169` 与 `:205-211` 两处同型——逐事件 `slots.some(([p, root]) => ev.seq > p && ev.seq < root)` 线性扫区间表。
- 机理：长篇事件量（数万级）× 区间数线性增长 → 保活判定平方级；触发面为分支树重建/裁剪。修法：区间排序后二分或游标归并（一次排序线性合并）。

**R-P2-5（C）listEvents 消费方全书投影常驻**
- 位置：定义 `src/events/store.ts`（node:sqlite 游标流式，PM-10 证伪记在案）；消费方 `src/studio/server/api/audit.ts`、`api/chat-history.ts`（另 ai/trace-stats、ai/cost-stats、knowledge/update、ai/orchestrate/chat/restore 同族）。
- 机理：listEvents 契约为全量投影（total/truncated 需全书计数），audit/chat-history 等端点每次请求把全书事件物化为数组驻留至响应完成——200 万字书事件量大时内存峰值与延迟双升。
- 修法：消费方分页/游标下推评估，与台账 PM-10（尾读通道立项）合并拍板。

**R-P2-6（G）SampleCandidateList v-for key 含全章正文**
- 位置：`src/studio/web-next/src/components/learn/SampleCandidateList.vue:110-111`——`:key="`${s.出处}\u0000${s.正文}`"`。
- 机理：key 为完整正文文本——列表 diff 大字符串逐项比较/哈希，样本多时（数十条 × 全章）渲染开销放大；文本相同的不同样本被 key 去重合并（正确性边角）。修法：稳定序号/数值 id 键。

## 五、内存泄漏专项结论

**零传统泄漏**（五面静态配对验证，全部成立）：

1. **监听器**：全仓 `addEventListener`/`removeEventListener` 计 586/586 配平；逐文件「失衡」复核均证伪（fullscreen.ts 互斥分支各自成对；heartbeat.ts setInterval 命中系注释文本；events/store.ts + useHeartbeat.ts 计数虚增系类型注记行）。
2. **定时器**：CLI 生命周期型（脚本退出即释）或显式清理/unref（SSE 心跳；dirty-mirror `mirrorTimers` 删即清）。
3. **子进程**：server-manager 停机 kill 链 + `waitOnChild` + 工具进程 `once('exit')` 观察者；桌面侧 FontList 超时熔断在位（PM-12 生产接线系功能挂账，台账 §三，非泄漏）。
4. **模块级缓存全部有界**：mtimeNs+size 指纹键 + FIFO 上限 + 书前缀失效——md-text-cache 4096 条/64MB 双闸、rebuild 2048、manifest 32、probe 4096、trueCase 512，逐点亲验在位。
5. **SSE/网络**：服务端 client 注册表 close 即摘；客户端 EventSource 单例 + 重连重建 + 卸载退订；Electron 窗口 closed 处理链在位。

**残余为峰值型非泄漏型**：R-P2-2（2s 全量 stringify CPU 峰值）、R-P2-5（全书投影常驻内存峰值）、R-P3-3（learn 全书数组一次性峰值）——三者即 §四 对应项，修法同处。结论：**「200 万字长篇不崩」设计目标下，无泄漏性障碍；风险集中在峰值型三处，均已有明确修法。**
