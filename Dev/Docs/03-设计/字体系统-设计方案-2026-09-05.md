## 一、背景与问题定义

### 1.1 三字体面现状

| 面 | 现值（tokens.css） | 证据 | 状态 |

### 1.3 缺口的用户可见形态（问题定义）

正文默认栈 `PROSE_DEFAULT_STACK = ['LXGW WenKai', 'Noto Serif SC', 'SimSun']`（useSystemFonts.ts:52-54；tokens.css:82 同源）。普通 win 用户：

- 'LXGW WenKai' 未装（非系统字体）→ 'Noto Serif SC' 未装 → **落 SimSun（中易宋体）**：17px + ClearType 下点阵混合渲染发虚，「设计意图整个落空」。
- 正文选择器默认态解析按已装列表进行——裸机用户解析不到文楷，显示回落占位，**用户不知道默认该是什么**。
- 用户想要文楷观感，唯一出路是自己找字体安装（选择器只列已装）。

**作者机盲区警示**：本机（作者开发机）实测装有 Noto Sans SC（三档 + VF）与 Noto Serif SC（VF）——默认栈第二跳恰好命中，**作者在开发机上从未见过裸机真实观感**。普通用户看到的是宋体。

### 1.4 历史决策账（本设计必须直面）

- **2026-08-31 J5**：内嵌字体（MiSans/Noto）试用后全部撤，包体 -29MB；结论「渲染质量由行高/字号/字重/对齐体系保证」（tokens.css:122-124 注记）。→ 本次若内嵌，量级必须压到个位数 MB 且只嵌正文一款，与该决策不矛盾（当时撤的是 UI 面全家桶）。
- **win +1px 字号档**（tokens.css:129）：ClearType 小字 hinting 差一档的既有补偿，正文 17px 是在此基准上的取值。
- **win 亮色正文提亮 #2e2e2e**（tokens.css:138-140）：ClearType 偏黑闷的既有补偿。

## 二、事实底座（2026-09-05 三源调研）

### 2.1 三家对照（Cherry Studio / Obsidian / 本项目）

| 维度 | 本项目 | Cherry Studio（参考项目源码） | Obsidian（公开资料） |
|---|---|---|---|
| win 界面默认 | Segoe UI + 雅黑 UI（显式） | 雅黑 UI 首选（font.css:19 body[os='windows']，但中文前置→数字也雅黑） | Segoe UI（经 ui-sans-serif 兜底，无 CJK 显式声明） |
| win 正文默认 | 指名文楷→裸机落宋体 | default 同全局；notes 衬线档 = 裸 `serif` 关键字→**同样落宋体**（styles.ts:515） | **与界面同栈**（无衬线系统栈），零衬线倾向 |
| CJK 内嵌 | 无 | 无 | 无（只内嵌 Inter / Source Code Pro 两个拉丁小字体） |
| 字体选择器 | 已建成（1.2） | font-list 枚举 + Combobox 全字体预览 + 全局/代码两项；正文二元 serif 开关 | 三项设置手输名字；枚举靠社区插件 |
| 分层架构 | 用户覆盖 → CSS 默认栈 | `var(--app-user-font-family, 默认)` 单槽 | override→theme→default 三层 + `'??'` 占位容错（为主题生态设计） |

结论：①「win 界面默认 = Segoe UI + 雅黑」三家一致，我们现状即三家最稳（显式 + 数字走 Segoe）；②「好看的中文正文」两家头部产品官方都不背（Obsidian 正文=界面同款，Cherry 衬线档落宋体），社区文楷/思源风全靠用户自装——**我们做正文字体是差异化口味题，不是补课**；③ Cherry 单槽 var 注入是我们现有架构的同类，Obsidian 三层制现阶段不必抄（无主题系统）。

### 2.2 Chromium/Windows 中文兜底规则（为何裸机落宋体）

Chromium 按脚本→默认字体规则兜底（非产品层可控）：sans 语境 → 微软雅黑（旧版/旧系统配置曾默认宋体，前端经典坑）；**generic `serif` 关键字 → 中易宋体 SimSun**；monospace → Consolas + CJK 兜底。我们 `--prose-font` 尾端 `, serif` 未命中指名字体时即走此规则。

### 2.3 干净 Win11 自带中文字体（本机 Fonts 目录实证）

系统级自带六族：**微软雅黑**（msyh.ttc，L/R/B + UI 变体）、**宋体**（simsun.ttc）、**黑体**（simhei）、**楷体**（simkai）、**仿宋**（simfang）、**等线 DengXian**（Deng/Dengb/Dengl，L/R/B）。华文系（ST*）与方正系（FZSTK/FZYTK）系 Office 附带，不保证存在。**推论：OS 自带的「衬线正文」实际不存在**——宋体点阵混合放大发虚、楷体零屏幕优化单字重；「好看的中文正文」在系统里没有答案，坐实正文字体本体需自带。

## 三、设计面拆解（改动面精确定位）

1. **UI 面：不动**。现状三家最稳且 J5 刚定稿。
2. **选择器面：小改**（仅当内嵌/下载落地时）——①useSystemFonts 枚举结果合并「内置字体」静态项（chineseFonts 计算属性）；②默认态解析（defaultProseFontCn 等）把内置字体纳入已装口径；③FontPicker「内置」分组标注（可选项，一期可不做分组只并入列表）。
3. **等宽面：不动**（Consolas；代码块中文极少，CJK 兜底可接受）。
4. **正文面：核心缺口**——三个子决策：获取方式（内嵌/按需下载/零内嵌）× 默认字重（Regular/Medium）× fallback 兜底（SimSun 改造）。

## 四、组合备选（A-E，互斥可组合）

> 每组合含：内容 / 改动面 / 体积账 / 风险 / 工作量。组合 A 的 fallback 改造是**任何组合都建议叠加的兜底层**（见 D5）。

### 组合 A「零内嵌·止损」

- 内容：`PROSE_DEFAULT_STACK` 与 tokens.css:82 的 SimSun 槽位前插 `'KaiTi'`（楷体，系统自带）→ 裸机落楷体而非宋体；UI 文案「默认」tooltip 注明兜底链。
- 改动面：useSystemFonts.ts:52-54 + tokens.css:82 两处 + 相关测试锚。
- 体积：0。工作量：半天。
- 风险：系统楷体无屏幕优化、单字重，ClearType 下 17px 未必优于宋体——**须样张验证**，可能白改。
- 适用：作者拍板「零内嵌红线不可破」时的最低限动作。

### 组合 B「内嵌文楷 GB Lite」（主推）

- 内容：文楷 GB Lite 单字重转 woff2（cn-font-split 分包）入 `resources/fonts/`（electron-builder extraResources，asar 外）；`@font-face` 注册 family `'LXGW WenKai'`（**同名注册**：附加许可允许原名 web 交付；用户已装文楷时 @font-face 定义优先生效，但内嵌版本=官方 Lite 原样转换，遮蔽无感）；默认栈首选直接命中，裸机观感与作者机拉齐；选择器枚举合并内置项（三、2）。
- 字重子选项（对应 D2）：**B1** Regular 当正文（最忠实）；**B2** Medium 当正文 + CSS `font-weight:700` 映射 Medium（正文加粗走真字形免 Chromium CJK 算法加粗发糊，零额外体积——技术默认推荐）；**B3** Regular+Medium 双档内嵌（+5-6MB，加粗真字形，默认 Regular）。
- 改动面：构建脚本（cn-font-split 步骤 + electron-builder 配置）/ fonts.css @font-face / useSystemFonts 内置项合并 + 默认栈解析 / tokens.css 注记更新 / 版权页 OFL.txt 入口 / 测试（@font-face 构成、内置枚举合并、默认栈锚）。
- 体积：**+5-6MB**（B3 ×2）。工作量：1-2 天（含构建链）。
- 风险：①文楷 Regular ClearType 偏细（Screen 版 25.7MB 为升级路径，B2 为零成本先行解）；②cn-font-split 工具链引入（Node 依赖，构建期 only）；③ -29MB 前科的作者接受度（本组合量级 1/5-1/6 且只嵌正文一款，性质不同——J5 撤的是 UI 面全家桶）。
- 适用：作者接受个位数 MB 包体换「全平台正文观感统一」。

### 组合 C「按需下载文楷」

- 内容：交互与 B 全同（同名注册、内置项合并），字体文件不进安装包——首次进入正文页/首次设置时下载到 userData/fonts/，FontFace API 从本地文件加载；已下载即离线可用；下载失败/离线静默回落组合 A 兜底链。
- 改动面：B 的全部 + 下载器（URL/重试/校验哈希/版本号随字体更新）/ 存在性探测与加载时序（首帧闪替防护）/ 设置项「正文字体包：已下载/未下载/重试」/ 隐私与网络披露文案 / 测试（下载状态机、失败回落、离线路径）。
- 体积：0。工作量：2-3 天。
- 风险：工程面最重（状态机 + 失败矩阵）；首启无网用户体验分叉；版权文件仍须随包附 OFL.txt。
- 适用：作者拍板「安装包零增量红线」。

### 组合 D「等线特供」

- 内容：win 平台 tokens.css 分支 `--prose-font` 默认栈改 `'DengXian', 'SimSun', serif`（等线系统自带零内嵌）；mac 腿不动。
- 体积：0。工作量：半天。
- 风险：①等线非衬线/非文学体，与写作产品气质不符概率高；②小字号 hinting 弱（微软自家 Office 正文默认，但屏显优化一般）；③J5「一套视觉」原则在字体族层本就允许平台分支（1.1），但**正文观感分叉**比 UI 字体族分叉更刺眼。
- 适用：样张环节作为「零内嵌对照组」参与对比，不预设入选。

### 组合 E「内嵌思源宋 SC」

- 内容：与 B 同架构，字体换思源宋 SC（Medium 当正文，字重全）。
- 体积：+5-6MB 同级。工作量：与 B 等同。
- 风险：小字号偏细；气质「正式书卷」与网文写作的「温度」取向需作者过目定夺。
- 适用：样张环节与文楷对决的另一方；若作者要「正文内置两款任选」，可与 B 并存（选择器内置组两项，+11-12MB，不建议一期做）。
