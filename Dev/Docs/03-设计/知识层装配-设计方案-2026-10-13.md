## 二、口径(拍板)

| # | 项 | 定为 | 弃档(理由) |
|---|---|---|---|
| ① | 三层楼切分与作业包定位 | 技能包保留自有正文(用户可自建、`read_skill` 按需取)并**单向引用**语料篇(`references`);方法论本体单源在知识层 | 完全并入语料会丢用户级根与按需取;只去重不改机制则重叠仍在 |
| ② | 写稿/三审面吃不吃作者新增篇 | **固定篇名**语义:`book.yaml` 无选材声明;作者按书不同走「覆盖同名篇」(书级 > 随包),加全新篇只对对话面生效——文档写实 | 加 `book.yaml` 选材段会引入第二套选材配置;按类目全量+帽会让写稿 prompt 体量不可预期 |

| ⑤ | 质量检查清单速查 / 题材路由速查 去向 | catalog 声明 `purpose` + `faces: []` 显式「不下发」并记原因(前者已吸收进三审 prompt 基线;后者建书/大纲面未接线) | 移出知识层会丢「供人读」价值;接到建书面是本批外的功能活 |
| ⑥ | 批序 | **A→B→C 三批**,批 A 先行(纯重构、零行为变,是 B/C 地基) | 一次做完会让回归面与语义变互相掩盖 |

## 三、目标形态(三层楼)

```
第 3 层 协议   resources/prompts/*.md          作业协议(writer/review/analyst/rewriter)
                └ 版本化哈希门 + overlay;消费面 = 各 runSpec;不引用下层
第 2 层 作业包 resources/skills/*.md           三根覆盖(书 设定/技巧 > 用户 skills/ > 随包)
                └ 索引进对话面(帽 800 码点),正文 read_skill 按需取(帽 20000)
                     ↓ references(新,单向)
第 1 层 语料   知识层/(书级) > resources/knowledge/(随包)
                └ 三面注入:写稿(信号选材)/ 三审(lens 映射)/ 对话(类目序)
                  manifest + sha256 + 逐字节对账门 + 播种/升级
```

一句话:**协议说「怎么干活」,作业包说「可按名取用的成套打法」,语料说「判断类知识本体」**。方法论只在语料层一处;作业包与协议不重复承载方法论正文。

## 四、批 A:装配收敛(纯重构,零行为变)

**新增四个文件**(全在 `src/knowledge/`):

- `catalog.ts`——篇目注册表(篇目常量唯一定义处,替代现寄居 `select.ts` 的四常量):

```ts
export type CorpusPurpose = 'judgment' | 'license' | 'index'   // 借 V8「执行形态」声明
export type InjectionFace = 'draft' | 'review' | 'chat'
export interface CatalogEntry {
  rel: string                      // '<类目>/<篇>.md'
  category: string                 // 目录名即分类；类目取值集合归语料档（本文不锁，D1 重建后为 通用/长篇/短篇/去味/题材/许可）
  purpose: CorpusPurpose
  faces: readonly InjectionFace[]  // 注入面;空 = 不下发(purpose/note 记原因)
  note?: string
}
```

- `inject.ts`——装配单点(解析→截断→标题→计量→拼段→登记→超帽处置)。**文件名避与 `src/process/assemble.ts`(近况组装)重名**;导出名 `assembleKnowledge` 不变:

```ts
export interface PieceRecord {
  rel: string; layer: 'book' | 'bundled'; source: string   // 登记名(书级 / 知识层(内置)前缀)
  reason: string                                            // 为何入选(人话)
  codePoints: number; truncated: boolean
}
export interface DroppedPiece { rel: string; reason: 'missing' | 'cap-total' | 'switch-off' }
export interface KnowledgeAssembly {
  text: string; sources: string[]; records: PieceRecord[]; dropped: DroppedPiece[]
}
export function assembleKnowledge(args: {
  bookRoot?: string; rels: readonly string[]; heading: string
  fileCap: number; totalCap: number; enabled?: boolean
  reasonOf: (rel: string, i: number) => string
}): KnowledgeAssembly
```

- `chat-method.ts`——对话面策略(从 `ai/prompts/chat.ts` 迁出,含选篇与帽);`ai/prompts/chat.ts` 只留调用。
- `switch.ts`——开关单源:`knowledgeInjectionEnabled(config, face)`,`face === 'chat'` 恒 true(作者主动问答,语料是其依据来源——设计稿 §五口径,代码里**显式声明**),其余 `config?.auto?.knowledge_injection !== false`。

**装配语义(定死)**:单篇超帽 → 保头截断 + 标注(维持现值);合计超帽 → 该篇记 `cap-total` 并**即止**(低优先级篇不得挤掉高优先级篇的位置;候选表本身即优先级序);两级皆缺/不可读/超 256KB → `missing`;关停 → 不读盘,逐 rel 记 `switch-off`。

**改动面**:`select.ts`/`review-method.ts` 变薄(只留选篇规则 + 帽声明,调 `assembleKnowledge`);`ai/prompts/chat.ts` 删 `buildKnowledgeContext` 与三帽常量;`draft-pipeline.ts:645-648`、`review.ts:415-424` 改调单源开关 + 新返回型;`check-knowledge.ts` 改读 catalog。

**测试面**:新增 `test/knowledge/inject.test.ts`(`it.each` 面表:截断/合计即止/缺失/开关关/空候选);三面测档收去重复的帽与截断断言、只留各自策略(选篇规则 / lens 映射 / catalog 序 + 额外篇);新增 switch 面表(chat 恒 true;draft/review 遵显式 false)。

**安全性质**:当前帽的数值关系(单篇 2000 < 合计 3000/6000)让「continue vs break」不可观测,故批 A 零行为变;唯一行为差异是对话面选篇序,而对话面现实际只有 1 篇方法论(另 1 篇未随包),不可观测。

## 五、批 B:作业包升级

**技能包 frontmatter v2**(三篇):

```yaml
name: 对话节奏
description/whenToUse:（保留,人话）
when_face: chat            # 新:投放面(可选,缺省 = 不限面)
when_kinds: [long, short]  # 新:适用档位(可选,缺省 = 不限档)
references: [通用/对话技法速查.md]   # 新:引用语料篇(单向;书级优先解析)
```

- **判据形态落平铺两键**(`when_face`/`when_kinds`,非嵌套 `when:` 块):frontmatter 解析是受限子集(平铺键 + 内联数组),嵌套块不在子集内;判据本来就只有面与档两个维度,两键即够,不为此扩解析器。
- **判据两侧同源**:索引投放(`buildChatContext`)与取正文(`read_skill`)同过 `skillDispatchOK`——只在一侧过滤会造出「索引里有、读了说没有」。档位判据取 `book.yaml` 的 `kind`(缺省 long),面判据按字面比较(写错面名 = 不投放 + warn 留痕)。
- **引用解析**:`loadSkill` 取正文后逐 `references` 走 `resolveCorpusFile(bookRoot, rel)`(书级覆盖随包,与三面同源),以 `## 引用篇目（来自本书知识层）` 附于正文后,同受 `READ_SKILL_MAX_CHARS`(20000)帽。模型无通用读文件工具(`chat` 工具面只有 read_chapter/read_skill 等),解析必须由代码做。
- **引用目标取现行 rel**:rel 一律指向 catalog 篇目(`src/knowledge/catalog.ts`);体裁专属篇按书 `kind` 取本档同名件,通用判断类走 `通用/`。
- **内容去重(实测重叠)**:`对话节奏` ⊃ 语料篇对话段(更偏操作)→ 保留操作清单 + `references` 引 `通用/对话技法速查`;`黄金三章` → `references: [长篇/开篇设计速查.md, 短篇/章节钩子速查.md]`(取用时按书档只嵌本档那篇);`场景描写` 无同域篇,不引。
- **`## 使用边界`**:三篇各补轻量边界段(借 V8 `## Off-limits` 之形,如「不覆盖本书设定;细节不得改变已确认事件」)。V8 四段协议(工件契约/作者介入/失败恢复)不逐字搬——其控制器是 LLM、协议必须写在 Markdown;我们的编排在代码(self-heal/落盘/作者通道均有代码与测试),协议细节留 prompts + 代码,避免双写。
- **引用门**:`check:knowledge` 增 `scanSkillReferenceMismatches`——`references` 声明的每篇须在 `知识层/` 且随包在位(判据同 catalog 的「声明即门」;引用篇缺件不报错、只静默少一块,故只有门能拦)。解析用 `parseReferences` 单源(门与运行时同一判据)。
- **`SkillMeta` 增 `when`/`references` 字段**(解析入索引;`formatSkillIndex` 不展示,索引面不变)。

## 六、批 C:报告面

`DraftPrompt` 增 `knowledge: { records: PieceRecord[]; dropped: DroppedPiece[] }`(`GET /draft-prompt` 已回传前端,加字段即得数据);三审面 dropped 随响应返回;对话面不入。**首期只到接口 + log,不上 UI**(UI 另开批)。

- **字段非可选**:`knowledge` 是必填(空段也是 `{records:[],dropped:[...]}`)——报告面要回答的就是「这一面是不是少给了料」,可选字段会让「没数据」与「没接通」两种状态在消费侧不可分辨。
- **三审按 lens 标注**:同看一篇可能被多视角取到,`records[].reason` 前缀视角名、`dropped[].rel` 前缀 `lens@`——否则回答不了「哪个视角缺了料」。
- **log 只记计数**:`入选 N 篇 / 未入选 M 篇（missing×a cap-total×b switch-off×c）`——带 rel 就成书库侧取值、须走诊断包内容门登记,而缺口计数已够回答「少没少、少在哪一类」;完整两列随接口返回。
- **对话面不入**:对话是作者主动问答(语料是其依据来源),无「按章选材」语义,report 无处可用。
