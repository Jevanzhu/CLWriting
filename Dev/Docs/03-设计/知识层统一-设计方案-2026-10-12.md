# 知识层统一(书级 > 随包)设计方案

- 定位:已实施设计正本。拍板 = 作者「写稿和三审我希望也走书根目录的,这样每本书都会根据不同的情况和设定来使用,也会更新」。
- 前身:`03-设计/知识层注入-设计方案-2026-10-11.md`(写稿/三审随包注入批)——该批把画稿/三审的**判断类技法**接进真模型链路,形态取「随包」;本批把三面读取统一为**书级优先、随包兜底**,三审技法由 prompt 固化改为运行时注入。

## 一、问题与口径(拍板)

原状两口径并存:对话面读书根 `知识层/`(实际因建书不建该目录而恒空转),写稿/三审读随包 `resources/knowledge/`;三审技法更是逐字**烧进** `resources/prompts/review-*.md`。结果是每本书的语料无从按书不同、改动语料要动源码。

| 项 | 定为 |
|---|---|
| 读取顺序 | **书级 `知识层/<rel>` > 随包 `resources/knowledge/<rel>`**(同名去重,高覆盖低);书级缺失/为空回落随包 |
| 三面同构 | 写稿 `src/knowledge/select.ts`、对话 `src/ai/prompts/chat.ts`、三审 `src/knowledge/review-method.ts` 共用 `src/knowledge/corpus.ts` 解析 |
| 分类口径 | **目录名即分类**(`知识层/方法论/*.md` 等);运行时不再读 `_manifest.json`(manifest 仍是仓库 CI 对账正本) |
| 三审技法 | **从 prompt 抽出,改运行时注入**;prompt 只留审查契约(只报问题/evidence/S1-S4/输出工具)与审计基线(通用章级判断条/连载连续性),视角对口技法按 lens 从知识层选篇 |
| 供给 | 建书时把随包语料**播种**进书根 `知识层/` 作作者可编辑起点;应用升级刷新「未被作者改动」的种子篇 |
| 升级判据 | 书级文件字节哈希命中随包历史哈希表(`resources/knowledge/versions.json`)= 未改动 → 升级;不命中 = 作者改过 → **永不覆盖** |
| 可复现 | 技法注入段经 `systemPromptSuffix` 拼在内置/overlay 解析**之后**(不参与 `matchBuiltinPrompt` 哈希);注入源并入 `promptFiles`(书级 = `知识层/<rel>`,随包 = `知识层(内置)/<rel>`)满足「模型可见 ⟺ 已记录」 |

## 二、实现面

- **新增** `src/knowledge/corpus.ts`:两级解析单源。`resolveCorpusFile(bookRoot, rel)`(书级经 `resolveWithinRoot` 防越界 fail-closed)、`listBookKnowledgeEntries` / `listBundledKnowledgeEntries`(目录扫描)、`BUNDLED_SOURCE_PREFIX = '知识层(内置)/'`。
- **新增** `src/knowledge/review-method.ts`:lens → 对口技法篇映射(`hook/emotion_peak/payoff/reader/editor/continuity` → 钩子/反转/节奏/人物对话四篇),`buildReviewMethodInjection(lens, bookRoot)`。
- **新增** `src/knowledge/seed.ts`:`seedBookKnowledge`(播种 + 升级,幂等)、`seedKnowledgeOnBookCreate`(建书,seedOnly)、`migrateBookKnowledge`(启动逐书升级)、`readKnowledgeVersions`。许可类目不播种(MIT 署名随包留存即满足)。
- **新增** `resources/knowledge/versions.json`:随包语料历史哈希表(播种/升级判据正本;`check:knowledge` 豁免逐字节对账)。
- **改** `src/knowledge/select.ts`:写稿选材改经 `resolveCorpusFile`(新增 `bookRoot?` 入参;缺省只读随包 = 旧行为)。
- **改** `src/ai/prompts/chat.ts`:`buildKnowledgeContext` 由 manifest 驱动改**扫描驱动**(书级 ∪ 随包方法论类目,书级优先);移除 manifest/`resolveWithinRoot` 依赖。
- **改** `src/ai/tasks/spec.ts`:`SpecOpts` 增 `systemPromptSuffix`(哈希解析后追加段,`runSpec` 自持 `\n\n` 分隔)。
- **改** `src/studio/server/api/review.ts`:逐 lens 调 `buildReviewMethodInjection`,技法段走 `systemPromptSuffix`,注入源并 `promptFiles`。
- **改** `resources/prompts/review-*.md`(6 档):摘去可抽出的视角对口技法(章尾八式/反转机制/打脸节奏/升级感三步/期待管理/对话质量/人物活人度/关系网);`versions.json` 追加新哈希 + golden fixture 同步。
- **改** `src/studio/server/api/books.ts`:建书成功后播种(在 server 层触发——`install/` 底座不得 import AI 层,依赖方向治理约束)。
- **改** `src/studio/server/index.ts`:启动链增逐书知识层升级。
- **改** `scripts/check-knowledge.ts`:`versions.json` 入豁免集。
- **改** `src/diagnostics/index.ts`:`knowledge-seed@...#rel` 入内容门例外表(随包语料文件名,跨书恒定)。

## 三·补、收口复核(简洁度/优雅度复审)修正项

收口后按「简洁 + 优雅」标准复读本批全部产出,修四处**判据重复**(非缺陷,是维护性债):

1. **扫描判据三处重复 → 单源**:`corpus.ts` 的书级/随包扫描原为逐行同构孪生(仅取根方式与日志措辞不同),`seed.ts` 又各抄一份遍历 + 一份同名跳过名单(三项同、顺序不同)。收敛为 `corpus.ts` 私有 `scanKnowledgeEntries(root, label)`,`seed.listBundledSeedRels` 改为复用随包扫描再滤类目——保证「播种面恒 ⊆ 三面读取面」,新增跳过项不再可能单边漂移。
2. **截断三连 → 单源**:`clipWithNotice(text, max)` 下沉 `src/shared/text.ts`(先例:`isUtf8`/`codePointLength` 同族收敛),写稿/三审/对话三面不再各写一遍「判帽 → clip → 拼标注」,标注文案(`…（超长截断）`,测试锚定)与码点口径单一处可改。
3. **无覆盖的截断路径补测**:`review-method` 的单篇帽分支此前无用例;补「超长 → 保头截断 + 仍登记书级源」。
4. **死代码删除**:`REVIEW_METHOD_TOTAL_CAP` 及其守卫分支——本模块是单文件映射,注入体实测 591–789 码点、单篇帽 2000 更紧,该分支恒不可达(原注释自认),删除后单篇帽即有效总帽。

测试面同时按「同族分支参数化一表」把六视角断言收成 `it.each` 表(顺带补齐此前只断言 3 个 lens 的登记名缺口)。

## 四、边界登记

1. **书级不做 manifest、不做 sha256 对账**:manifest 是仓库 CI 对账正本(`check:knowledge`),运行时读书按目录扫描。作者加料 = 往 `知识层/<分类>/` 丢 `.md`。
2. **用户级(`<userData>/knowledge/`)留位未做**:rank 表可扩第三级,本批只做书级 > 随包(诉求是「每本书按自己情况」)。**处置已定:不做**(诉求方向相反——该级是把各书拉齐,书级层已答「按书不同」;真出现跨书一致性诉求时应做「写面传播动作」而非读取面第三级)。原「留位」措辞不再作为待办读。
3. **升级刷新是启动动作**:随包种子篇哈希命中历史表才升级;历史表须随每次改随包语料追加(否则当次不可判,保守不覆盖)。
4. **语料同步仍是人工动作**:改 `知识层/` 原稿后须同步 `resources/knowledge/` 同名件并追加 `versions.json` 哈希,`check:knowledge` 只负责报红。
5. **技法抽出后 prompt 变薄**:三审跨书可比性从「基线 + 书级技法」两层构成;基线(契约/章级判断/连载连续性)恒在 prompt 保证同版本可比。

## 五、补批：注入开关 `auto.knowledge_injection`（2026-10-12）

**背景**:前身《知识层注入》§五.1 登记「无开关(未做)」时,写稿面按「删书级文件即关停」可行;本批的统一口径把书级缺失/为空改为**回落随包**,且建书播种 + 启动逐书升级会把随包语料种回书根——**删文件关停的出口因此消失**(改得动内容,关不掉存在)。开关是把这条出口补回来,即前身设计稿自己开的方子(「后续在 `book.yaml` 加段」)。

| 项 | 定为 |
|---|---|
| 键 | 书级 `auto.knowledge_injection`(布尔);全局托底 `knowledgeInjection` |
| 缺省 | **true = 注入**。全表唯一缺省 true 的回落(其余「功能开关」缺省 false)——注入是现行行为,缺省反了等于给所有存量书静默加关停 |
| 覆盖面 | 写稿面「写作方法参考」+ 三审面「视角技法参考」两处;**不含对话面**(作者主动问答,语料是其依据来源) |
| 判据落点 | **接线点**,不入 `select.ts` / `review-method.ts`(纯函数不该持「要不要做这件事」的编排策略):`draft-pipeline.ts` 与 `review.ts` 各一处早退 |
| 判据形态 | `=== false` 显式关。config 缺省(直调/测试路径)与键未设都照旧注入,**不因读不到配置而静默降级** |
| 关停形态 | 复用现成降级路径——写稿段与 `files` 登记一并消失、三审走「空段不入 prompt 不登记」。非新分支语义 |
| 前端 | 全局控件入「智能分析」页(知识层组);书级覆盖组入「本书」页分析组(全页唯一「未设 = 开」的组) |
| 三级链 | 书级显式值恒赢(判据 `=== undefined` 而非 `!== true`,否则作者「本书关掉」会被全局 true 反悔) |

**验收**:`test/process/draft-pipeline.test.ts`(off 段+files 双消失 / true 与未设同效)、`test/studio/server/review-doc-api.test.ts`(按 `llm/call` 的 `promptMeta.files` 断两头——只在接口 200 层断不出注入是否被摘)、`test/format/global-defaults.test.ts`(缺省 true / global 托底 / 书级两向不被翻案 / 脏值剔除不误关)、`test/format/yaml.test.ts`(YAML 惯例布尔 `on`/`yes` 与往返)、`test/format/yaml-schema-snapshot.test.ts`(叶键入 PUT 白名单锁)、`test/studio/webnext/dom/settings-book-analysis.test.ts`(组开关四态)。回退即红已实证:撤两处接线点的早退 → 写稿面与三审面各一例红。
