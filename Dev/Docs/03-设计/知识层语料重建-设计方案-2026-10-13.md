## 四、生产方法（逐篇四步）

1. **定题**：从 catalog 取 rel + 上游源 + 档位/面。
2. **取材**（只读 MIT 源）：标三类——**判断类**（角度/取舍/法则 → 进语料）/ **可判定类**（阈值/枚举/词表/正则 → 走 §五 分流进代码）/ **时效类**（平台榜单数值、样本统计 → 丢弃，避免过期污染长期语料）。
3. **速查化重写**（写作规范即质量门）：
   - **四段固定结构**：决策路由（什么信号选哪条法则）→ 法则清单（每条一句可执行判据）→ 自检清单（可打勾）→ 来源注。
   - **体量帽**：单篇 ≤3000 码点（对齐现行 `METHOD_FILE_CAP`/`KNOWLEDGE_FILE_CAP`）；题材卡 ≤3500。
   - **跨档口径切断**：长篇篇不出现短篇默认值（「每节 500–800 字」类），短篇篇不出现卷级指标——上游契约明文禁跨档读取，我们在自检清单里落成检查项。
   - **v8 结构借点篇**（如质量清单）：先列维度清单，合上底稿再自撰每节——结构照借、表达全自撰。
4. **登记**：frontmatter 三字段 + `_manifest.json` sha256 全量重建 + `versions.json` 追加首版哈希 + 门跑绿。

## 九、边界登记

1. **长期语料不收时效数据**：平台榜单数值/样本统计只收方法不收数字。
2. **v8 文本零字节**：借点仅结构（对照隔离见 §一.1）；违者 = 版权风险 + 本档作废。
3. **上游同步仍是人工动作**（现行口径）：本批一次性对齐到 `2cf7be6`，此后漂移按开放项管理。
4. **两处接口缺口登记**：① 作业包 `references` 在 long/short 分档后需按书档解析，而 chat 面现无档位判据（`buildChatContext` 不收 `kind`）——批 B 已补（判据落 chat 面内部 `readKind`）；② 三审 lens 扩充（§二③）——独立批已补（长篇产信息披露 / 情节与因果两视角）。
5. **题材卡不播种者仍可通过随包读取**（书级 > 随包语义不变），播种只决定「作者能否在书根直接改」。
6. **短篇书与题材卡**：卡按长篇语境取材（含「前中后期打法」）；机制面无档位裁切（短篇书命中即整卡下发），
