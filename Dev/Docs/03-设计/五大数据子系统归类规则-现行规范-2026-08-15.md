# 五大数据子系统归类规则（现行规范）

- 日期：2026-08-15（批次 E3 / CS-13，按 CLWriting 现状重建）
- 角色：**现行规范**（03-设计/）——新数据落盘前先归类，防「随手落盘不归类」的漂移
- 出处：8-14 原文已归档且本地删除（git 历史 0 字节占位，内容从未入库）——本条按 CLWriting 现状重建
- 关联：批次 E2（route schema 单点声明）提供数据接口的 HTTP 形态；F1（事件溯源）为会话数据单一事实源

## 一、目的

CLWriting 的数据落盘分散在文件系统 / SQLite / 内存缓存三层。归类规则回答四个问题：

1. 每一份数据**归哪个子系统**（职责唯一，防多处写同一份数据）；
2. **存在哪**（书目录 vs 用户数据目录；文件 vs SQLite vs 缓存）；
3. **读写入口**是什么（HTTP 端点 / 模块，禁止绕过入口裸落盘）；
4. 一致性规则（原子写 / append-only / 可重建 / 只增不改）。

## 三、各子系统细则

### S1 书库子系统（Book Store）

- **范围**：书元数据（book.yaml：书名/长线/格式版本/正文规范）、章节正文、文档树（`document/tree`）、定稿队列（`document/queue`）、版本与快照（`document/version` `document/snapshot`）、回收站（`document/trash`）、格式读写（`format/*`）。
- **位置**：书目录（`bookRoot`）。根元数据 book.yaml 是书库单一事实源（`install/books.ts` readBooks 是唯一读入口）。
- **写入口**：`process/draft-pipeline`（正文生成）、`document/finalize`（定稿）、`document/queue`（队列）、`format/*`（格式化读写）。HTTP：books/onboard/draft-save/documents/snapshots/io(export)。
- **一致性**：所有写走 `fs/atomic`（临时文件 + rename）；文档树用稳定 id（`document/stable-id`），重排不破坏引用；删除进回收站不直接删。
- **禁止**：绕过 `document/*`/`format/*` 直接 `fs.writeFile` 写章节正文。

### S2 事件子系统（Event Store）

- **范围**：会话事件（session/turn/user/assistant/tool/compaction 事件族），surface 投影（`events/projection`），历史恢复（`events/chat-bridge`）。
- **位置**：用户数据目录 SQLite（F1 决策：按书分库）。
- **写入口**：唯一——`events/store.ts` 的 append（事件写入仅经 `chat-bridge` 的事件构造器）；读——`store.listEvents` + `projection`。
- **一致性**：append-only（不更新不删除），replace 遮蔽（shadowStart/shadowEnd），重放按 seq 排序。手动编辑**不**事件化（F1 决策）。
- **禁止**：绕过 store 直接改 SQLite；向 prompt 注入无出处的模型可见内容（事件必须可回溯，CLAUDE.md「模型可见⟺已记录」）。

### S3 设置子系统（Settings Store）

- **范围**：全局（provider 注册表/当前模型/层级预算 tiers）、书级（机检阈值/偏好 prefs/completion 名单）、注入链（`process/settings-injection` 组装进 prompt）。
- **位置**：用户数据目录 settings + 书目录 book.yaml（书级覆盖）+ prefs。
- **写入口**：providers/settings/config/prefs 端点；`ai/provider/store` 是 provider 单一事实源。
- **一致性**：默认值显式 resolve——链路参数不允许隐式默认穿透（CLAUDE.md）；配置注入链单一（settings-context → settings-injection）。
- **禁止**：组件自行拼配置注入 prompt（须走注入链）；模型/阈值在两端点各写一份（单一事实源）。

### S4 知识子系统（Knowledge Store）

- **范围**：RAG 索引与检索（`rag/*`：embed/store/schema/index）、缓存（`cache/*`：schema/sync/rebuild）、伏笔/知识 manifest（`knowledge/manifest`）、风格条目与候选（`format/style-*` + `learn/*` 学习提交）。
- **位置**：用户数据目录缓存（RAG/向量，可重建）+ 书目录知识文件（风格条目/伏笔清单，单一事实源）。
- **写入口**：knowledge（learn/learn-commit）、style（entries/candidates/harvest）、search/foreshadows/rhythm/analysis 读；`cache/rebuild` 重建缓存。
- **一致性**：缓存一律可重建（删缓存不丢权威数据——权威数据在书目录文件或事件库）；风格条目确认后才落书目录。
- **禁止**：把可重建缓存当作权威数据备份；RAG 索引直接改 schema（走 `cache/schema` + rebuild）。

### S5 审计子系统（Audit Store）

- **范围**：LLM 调用轨迹与成本（`ai/trace` `ai/trace-stats`）、机检报告（`check/*`）、计数（`check/count` `metrics/*`）、字数日志（`document/words-diary`）、git AI 提交追踪（`git/ai-track`）。
- **位置**：书目录审计文件（报告/计数）+ 用户数据目录（跨书成本）。
- **写入口**：各链路终点（trace 在调用处记录；报告在 `check/run` 生成）；HTTP：trace-stats/check/ai-status/health(style)/heartbeat(活跃)。
- **一致性**：只增不改——成本/轨迹/字数累计不覆盖；报告按轮归档不重写历史。
- **禁止**：审计数据被业务读路径依赖（审计是证据不是输入）；报告回写正文章节。

## 四、归类规则（防漂移）

1. **先归类再落盘**：新增任何持久化数据，先确定归属 S1-S5 之一，再选形态与位置；无法归类的数据视为设计缺陷，先讨论再实现。
2. **单一事实源**：每份数据只允许一个子系统写（S2 事件=append-only 唯一写；S3 provider=store 唯一写；S4 风格条目=书目录唯一写）。
3. **接口归属**：新增 HTTP 端点必须声明数据归属（批次 E2 defineRoute 的 schema 注释里标注 S1-S5），禁止「接口直写文件/直改库」。
4. **分层引用**：上层（AI 链路）只读不写 S1 正文（正文由 process/document 写）；审计只读不写书库。
5. **位置边界**：书目录放「作者可编辑/可版本管理」的数据（正文/风格/清单）；用户数据目录放「运行生成/机器持有」的数据（事件库/缓存/全局设置）。跨边界的（快照）放书目录 `.clwriting/` 并版本化。
