## 一、现状层核查（设计 §5.1/§5.4 三个「实施首步核实」项清偿，file:line 实证）

1. **parseFlat 小数口径（`序: 12.5`）**：`parseValue` 只认纯整数为 number（frontmatter.ts:71 `/^-?\d+$/`），小数落**字符串** `"12.5"`。落点：读侧对 `序` 做强转收编（number / 数字串双认——对齐章号 R62-13 口径）+ 校验 `Number.isFinite && > 0`，非法按缺省（章号）不报错（设计 §5.1 值校验）；写侧 number 经 `stringifyValue`（frontmatter.ts:118）原样 `String(val)` 落 `12.5`，读回字符串再强转——写读闭环成立，**无需动 parseValue**（动它影响全部 fm 值语义，风险外溢）。
2. **`并入` 多值分隔符**：**逗号**。规范写形态 = **数组**（写侧 `stringifyValue` 原生渲染 `并入: [12, 13]`；读侧 parseValue:63 splitInlineArray 读回字符串数组）；读侧三形态兼容归一 `number[]`——number（`并入: 13` 纯整数命中 int 分支）/ 字符串（手写 `并入: 12, 13` 或引号包裹 `"12, 13"`）/ 数组（`[12, "13"]`）。分隔符读侧双认 `,`/`、`（中文作者顿号习惯，对齐 R31-2 全角冒号双认的容错读先例）；写侧恒 `,`。
3. **投稿导出章号来源**：长篇分章 = fm 章号全链（export/index.ts:239 `num: ch.章号` → :312 数值排序 → :429 `String(unit.num).padStart(4,'0')` 分章文件名前缀）；投稿视图 = **短篇专用**（:574 scanShortCollection，长篇不产，D7 不落此面）；全本 merged 内容形 `# {标题}` 无章号呈现。**D7 落点收窄为两处**：分章文件名前缀（displayNum）+ 全链排序键；全本（本地存档/合并稿，D7 明文保留本地章号）= 现状零改动。

## 三、文件级落点明细（关键函数级说明）

1. **readChapter（chapters.ts:28）**：`map.get('序')` → `parseOrderOf`（number 直取；字符串 trim 后 `Number()` 强转；`Number.isFinite && > 0` 否则 undefined——缺省语义，不进错误）；`map.get('并入')` → `parseMergedInto`（number → [n]；字符串按 `,`/`、` 切分逐项 trim 强转正整数、非法项丢弃全空则 undefined；数组逐项 String→Number 同校验）。两键入 KNOWN_FM_KEYS 后不再落 `_raw`。
2. **chapter-lookup.ts（新）**：`mergedIntoMap(bookRoot)` = readChapterDir(正文目录) 一遍 → Map<源章号, 目标章 path>（每章 `并入` 数组逐项登记；折叠链已在写侧单跳化——11 并 12,13 时源 13 直接重指向 11，读侧无需递归）；`chapterTextByNumber(bookRoot, n)` = 既有按名定位（chapterNamePrefixes 三口径）命中优先 → miss 查 Map → 目标章 readFile().body → 再 miss 返 null（调用方既有容错）。消费面五处把「按名定位 miss 即失败/空」改为「先走回退」。
3. **tree.ts sortTreeByOrder**：annotate 后遍历，仅对 `写作/正文` 前缀目录的 children 重排（其余目录维持 localeCompare 现状）；chapter 角色节点 key = probe.order ?? chapterNoOf(name)（probe miss 时回落文件名章号），非数字前缀文件不参与重排保持原相对位（稳定排序 + tie-break 章号 → path）；probe.order 来自 probeFile 新增的 `序` 行 regex 解析（复用已读字节，零额外读）。
4. **leads.ts:134**：判定式 `章号 ≤ currentChapter` 改 `章号 ≤ max(currentChapter, mergedMax)`，mergedMax = mergedIntoMap 在档最大**源**章号；仅此单点，其余检查器零改动。
5. **export/index.ts**：units 组装时带出 `ch.序`（readChapterDir 路径已含）；排序 `sortKey = 序 ?? 章号`；displayNum 分流——`published`（fm 已发布，分章导出侧需经 probe/parseFlat 取——实施时定：readChapterDir meta 已含 `_raw` 可判，或复用 finalizedPathSet+probe；倾向 fm 直判）章 = 本地章号；未发布段（排序后 published 段之后）= 按序位 1..N 连续编（起点 = 已发布段后继续递增？——**拍板口径：未发布段从「已发布最大章号 + 1」起连续编**，与连载投稿语境一致：读者所见下一章编号顺承上一发布章）。分章前缀 padStart(displayNum)；全本与 warnings 文案中的章号引用维持本地章号（作者侧定位用）。
6. **structure-plan 干跑**：对 merge 返回——目标章/源章 meta、正文拼接摘要（源章正文字数/段落 previews）、受影响消费面清单（履历引文命中预演：leads.ts 既有引文正则对并入后正文 grep，失配行先暴露）、RAG 将清除的 chunk 数预估、plan 指纹（参数 + 双方 fm/正文哈希，apply 时复核防 TOCTOU）。
7. **六态回落（合并定稿章）**：executeSave 语义写完目标章 → 哈希与 manifest finalizedRevision 失配 → deriveStatus 回落草稿——**预期行为**：须作者重审重新定稿（重走三检/防吃书闸）；窗口内「只导定稿」不含该章、D7 已发布判定回落，均属预期（验收覆盖）。
