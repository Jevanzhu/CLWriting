# 章节结构操作（合并/拆分/卷重组）-设计方案-2026-08-30

- 版本：v3（D1-D7 已拍板）——`src/document/structure.ts` 头注「设计口径」所指即本件。
- 状态：**已实施完成**；体例：设计文档，不纳入计划、只做展示，任务状态以总览第三节阶段行为准。

## 一、背景与问题

### 1.1 操作语义

- **拆分**：一章拆为两章；**合并**：相邻两章并为一章；**卷重组**：章节跨卷目录移动/卷边界调整。三者统称结构操作——改变章与章的组织关系，而非单章内容。

### 1.2 章号是账本的 join key（级联面核查）

「第几章」不只是文件名数字，而是多条互相咬合的账本的关联键。按章号挂引用的面（亲读核实）：

1. **正文文件自身**：文件名带章号（`写作/正文/<卷>/NNNN-标题.md`），fm 带 章号 字段；机检 `fm-chapter-mismatch`（fm 章号≠文件名前缀）。全书无章号连续性机检（fm-enum 系枚举校验，非连续性检查）。
2. **布线履历行**：`- 悬念-001 埋下：第N章 ……`——章号写在账本文件正文行里；三检「章号一致/引文命中/两端闭合」（check/leads.ts）+ `lead-chapter-future`/`lead-chapter-disorder` 红项。
3. **引文命中按章号回读正文**：章文件定位按文件名前缀数字建「章号→路径」查表（leads.ts，`/^(\d+)-/`，首见优先）；同族按名定位：growth、伏笔 collectChapterTexts、RAG 精准读取（chapterNamePrefixes）、写稿前章正文结尾（prepare.findChapterByNumber）——**全部要求 `数字-标题` 命名形态**。
4. **成长线（境界体系）**：每次跃迁记「章号+章内证据」；`growth-regress`/`growth-span-exceed` 按章号排序判定。
5. **账本推进声明**：`工作区/账本推进.md` 落盘补当前定稿章号。
6. **细纲/章纲**：细纲为 `工作区/细纲.md` 单文件覆盖写（fm 自带章号）；短篇章纲按正文同名。
7. **版本快照**：`.版本/<docId>/`、journal `<docId>.jsonl`——按 **docId**（ULID 稳定身份）键控，与章号无关；单章改号已有 op=meta（docId 不变）。
8. **周边全套**：事件账本（append-only）、RAG（**rag.db chunk 按章号整型键**）、节奏双轨/字数日记/总览卷结构、`state.ts` 下章号推算（= 正文区文件名最大章号+1，与留洞制 max+1 同语义，**零改动**）、树红点章级缓存、导出分章/按卷。

### 1.3 重排制的成本

重排（拆分 +1 / 合并 −1）= 跨上述面的**事务性重写**：N 文件改名+改 fm、M 行履历改号（**append-only 原则违背——唯一不可逆项**）、指标重算、崩溃安全（原子写+journal+fsync+跨进程锁口径）。且连载章号一旦发到平台即对外承诺，作者不可能中途重排。立项级成本，降级为离线工具挂账（D6）。

## 二、现状核查结论

### 2.1 已就绪（零改动/直接复用）

- **移动/重命名/单章改号管线**：`PATCH /documents/:docId` op=move/rename/meta/fm（documents.ts:465-542；伏笔快照系 `设定/伏笔/` 路径作用域机制，章正文不触发）、expectedRevision 乐观并发、PUT 临界段排水；op=meta 改章号即文件规范重命名（docId 不变）。

- **长任务并发闸**：task-gate（15 action 注册表 + KNOWN_ACTIONS 对账机器门 R77-2）+ orchestrationBusyFor 409 家族。
- **保存链**：snapshotBeforeOverwrite、journal+fsync、跨进程保存锁；快照策略 book.yaml `snapshots.max_days/max_count`。
- **导出基建**：merged/split/both、只导定稿、worker 线程。
- **事件账本**：append-only + 审计重放——结构事件**副录**落点。
- **fm 解析对未知键宽容**（`_raw`）；树 probe 已整读 fm（字数/已发布同源）——`序` 提取零新增读取。
- **清单 order 字段已定义**（ManifestEntry.order，自由区语义，章缺省=编号派生）——终态**不用于章排序**（文件本位原则），维持现状。
- **文件名单源**：sanitizeFileNamePart / encodeDocDirName / chapterFilePrefix / sanitizeChapterTitle。

### 2.2 缺口清单

fm 键集封闭（无 `序`/`并入` 键）；按名定位族无「章已并入」回退；导出/树按章号排序（无显示序）；导出章号呈现无「已发布/未发布」分流（D7）；无结构操作端点与 UI；无干跑预览；RAG 合并清理无挂点。**另记**：裸数字文件名（`0001.md`）对按名定位族全失明且机检零提示（青云录实证）——独立挂账 chapter-name-bare 黄项，不进本台账。

## 三、方案总纲：留洞制（文件本位）

### 3.1 核心不变量与文件本位原则

> **章号一经分配，永不改指**（append-only 章号空间）；**显示顺序 = fm `序` 键（缺省 = 章号）**；**被合并的章从正文区消失**（走既有软删回收站），**其去向记录在目标章 fm `并入`**。

> **文件本位原则（作者拍板）：书库的真实存储文件是唯一权威；事件库/缓存/清单只做副录或投影。** fm `并入` 是章号映射的**权威源**；事件账本为审计副录（满足「模型可见 ⟺ 已记录」），不是映射来源。

结构操作由此保持 O(1)：履历章号引用永不失效（回退单源）、docId 永不变、快照/journal 零触碰、正文目录即「活章过滤器」（无逐消费面过滤、无口径漂移风险）。

### 3.2 三操作语义

- **合并（13→12）**：13 的正文并入 12（走既有保存管线，自然留版本）；12 的 fm 写 `并入: 13`（若 12 自身已被并过则链式折叠——如再 12→11 时 11 写 `并入: 12, 13`，解析永远单跳）；13 走既有软删管线消失于正文。
- **拆分（12→12+新章）**：新章号 = 全书 max+1（不插中间占号；state 下章号已是此语义）；新章 fm `序` 取 12 与下一章有效序的中值；12 保留前半，后半入新章；拆分点由作者在编辑器内选定。**平台边界（P3）**：已发布段中段拆分在平台侧本就不可能（连载无插入机制）——拆分仅对未发布段有意义，D7 的已发布/未发布分流已隐含此约束。
- **卷重组**：物理 move 已有；fm 无卷字段（已核实），卷归属纯目录，聚合面核对见验收。

### 3.3 方案对比（墓碑壳的消解：曾案 vs 终态）

| 维度 | 曾案（fm 墓碑壳 + fm order） | 终态（软删 + fm 序/并入） |
|---|---|---|
| 被并章形态 | 壳文件留正文（扫描看得见、消费面须忽略） | 真消失（软删回收站，目录即过滤器） |
| 查表回退 | 命中壳→读 fm 判墓碑→重定向（每处查表都要懂墓碑） | 真 miss→读目标章 fm 并入→目标章（一处单源） |
| RAG | 壳注记被 re-chunk 入库（曾案未察） | 源章号 chunk 清除 + 目标章指纹失效 |
| fm 键 | 英文键 order/mergedInto（与既有中文键风格相悖） | 中文键 `序`/`并入`，封闭键集内加两枚 |
| 检查器 | fm-enum 放宽 + fm-gap-unmarked（对象不存在/多余） | 零改动（无连续性机检可放宽） |
| undo | 去 fm 墓碑 + 内容恢复 | 还原回收站 + 摘 并入 + 目标章版本回滚（一键动作） |

## 五、批 2 详细设计

### 5.1 数据模型（fm 封闭键集扩两枚中文键）

- `序?: number`——显示排序键，缺省 = 章号（旧书零迁移：无字段即现状）；取中值（12 与 13 之间新章取 12.5）。**值校验**：正有限数；非数值按缺省（章号）处理，不报错。
- `并入?: string`——本章吸收的章号清单（`13` / `12, 13` 链式折叠）；机器可解析、人眼可读。
- **结构键保形**：`序`/`并入` 是宿主管的结构键——AI 不得产出，也不得经 fm 重装配丢失。`assembleChapter` 从 tool_use 字段从零重建 fm（ai/contract/chapter.ts:90，不读盘上既有值），拆分新章（必然草稿）+ AI 改稿/自愈重写即主流程触发：`序` 蒸发致显示位跳回章号序、`并入` 蒸发致回退映射静默断。全部 fm 重写路径逐一声明保形口径：**assembleChapter/saveDraft**（组装前读盘上既有 `序`/`并入` 强制透传，或落盘前回补校验）；**updateChapterMeta/updateDocMeta**（合并写不摘既有键）；**编辑器 PUT**（作者手改，接受——但干跑/检查器可见）。
- 已核实：fm 为 flat Markdown+YAML，未知键宽容落 `_raw`；KNOWN_FM_KEYS 扩键后旧版应用读新 fm 仍宽容。实施首步核实：parseFlat 对小数值的解析口径（`序: 12.5`）与 `并入` 多值分隔符定稿。

### 5.2 干跑预览

`POST /documents/:docId/structure-plan`（op=merge/split + 参数）返回：正文变化摘要、受影响章清单、**履历引文命中预演**（合并前即知第 13 章履历证据在并入后正文的 grep 命中率——失配行先暴露，作者先处理或确认降级）。确认后携 plan 指纹执行（防 TOCTOU，与 expectedRevision 同思路）。

### 5.3 执行管线（合并）

task-gate 独占（`'structure'` 注册进 KNOWN_ACTIONS，反向 chat/auto-write/spawn/删书 busyGate 自动互斥；入口互斥清单照 rewrite 端点实序：self-heal / spawn / orchestrationBusyFor / review 在途检查）→ **per-book structure 串行链**（链首 bookMovedFailure 重验 + books.ts 删书/改名排水第 5 drain——重评-0912-4 幽灵目录教训的同型防线）→（伏笔快照不涉：Z-P2-6 系 `设定/伏笔/` 路径作用域机制，章正文合并不触发）→ ① 目标章正文并入（**executeSave 语义专用通道 = `svc.save` origin `'external-merge'`**：journal pending→快照（强制留底，版本即 undo 的 rollbackSnapshotId）→原子写→settled；saveDraft 对定稿目标章被 ensureChapterNotFinalized 拦〔`format/draft.ts:139`〕，不可用；`并入` 经 patchFlatFm 与正文同笔原子写，其余 fm 键行逐字节保形）→ ② 源章软删（`svc.trashDocument` 既有管线：自取源章 save 锁 + 定稿基线 RMW 落账）→ ③ 事件副录 `structure.merge`（载荷携 trashEntryId/rollbackSnapshotId/planHash 供 undo）→ ④ RAG 源章号 chunk 清除 + 目标章指纹失效（best-effort，下轮 buildIndex 自愈兜底）→ ⑤ 缓存失效（tree-issues/书摘要，structural）。

**六态回落语义**：① 写目标章正文 → 哈希与 finalizedRevision 失配 → `final` 回落草稿态——须作者审后**重新定稿**（重走三检/防吃书闸，顺带留 pinned 定稿版本作合并凭据；语义合理：并后内容理应重审）。窗口内「只导定稿」导出不含该章、D7「已发布」判定回落，属预期行为，验收覆盖。

拆分：task-gate → 新章创建（max+1 取号，fm 序=中值）→ 原章截断（保存管线）→ 事件 `structure.split` → 缓存失效。

**撤销合并（一键动作）**：还原回收站 + 目标章摘 `并入` + 目标章版本回滚——编排层动作，不依赖通用还原。通用还原下陈旧 `并入` 惰性无害：回退仅在 miss 触发，文件一回来正文命中优先，陈旧映射永不被咨询。

### 5.4 读取路径适配（改读取不改数据）

- **章号回退 helper 单源**：`chapterTextByNumber(bookRoot, n)`——正文按名定位 miss → 经 readChapterDir（CC-P1-3 stat 级缓存）取各章 ChapterMeta 建 `并入` Map（含折叠链，一次扫描，勿裸 walk 逐文件读）→ 目标章正文。消费面五处接线：leads 引文命中、伏笔 collectChapterTexts、RAG 精准读取（`process/materials.ts` readChapterBodiesByNumbers）、summary（findChapterFile + 定稿章识别）、prepare 前章正文结尾——growth 已退出按名定位族（纯 db 读）。
- **排序键接线**：树——compareNode 在 scanDir 阶段无 fm 数据，排序挪到 annotate 之后按 `序 ?? 文件名章号` 重排；probe 已整读 fm，新增 `序` 解析路径（现仅 `已发布` regex）；同 `序` tie-break = 章号 → path。导出同键（readChapterDir 路径）。
- **导出章号呈现（D7）**：已发布章固定本地章号（fm `已发布` 判），其后未发布段按 `序 ?? 章号` 序位连续编；本地存档/合并稿导出保留本地章号。实施首步核实投稿导出现有章号来源。
- **state 下章号**：已核实 = 文件名最大章号+1，零改动；currentChapter 平时有持久化状态机值（nextChapter 已推进）护住不回落。
- **检查器**：无连续性机检可放宽，但**非零改动**——`lead-chapter-future` 判定基准须**并入感知**：合并最高定稿章后若状态缓存重建（.cache 删损，兜底 = maxFileNameChapter−1，state.ts:847；rebuild 后清单定稿集已无被并章——其条目随软删摘除），currentChapter 回落会使既有履历行「第13章」被判「凭空声称未来章」假红卡定稿。修单点：future 基准 = max(currentChapter, `并入` Map 在档最大章号)。

### 5.5 崩溃恢复

**崩溃不变量（repair 判定式）**：`并入` 所指章**不得存活于正文**——violation 即未完成态（① 后崩溃：并入 指向仍存活的源章 → 幂等续跑 ② 或整体回退）。顺序「先并后删」保证无数据丢失窗口：崩溃在 ① 后——源章仍在正文、内容重复可见、重跑幂等；② 半途态（登记成功/rename 失败孤儿条目）为回收站既有注释明载的无害态。各步用既有原子原语（保存通道 journal、软删登记先于移文件）；事件最后追加即完成声明；**repair 挂点**：书内恢复检查挂 detectState issues → 态 1 报文 → crashedPendingOpIds/acknowledge 既有闭环（照 crashedWrite 样式带 opId），**不挂 startup-notices**（server 生命周期一次性通告通道，非书内恢复通道）；目标章写入的崩溃窗由 executeSave pending/settled + reconcileSavePending 三态闭环自愈（既有闭环，零新代码）。撤销合并顺序（先版本回滚目标章、再还原源章）保证 undo 中途态同样永不违反不变量。崩溃注入回归纳入验收。

### 5.6 事件与审计

新增事件类型 `structure.merge` / `structure.split` / `structure.merge-undo`（append-only 审计副录，携带 plan 指纹与章号映射——merge 载荷另携 trashEntryId/rollbackSnapshotId 供 undo 直取，满足「模型可见 ⟺ 已记录」）；映射权威源 = 目标章 fm `并入`（文件本位原则）。卷重组无新事件类型（降级验收项后零新端点，无产生点）。
