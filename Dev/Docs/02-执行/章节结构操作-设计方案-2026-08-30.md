## 一、背景与问题

### 1.1 操作语义

- **拆分**：一章拆为两章；**合并**：相邻两章并为一章；**卷重组**：章节跨卷目录移动/卷边界调整。三者统称结构操作——改变章与章的组织关系，而非单章内容。

### 1.2 章号是账本的 join key（级联面核查·v2 修正口径）

「第几章」不只是文件名数字，而是多条互相咬合的账本的关联键。按章号挂引用的面（亲读核实）：

1. **正文文件自身**：文件名带章号（`写作/正文/<卷>/NNNN-标题.md`），fm 带 章号 字段；机检 `fm-chapter-mismatch`（fm 章号≠文件名前缀）。**v2 注**：全书无章号连续性机检（v1 所称 fm-enum 实为枚举校验）。
2. **布线履历行**：`- 悬念-001 埋下：第N章 ……`——章号写在账本文件正文行里；三检「章号一致/引文命中/两端闭合」（check/leads.ts）+ `lead-chapter-future`/`lead-chapter-disorder` 红项。
3. **引文命中按章号回读正文**：章文件定位按文件名前缀数字建「章号→路径」查表（leads.ts，`/^(\d+)-/`，首见优先）；同族按名定位：growth、伏笔 collectChapterTexts、RAG 精准读取（chapterNamePrefixes）、写稿前章正文结尾（prepare.findChapterByNumber）——**全部要求 `数字-标题` 命名形态**。
4. **成长线（境界体系）**：每次跃迁记「章号+章内证据」；`growth-regress`/`growth-span-exceed` 按章号排序判定。
5. **账本推进声明**：`工作区/账本推进.md` 落盘补当前定稿章号。
6. **细纲/章纲**：细纲为 `工作区/细纲.md` 单文件覆盖写（fm 自带章号）；短篇章纲按正文同名。
7. **版本快照**：`.版本/<docId>/`、journal `<docId>.jsonl`——按 **docId**（ULID 稳定身份）键控，与章号无关（v1 勘误①）；单章改号已有 op=meta（docId 不变）。
8. **周边全套**：事件账本（append-only）、RAG（**rag.db chunk 按章号整型键**，v1 勘误⑤）、节奏双轨/字数日记/总览卷结构、`state.ts` 下章号推算（= 正文区文件名最大章号+1，与留洞制 max+1 同语义，**零改动**）、树红点章级缓存、导出分章/按卷。

### 1.3 重排制的成本（v2 修正论证）

重排（拆分 +1 / 合并 −1）= 跨上述面的**事务性重写**：N 文件改名+改 fm、M 行履历改号（**append-only 原则违背——唯一不可逆项**）、指标重算、崩溃安全（原子写+journal+fsync+跨进程锁口径）。且连载章号一旦发到平台即对外承诺，作者不可能中途重排。立项级成本，降级为离线工具挂账（D6）。

## 三、方案总纲：留洞制（v2 终态：文件本位）

### 3.1 核心不变量与文件本位原则

> **章号一经分配，永不改指**（append-only 章号空间）；**显示顺序 = fm `序` 键（缺省 = 章号）**；**被合并的章从正文区消失**（走既有软删回收站），**其去向记录在目标章 fm `并入`**。

> **文件本位原则（作者拍板，2026-09-04）：书库的真实存储文件是唯一权威；事件库/缓存/清单只做副录或投影。** fm `并入` 是章号映射的**权威源**；事件账本为审计副录（满足「模型可见 ⟺ 已记录」），不是映射来源。

结构操作由此保持 O(1)：履历章号引用永不失效（回退单源）、docId 永不变、快照/journal 零触碰、正文目录即「活章过滤器」（无逐消费面过滤、无口径漂移风险）。

### 3.2 三操作语义

- **合并（13→12）**：13 的正文并入 12（走既有保存管线，自然留版本）；12 的 fm 写 `并入: 13`（若 12 自身已被并过则链式折叠——如再 12→11 时 11 写 `并入: 12, 13`，解析永远单跳）；13 走既有软删管线消失于正文。
- **拆分（12→12+新章）**：新章号 = 全书 max+1（不插中间占号；state 下章号已是此语义）；新章 fm `序` 取 12 与下一章有效序的中值；12 保留前半，后半入新章；拆分点由作者在编辑器内选定。**平台边界（P3）**：已发布段中段拆分在平台侧本就不可能（连载无插入机制）——拆分仅对未发布段有意义，D7 的已发布/未发布分流已隐含此约束。
- **卷重组**：物理 move 已有；fm 无卷字段（已核实），卷归属纯目录，聚合面核对见验收。

### 3.3 v1↔v2 对比（墓碑壳的消解）

| 维度 | v1（fm 墓碑壳 + fm order） | v2 终态（软删 + fm 序/并入） |
|---|---|---|
| 被并章形态 | 壳文件留正文（扫描看得见、消费面须忽略） | 真消失（软删回收站，目录即过滤器） |
| 查表回退 | 命中壳→读 fm 判墓碑→重定向（每处查表都要懂墓碑） | 真 miss→读目标章 fm 并入→目标章（一处单源） |
| RAG | 壳注记被 re-chunk 入库（v1 未察） | 源章号 chunk 清除 + 目标章指纹失效 |
| fm 键 | 英文键 order/mergedInto（与既有中文键风格相悖） | 中文键 `序`/`并入`，封闭键集内加两枚 |
| 检查器 | fm-enum 放宽 + fm-gap-unmarked（对象不存在/多余） | 零改动（无连续性机检可放宽） |
| undo | 去 fm 墓碑 + 内容恢复 | 还原回收站 + 摘 并入 + 目标章版本回滚（一键动作） |

## 五、批 2 详细设计

### 5.1 数据模型（fm 封闭键集扩两枚中文键）

- `序?: number`——显示排序键，缺省 = 章号（旧书零迁移：无字段即现状）；取中值（12 与 13 之间新章取 12.5）。**值校验（P3）**：正有限数；非数值按缺省（章号）处理，不报错。
- `并入?: string`——本章吸收的章号清单（`13` / `12, 13` 链式折叠）；机器可解析、人眼可读。
- **结构键保形（二轮评审 P1）**：`序`/`并入` 是宿主管的结构键——AI 不得产出，也不得经 fm 重装配丢失。`assembleChapter` 从 tool_use 字段从零重建 fm（ai/contract/chapter.ts:90，不读盘上既有值），拆分新章（必然草稿）+ AI 改稿/自愈重写即主流程触发：`序` 蒸发致显示位跳回章号序、`并入` 蒸发致回退映射静默断。全部 fm 重写路径逐一声明保形口径：**assembleChapter/saveDraft**（组装前读盘上既有 `序`/`并入` 强制透传，或落盘前回补校验）；**updateChapterMeta/updateDocMeta**（合并写不摘既有键）；**编辑器 PUT**（作者手改，接受——但干跑/检查器可见）。
- 已核实：fm 为 flat Markdown+YAML，未知键宽容落 `_raw`；KNOWN_FM_KEYS 扩键后旧版应用读新 fm 仍宽容。实施首步核实：parseFlat 对小数值的解析口径（`序: 12.5`）与 `并入` 多值分隔符定稿。

### 5.2 干跑预览（保留 v1 设计）

`POST /documents/:docId/structure-plan`（op=merge/split + 参数）返回：正文变化摘要、受影响章清单、**履历引文命中预演**（合并前即知第 13 章履历证据在并入后正文的 grep 命中率——失配行先暴露，作者先处理或确认降级）。确认后携 plan 指纹执行（防 TOCTOU，与 expectedRevision 同思路）。

### 5.3 执行管线（合并）

task-gate 独占（结构操作期间禁自动写章/编排/三审，双向互斥）→ 伏笔快照先行（Z-P2-6 既有）→ ① 目标章正文并入（**executeSave 语义专用通道**：journal pending→快照→原子写→settled——saveDraft 对定稿目标章被 ensureChapterNotFinalized 拦〔draft.ts:139〕，不可用；`并入` 与正文同笔原子写）→ ② 源章软删（回收站登记→移文件，既有管线）→ ③ 事件副录 `structure.merge` → ④ RAG 源章号 chunk 清除 + 目标章指纹失效 → ⑤ 缓存失效（tree-issues/书摘要，structural）。

**六态回落语义（二轮评审 P2）**：① 写目标章正文 → 哈希与 finalizedRevision 失配 → `final` 回落草稿态——须作者审后**重新定稿**（重走三检/防吃书闸，顺带留 pinned 定稿版本作合并凭据；语义合理：并后内容理应重审）。窗口内「只导定稿」导出不含该章、D7「已发布」判定回落，属预期行为，验收覆盖。

拆分：task-gate → 新章创建（max+1 取号，fm 序=中值）→ 原章截断（保存管线）→ 事件 `structure.split` → 缓存失效。

**撤销合并（一键动作）**：还原回收站 + 目标章摘 `并入` + 目标章版本回滚——编排层动作，不依赖通用还原。通用还原下陈旧 `并入` 惰性无害：回退仅在 miss 触发，文件一回来正文命中优先，陈旧映射永不被咨询。

### 5.4 读取路径适配（改读取不改数据）

- **章号回退 helper 单源**：`chapterTextByNumber(bookRoot, n)`——正文按名定位 miss → 经 readChapterDir（CC-P1-3 stat 级缓存）取各章 ChapterMeta 建 `并入` Map（含折叠链，一次扫描，勿裸 walk 逐文件读）→ 目标章正文。消费面五处接线：leads 引文命中、growth、伏笔 collectChapterTexts、RAG 精准读取、prepare 前章正文结尾。
- **排序键接线**：树——compareNode 在 scanDir 阶段无 fm 数据，排序挪到 annotate 之后按 `序 ?? 文件名章号` 重排；probe 已整读 fm，新增 `序` 解析路径（现仅 `已发布` regex）；同 `序` tie-break = 章号 → path。导出同键（readChapterDir 路径）。
- **导出章号呈现（D7）**：已发布章固定本地章号（fm `已发布` 判），其后未发布段按 `序 ?? 章号` 序位连续编；本地存档/合并稿导出保留本地章号。实施首步核实投稿导出现有章号来源。
- **state 下章号**：已核实 = 文件名最大章号+1，零改动；currentChapter 平时有持久化状态机值（nextChapter 已推进）护住不回落。
- **检查器**：无连续性机检可放宽（v1 误读），但**非零改动**——`lead-chapter-future` 判定基准须**并入感知**（二轮评审 P2）：合并最高定稿章后若状态缓存重建（.cache 删损，兜底 = maxFileNameChapter−1，state.ts:847；rebuild 后清单定稿集已无被并章——其条目随软删摘除），currentChapter 回落会使既有履历行「第13章」被判「凭空声称未来章」假红卡定稿。修单点：future 基准 = max(currentChapter, `并入` Map 在档最大章号)。

### 5.5 崩溃恢复

**崩溃不变量（repair 判定式，二轮评审 P3）**：`并入` 所指章**不得存活于正文**——violation 即未完成态（① 后崩溃：并入 指向仍存活的源章 → 幂等续跑 ② 或整体回退）。顺序「先并后删」保证无数据丢失窗口：崩溃在 ① 后——源章仍在正文、内容重复可见、重跑幂等；② 半途态（登记成功/rename 失败孤儿条目）为回收站既有注释明载的无害态。各步用既有原子原语（保存通道 journal、软删登记先于移文件）；事件最后追加即完成声明；启动 repair = 按上述不变量比对盘面（正文/回收站/fm 并入）与事件，可挂 startup-notices。崩溃注入回归纳入验收。

### 5.6 事件与审计

新增事件类型 `structure.merge` / `structure.split` / `structure.volume-move`（append-only 审计副录，携带 plan 指纹与章号映射，满足「模型可见 ⟺ 已记录」）；映射权威源 = 目标章 fm `并入`（文件本位原则）。

## 八、风险与备记

- **序中值精度**：双精度对半连插 50+ 次才耗尽，200 万字书不现实；兜底 =「序重整」维护动作（按当前序重写等距值——fm 载体下重整触 N 份 fm，频次极低可接受）。
- **陈旧并入**：通用还原后目标 fm 残留 `并入`——惰性无害（回退仅 miss 触发，正文命中优先）；撤销合并一键动作收口。
- **账本推进声明与并入交互**：声明落盘补定稿章号，若该章后被合并，履历按原章号在档——回退同引文命中，无须改写数据。
- **短篇集**：fm `序` 同机制承载篇目重排（红利注记：清单 order 方案作废后短篇集与长篇共用一套键；重排 UI 入口仍不含）。
- **win 面**：文件名/目录名走 sanitizeFileNamePart 与 encodeDocDirName 既有链路，结构操作不新增字符面。
- **实施首步核实**：已核（fm 无卷字段 / 细纲单文件 / 未知键宽容）；待核（parseFlat 小数口径、`并入` 分隔符、投稿导出章号来源）。
- **挂账（不进本台账）**：chapter-name-bare 机检黄项——裸数字文件名（`^\d+\.md$`）对按名定位族静默失明且机检零提示（青云录实证 2026-09-04），独立小项。
