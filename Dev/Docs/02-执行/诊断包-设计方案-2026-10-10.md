# 诊断包 —— 设计方案（已拍板 · 已实施）

- 定位：1.0 前增补项之一（原登记于总览第三节「余下候选」）。正本 = 本文件；
  实现锚 = `src/diagnostics/zip.ts`（ZIP 写入器）、`src/diagnostics/index.ts`（收集器）、
  `src/studio/server/api/diagnostics.ts`（端点）、`SettingsDiagnostics.vue`（入口）。
- 背景：作者报障时只能给一段文字描述，版本/运行环境/日志都得来回问。诊断包把「排查一个
  bug 需要的最小信息集」一次打成单文件，且**默认就不含敏感内容**——不给作者「为了报障先交
  出书稿」的两难。

## 一、口径（拍板）

| 项 | 定为 |
|---|---|
| 内容 | **基础集**：环境（应用版本/平台/架构/运行环境版本/生成时间）+ 配置白名单 + 近 7 天日志 + 说明.txt |
| 配置白名单 | 显式列名取键：全局编辑器偏好 27 键、供应商「协议 + 模型名 + 是否配了 key」、当前模型、任务档位、RAG 服务商同款、书库书数 |
| 日志 | 近 7 天 `app-YYYYMMDD.jsonl`（保留期判据与日志轮转同源 `recentLogFiles`），逐行经既有 `redactSecret` |
| 形态 | 单个 ZIP（**手写 store 模式写入器**，零新依赖） |
| 落点 | `<userData>/诊断包/诊断包-<本地时间戳>.zip` |
| 入口 | 设置 → 系统 →「诊断」页：生成 + 落点显示 +「打开所在文件夹」（桌面版） |

**落点为何不放 `工作区/导出/`**：诊断包是**应用级**排查件（与某本书无关）；放书库会被云同步
带走、在 `导出/` 里与导出稿混面，且书库可移植性被污染。userData 是本应用的私有数据目录，
配合「打开所在文件夹」入口，作者找得到；旧包不清理（同「归档不删」哲学，作者自清）。

## 二、隐私红线（写死在内核，用例锚定）

- **书稿正文永不入包**：收集器不读 `写作/` 下任何文件，只读应用级数据目录；
- **密钥永不入包**：供应商只取 `protocol` / 模型名 / `keyConfigured` 布尔——`apiKey`
  （含密文）与 `baseUrl` 一概不读入内存；日志逐行 `redactSecret`（URL 凭据 / Bearer /
  各厂商 key 形态）；
- **路径脱敏**：应用数据目录 / 用户目录 / 书库根替换为 `<应用数据>` / `<用户目录>` /
  `<书库根>`；另加家目录形态正则兜底（`C:\Users\x`、`/Users|x/home`）。脱敏在**解析后的
  字符串值**上做（JSONL 行先 parse 再遍历替换再序列化）——直接对原文做子串替换会因 JSON
  转义形态差异（`C:\\Users\\x`）而漏网。
- 登记（有意保留）：日志里的**网关主机名**随 SDK 报错原文入包——「走既有脱敏」口径只掩凭据
  不掩主机，而主机名是排查连通性问题的关键信息；供应商别名（用户自述文本）不入包。

## 三、实现面

- **ZIP 写入器**（`src/diagnostics/zip.ts`）：store 模式最小子集（本地文件头 + 数据 /
  中央目录项 / 中央目录结束记录）。中文条目名置 UTF-8 标志位（bit 11 = 0x0800）——否则
  解压端按 CP437 解码条目名，包对作者/开发者直接不可读。`zlib.crc32` 取 CRC（Node ≥24，
  与引擎下限一致）。超限 fail-loud（>4GiB / >65535 条目 → 抛，需 zip64 即不产坏包）。
  外部属性给 `0o100644`（0 会让部分解压端按 000 处理）。
- **收集器**（`src/diagnostics/index.ts`）：同步 IO（MB 级、设置页显式动作、非热路径）；
  条数顺序 = 说明.txt → 环境.json → 配置.json → 日志/*.jsonl；`atomicWriteFile` 落盘。
  白名单字符串值限长 60 且不含路径分隔符（防某个键藏了长路径混进包）。
- **端点**（`src/studio/server/api/diagnostics.ts`）：`POST /api/diagnostics`（写 token 闸覆盖
  POST；APP 级路径，不在 `/api/books/:name` 下）；版本走 `resolveAppVersion()` 版本单源；
  失败 422 `DIAGNOSTICS_FAILED` 信封（不穿 500 兜底）。
- **桌面能力**：新增 IPC `desktop:reveal-diagnostics`——目录由主进程自行推导
  （`diagnosticsDirOf(app.getPath('userData'))`），**不接受渲染层传路径**（与
  show-in-folder / open-book-dir / open-library-dir 三入口同口径）；未生成过包时静默返回。
- **前端**：`api/diagnostics.ts` + `SettingsDiagnostics.vue`（新 tab「诊断」，归「系统」组）——
  浏览器版无桌面通道则隐藏「打开所在文件夹」。

## 四、验收

- 写入器（`test/diagnostics/zip-store.test.ts`，6 条）：多条目（含中文名/目录名）经**独立
  读取器**（`test/helpers/zip-read.ts`，自带表驱动 CRC，不用被测模块的 crc32 自证）完整解析；
  CRC 与 `zlib.crc32` 同值且等于 "abc" 标准值 `0x352441C2`；UTF-8 标志位/store 模式逐条目
  就位；空归档合法；超 65535 条目抛错；mtime 注入 → DOS 时间/日期字段自洽。
- 收集器（`test/diagnostics/bundle.test.ts`，9 条）：落点与命名（时间戳本地时）；条目清单；
  环境字段齐备；配置白名单（白名单内进/外不进、书数只记数量）；10 天前日志不入包；
  三类隐私红线（密钥整包不得出现 / 书稿正文标记不得出现 / 原文路径不得出现且占位符出现）；
  非 JSON 半行按文本脱敏保留；无 userDataPath 失败面。
- 端点（`test/studio/server/diagnostics-endpoint.test.ts`，2 条）：200 域形状 + 盘上确有包；
  另起无 userDataPath 实例 → 422 信封。
- 前端（`test/studio/webnext/dom/settings-diagnostics.test.ts`，4 条）：成功 toast + 落点显示；
  告警 toast；失败 toast 且无落点；桌面通道缺失隐藏按钮 / 存在则点击转 IPC。
- **真解压验收**（本机实录）：生成的包交 Windows `Expand-Archive` 解压 → 四个条目名中文
  正常显示，`配置.json` 白名单形状正确、`日志/app-*.jsonl` 中 key 落 `***REDACTED***`，
  全树 grep 密钥与原始临时路径零命中。

## 五、边界登记

- 未实现（诊断包规模用不到）：zip64、压缩方法 8、加密、数据描述符、归档注释。
- 日志窗口取「距今 7×24h」（与轮转清理同判据），非「7 个自然日」——口径同源优先一致。
- 不做自动上报/联网发送：包只落本地，是否分享由作者决定（不引入出网面）。
