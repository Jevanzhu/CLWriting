## 一、背景与目标

- 目标：启动时静默检查一次新版本；有更新的**正式版**才提示并指路下载。**不自动下载、不自动安装**——与「不做代码签名、更新走手动下载」的对外承诺一致（根 README「下载与安装」现句需随批改写，见 3.5）。
- 现状缺口（实核）：① 运行时无版本号通路（全库无 `app.getVersion` / `APP_VERSION`）；② 应用无打开系统浏览器能力（窗口外链封死，全仓无 `openExternal`）；③ 发布链 rc 不带 prerelease 标记 → GitHub `/releases/latest` 会返回 rc，不能直接当「最新正式版」。

## 二、现状核查（实核）

1. **版本通路可建**：主进程 `app.getVersion()`（打包态读 asar 内 package.json）；env 注入纪律已立——`src/desktop/server-manager.ts:316-349`（`CLW_STUDIO_TOKEN` / `CLW_LOG_STDOUT` / `CLW_OS_KEK` 注入前逐键大小写不敏感清洗宿主残留）；读侧先例 `src/desktop/server-boot.ts`（token 经 env 读取）。
2. **发布链实况**：tag 触发 `v*`；`gh release create --draft --verify-tag` 后 `--draft=false` 转正、无 `--prerelease`（`.github/workflows/desktop.yml`）→ rc 亦是正式 release；当前在架 = v1.0.0-rc.0。
3. **外链封闭**：`src/desktop/windows.ts:326-327`（will-navigate preventDefault + `setWindowOpenHandler` deny）；唯一门 = preload 桥（`src/desktop/preload.ts` → `window.clwritingDesktop`，类型正本 `src/studio/web-next/src/desktop.d.ts`）+ `src/desktop/ipc.ts` 的 `handleTrusted` 通道清单。

## 三、口径六面（已定）

### 3.1 版本源

主进程 `app.getVersion()` → env `CLW_APP_VERSION` 注入子进程（清洗面加键，照既有纪律）→ server 启动记下 → 新增只读端点 `GET /api/app-info`（返回 `{ version, update: { version, url } | null }`）→ 前端横幅取用；设置页可顺带显示当前版本（纯展示）。node 直跑形态（dev:api / e2e）回落读 package.json（try/catch 容错）。

### 3.2 比对与提示规则

- 数据源：`GET https://api.github.com/repos/Jevanzhu/CLWriting/releases?per_page=20`（公开仓、匿名，60/h/IP；每次启动至多 1 请求）。
- 候选 = tag 去掉前导 `v` 后形如 `X.Y.Z`（不含 `-`、非 draft）的最大 semver；仅当候选 > 当前版本才提示；比较按 semver，`1.0.0-rc.0 < 1.0.0`。故 rc 用户会收到首个正式版提示（正向），rc→rc 不打扰。
- 自研比较器（十行级，零新依赖）。

### 3.3 频率与静默

启动后延迟数秒 fire-and-forget，进程内一次、不落盘；5s 超时；失败/离线/被墙/限速一律静默（可选一行 info）；代理环境直连失败即静默（不学 RAG 的 warn——那边 warn 是给「配了代理为何召回为空」定位，更新检查失败无任何用户可见损害）；测试态 env 开关关闭，保证 e2e 不打网。

### 3.4 UI 落点与外链

- App 级可关横幅（复用 `StartupNoticeBanner` 的形态与位置）；dismiss 按版本号记忆——同版本关掉不再弹，出新版再弹。文案「有新版本 vX.Y.Z（当前 vA.B.C）· 去下载」。
- 新增 `desktop:open-external`（走 `handleTrusted` + URL 白名单前缀 `https://github.com/Jevanzhu/CLWriting/releases`——不信 API 返回的任意 URL）；`preload.ts` 与 `desktop.d.ts` 同步；浏览器版无桥则按钮降级「复制链接」。

### 3.5 披露与开关

根 README「下载与安装」现句（「也没有自动更新，有新版本手动下载」）改写为：不自动下载/安装，但启动时会静默检查一次新版本（仅访问 GitHub 公共接口、不发送任何本机信息），有新版本会提示、仍走手动下载。**不做设置开关**。机器门随批跑 `check:docs` / `check:counts`。

### 3.6 发布链零改动

不给 rc 加 `--prerelease`（动发布链的风险大于收益，列后续可选）。

## 七、风险与备记

- **GitHub 可达性**（国内网络）：静默失败是设计而非缺陷；不重试、不弹错。
- **匿名限速**：每次启动 1 请求，余量充足；被限速即静默。
- **端点安全**：只读、走现有 token 闸；不落任何 token 或凭据。
- **外链面**：白名单前缀校验（防 API 返回被篡改的 URL）；该 IPC 后续可复用（CHANGELOG / 文档链接）。
- **版本比较边界**：非 semver tag（`v1.0`、`nightly` 等）忽略；比较器对垃圾输入不抛（返 null）。
- **后加项（不在本批）**：会话内 24h 重查定时器；诊断包（另批次，口径未定）。
