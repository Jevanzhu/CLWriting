# 知识层实施（装配 + 语料重建）实施计划

- 定位：执行正本——顺序、任务分解、验收门、执行记录（末节回填）。**设计理由不在本档**，正本 = `03-设计/知识层装配-设计方案-2026-10-13.md` + `03-设计/知识层语料重建-设计方案-2026-10-13.md`。
- 关系：装配档 = 机制面（catalog/装配/开关/报告/作业包接线）；语料档 = 内容面（篇目/取材/署名/退役）。本档只回答「谁先谁后、每步动什么、怎么算过关」。
- 全局序：**A → D1 → {B, C, D2, D3, D4}**；独立批 = 三审补 lens（信息披露/情节与因果）。

## 一、起点

**从《知识层装配》§四批 A 开始。** 三条理由：

1. 批 A 是**纯重构、零行为变**——现有测试的断言期望值一字不改仍全绿即过关，是全局序里唯一能独立验证的批。
2. 批 D1 的 catalog 条目值依赖批 A 落的机制（`CatalogEntry` 形制、`faces`/`purpose` 词表、门校验语义）——A 不落，D1 无处填条目。
3. B（作业包 `references`）依赖 D1（须指新 rel）；D1 依赖 A。**A 是唯一无前置的批。**

**可并行面**：D1 的**语料正文写作**（通用 9 篇）不依赖任何代码——可与批 A 并行推进（写作只对照 v8 结构底稿与 oh-story MIT 源，见语料档 §一.1 隔离纪律）；D1 的**接线**（catalog 条目/manifest/门）必须在 A 之后。

## 二、批 A：装配收敛（6 步）

**零行为变的验收口径**：三面注入的**可观察输出**（段文本、登记名、超帽处置、开关效果）逐字不变。测试文件允许的改动仅两类：**import 换源**（常量搬家后）与**同族断言合并**（帽/截断收进 inject 面表）；**不允许改任何断言期望值**。

## 三、批 D1：骨架 + 通用 9 篇（增量，不删旧件）

**批界修正**（相对语料档 §六/§七，两档同步）：D1 **只做增量与机制，不删旧件、不动旧 rel**。原因——旧 6 篇中钩子/反转/节奏三篇是写稿面基础篇（长/短），其后继在 D2；若 D1 即退役，D1 与 D2 之间写稿面选材会落空。故：

- **退役机制**（代码 + 测试）D1 落，但 `versions.json` **退役段置空** → 实际不删任何件；
- **退役数据**（旧 6 rel 入退役段 + catalog 去旧条目）**随 D2 收口落**——那时全部后继篇已就位。

### D1a 退役机制 `seed.ts`

- 靶点：`seedBookKnowledge` 增退役步——扫书级 `知识层/`（复用 `listBookKnowledgeEntries`），对「不在 `listBundledSeedRels()`」且「书级哈希命中 `versions.json` 退役段」的件 → 删除 + `report.retired`（`SeedReport` 增字段）；哈希不命中 → `report.kept`（作者改过，永不删）。
- 验收：`test/knowledge/seed.test.ts` 增例——未改动旧件删除 / 作者改过保留 / 书级自发新件（不在退役表）不误删 / 退役表空时不删任何件。

### D1b 骨架重建

- 靶点：`知识层/{通用,长篇,短篇,去味,题材,许可}/`（空目录 `.gitkeep` 保形）+ 各类 README（`purpose: 'index'`、`faces: []`）。
- `_manifest.json` 按新条目重建（sha256/target/source/source_ref/license）。
- `check-knowledge.ts`：选材篇目断言改 **catalog 驱动**（`BUNDLED_CATALOG` 中 `faces` 非空 ⇒ 随包在位）+ **署名门**（每篇 source/license frontmatter；MIT 来源篇在 `许可/` 有版权行）。
- 验收：`npm run check:knowledge` 绿；门用例——缺署名红、`faces` 非空但随包缺件红。

### D1c 通用 9 篇（写作，可并行于 A）

- 验收：每篇过帽 + 四段结构在位 + 跨档口径词扫描（长篇篇无短篇默认值，反之同）。
