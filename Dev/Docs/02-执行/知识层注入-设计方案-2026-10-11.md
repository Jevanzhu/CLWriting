# 知识层注入（写稿/三审面）—— 设计方案（已拍板 · 已实施）

- 定位：把 `知识层/` 方法论语料接进真模型链路——**写稿首稿按章选材注入** + **三审视角清单固化**。
  拍板 = 作者「把这套知识库方法论和现在的流程结合进去，使用起来」。正本 = 本文件；
  实现锚 = `src/knowledge/select.ts`（选材器）、`src/process/draft-pipeline.ts`（注入段）、
  `resources/knowledge/`（随包语料）、`resources/prompts/review-*.md`（三审固化）。
- 背景：语料建好后只有「对话注入」一条细管（且要书根自带，无人播种），写稿/三审面从未读取——
  判断类技法（钩子清单/反转机制/节奏三步/人物对话/质检关注点）在链路上缺位。本批把其中
  **判断类**内容按两条落点接上，形态取「随包」，对每本书默认生效。

## 一、口径（拍板）

| 项 | 定为 |
|---|---|
| 形态 | **随包资源**（`resources/knowledge/` + 三审 prompt 固化）——不走「书级知识层运行时读取」 |
| 写稿落点 | 首稿 prompt 增段 `## 写作方法参考(按本章自动选取,冲突时以本书设定为准)`，置于「要求」段前 |
| 选材 | 基础篇 1（长篇＝章节钩子速查 / 短篇＝反转设计速查）+ 信号追加至多 1（节奏与升级感速查／人物与对话技法速查，按固定优先级取首个命中）；信号 = 本章细纲 + 章纲原文 |
| 双帽 | 合计 ≤2 篇、单篇 ≤2000 码点（超长保头截断标注）、合计 ≤3000 码点（超帽整篇跳过） |
| 溯源 | 注入源登记名带 `知识层(内置)/` 前缀（bundled 资源不在书根下）→ `promptMeta.files`，满足「模型可见⟺已记录」 |
| 三审落点 | 六视角 + 通用 fallback 各带通用「章级判断」条（水章/信息跟冲突/情绪落地/结尾变化）+ 按视角对口技法（hook←章尾八式；emotion_peak←反转机制；payoff←打脸节奏；reader←升级感三步；editor←对话与人物；continuity←连载连续性与关系网） |
| 语料一致性 | `resources/knowledge/` 每件与 `知识层/<rel>` **逐字节相等**（`check:knowledge` 对账）+ 选材四篇在位 |
| 未动 | 对话面仍读书根 `知识层/`（书级可选增强，缺省零注入）——两口径并存，未统一 |

## 二、为什么取随包形态（不取「书级运行时读取」）

- 写稿/三审的上下文纪律是「版本化捆绑 prompt（versions.json 哈希门）+ 机检代码 + 本书设定注入」；
  让运行时读书级自由文档会把输出可复现性绑到每本书的手工文件上，并绕过 prompt 版本门；
- 随包形态顺带解决分发：prompt 与资源本就随安装包，对每本书默认生效，不存在「谁没拷知识层」；
- 语料源仍单源在 `知识层/`（manifest + sha256 + 许可对账），随包件只是**逐字节同步的子集**——
  漂移即红，杜绝「包里语料与仓里原稿不是一回事」。

## 三、实现面

- `resources/knowledge/`：随包子集 4 篇（追读力/章节钩子速查、追读力/节奏与升级感速查、
  爽点/反转设计速查、方法论/人物与对话技法速查）+ `许可/oh-story-claudecode-MIT.md` + `README.md`（说明，豁免对账）。

- `src/process/draft-pipeline.ts`：注入段 + `files` 登记（两处 `parts.push`、一处 `pushFile`）。
- `resources/prompts/review-{common,reader,editor,continuity,hook,emotion_peak,payoff}.md`：清单固化；
  `versions.json` 逐文件追加新哈希（历史保留）；`test/ai/__fixtures__/prompts-golden.json` 同步。
- `scripts/check-knowledge.ts`：`scanBundledCorpusMismatches`（逐字节对账 + 选材篇目在位），main 接入 + 退出码 1。

- 度量面（本批不改代码，供后续实验）：`rule-hits` 台账（按书/任务记机检命中，self-heal 单列）+
  trace-stats 接口/界面 + 自愈重写轮次 + 三审 issue 数——基线窗口 vs 注入窗口对比即可判收益。

## 五、边界登记

1. **无开关**：写稿面方法参考恒开（同「文风样章」形态）；若需按书关停，后续在 `book.yaml` 加段（未做）。
2. **未随包两篇**：题材路由速查（建书/大纲面未接线）、质量检查清单速查（已以三审 prompt 固化形态消费，
   无运行时读取方）——留在 `知识层/` 供人读，避免「先搬后用不上」。
3. **悬空引用未清**：题材路由/节奏速查篇内「详细公式见 genre-writing-formulas.md」指向未随层素材；
   写稿面注入含该句——内容修订批处理（补件或改写引用）。
4. **chat 面两口径并存**：书根 `知识层/` 注入（方法论类，≤4 篇/2000/6000）与写稿面随包注入互不干扰；
   统一（书级覆盖随包）留待后续。
5. **deferred:1 无头账**：manifest 汇总字段自报一条未迁移，无对应条目——内容批顺手清。
6. **语料同步是人工动作**：改 `知识层/` 原稿后须手动同步 `resources/knowledge/` 同名件，门只负责报红。
