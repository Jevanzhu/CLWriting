## 一、背景与问题

### 1.1 现象

桌面版 studio server 跑在 utilityProcess 子进程里（`src/desktop/server-manager.ts`），事件循环单条——网络盘（SMB/网盘）书库上，机检链里任何「全树遍历级同步块」都把这条循环钉死：全部 API 请求与 SSE 心跳停摆、保存排队，用户视角即整个 app 卡死（主进程 UI 线程本身不受阻）。本地 SSD 上这些块毫秒级无感；慢盘上单遍全树 `readdir`+`stat` 即秒级（`src/cache/rebuild.ts` R47-11 节流块注已实证口径）。

### 1.2 两条目标（RC 重审 P3 登记）

- **P3-12 树红点聚合前奏段**：`/tree-issues` 请求进门先串行走完 rebuild 与多遍全树遍历，然后才是早已切片的章循环（每 25 章让出）。锚 = `src/check/run-tree-issues.ts:64` 注释自认（「rebuild/预扫段（readChapterDir×2 + 账本预扫）仍是单段同步块……其内核不在本批允许清单」）。
- **P3-13 单章机检 leads 冷读段**：`checkLeadsBookItems` 冷缓存时全树建章号表并逐章整读正文做引文核验，在请求 handler 内同步执行（稳态有 stat 指纹缓存，冷窗口即卡）。锚 = `src/check/leads.ts:118` 一带。

### 2.4 单章链的通路

- 生产唯一调用点：`runAllChecks` = `run.ts:420`；`checkLeadsForm` = `runner.ts:141`。

- 节流分账：树聚合 rebuild 不节流、单章链 opt-in 3s TTL（`run.ts:181` 与 R47-11 节流块注口径）。

## 三、方案总纲

两条规则：

1. **切片的实现体收进生成器核心，同步/异步双驱动共享单源**——切片点 = 纯悬停点（无值 `yield`），现有双驱动零改动承接（同步驱动 `next()` 到底；async 驱动每悬停 `await yieldToEventLoop()`）。
2. **跨线程的重活交给既有 worker 层，主线程只 await**——rebuild 段走 `runRebuildAsync`。

**唯一新增驱动机制 = rebuild 段的「效应让出」**：核心产出标签（如 `'rebuild'`）而非裸悬停，同步驱动同步执行 `openCheckDb`/`rebuild` 并 `next(结果)` 回填（与现行为逐位一致），async 驱动 `await openCheckDbAsync`（内部 `runRebuildAsync`）后回填。

同步路径行为逐位不变（存量回归全走同步口径）；async 路径是唯一行为变化面（HTTP 路径本就如此）。

## 五、详细设计

### 5.1 刀 1：切片点清单

| 切片点 | 实现位 | 手段 |
|---|---|---|
| fp 首/尾（目录递归 stat） | `tree-issues-cache.ts`：`dirFp` / `computeTreeIssuesGlobalFp` | 生成器核心（每 N 目录项让出）+ 同步包装，既有调用方零改动 |
| 正文目录整扫 | `format/chapters.ts`：`scanChapterDir` | 生成器核心（每 N 文件让出）+ 同步包装 |
| 账本预扫（归档循环） | `run.ts`：`scanChapterUpdatesByChapter` | 生成器核心（建表循环每 N 文件让出）+ 同步包装 |
| 账本全书性红项 | `leads.ts`：`checkLeadsBookItems` | 生成器核心 + 双驱动；树核 `yield*` 委托（`:256` 区改） |
| rebuild | `run.ts`：`openCheckDb` | 新增 `openCheckDbAsync`（`runRebuildAsync`）+ 效应让出；同步版保留 |

- 让出粒度：各切片点新设 `*_YIELD_EVERY` 常量（起步对齐既有 25 档，大书实测后可调），导出供测试断言。
- 观察口：`preludeYieldStats`（各段让出计数；生产只增不读，测试断言用）。

### 5.2 刀 2：单章链 async 孪生

- 生成器化自叶向顶：`checkLeadsBookItems` → `checkLeadsForm` → `runAllChecks` → `checkWithDb`，各自留同步包装；顶 `runCheckForDocumentAsync`（新增，唯一新导出）。
- 4 个调用点改 `await runCheckForDocumentAsync`；self-heal 回调与树内核继续走同步版（行为零变）。
- rebuild 走 `openCheckDbAsync`；R47-11 的 3s TTL 语义由主线程侧 TTL 承接（worker 每次新起、worker 内模块内存态节流不复用——承接形态列入实施首步核实）。

### 5.3 边界（本批不动）

rebuild 内核一行不动；runner 其余检查器（禁词/复读/句式/文风…）保持同步调用不动；前端、SSE、缓存结构、DB 结构不动；不引依赖；同步路径对外行为与错误信封不变。

## 七、验收口径

- **A1 等价（硬门）**：每个被切段「同步驱动 vs async 驱动」双跑结果 deep-equal（冷/热两态各一；树聚合有现成套，leads 与单章链新增同款）。
- **A2 让出计数（硬门，区分性主锁）**：目标段隔离夹具（把目标段喂大、其余段喂小），断言「处理 N 项 ⇒ 让出 ≥ ⌊N/K⌋」（K = 导出常量）。单靠心跳不能区分「刀落在目标段」，故以本条件为主锁。
- **A3 心跳（硬门，存活）**：聚合/请求期间 setImmediate 心跳至少插队一次（R37-3 先例）。
- **A4 worker 路数（硬门）**：async 驱动确经 worker（注入桩断言被调用），且结果与同步驱动等价（含 `rebuildFailed` 降级分支）。
- **慢盘仿真（收口证据，不进 CI）**：`vi.mock('node:fs')` 给源树 stat/读注延迟跑目标链，记录「最长单次事件循环停顿 / 请求总时长」；真网络盘进不了 CI，如实记账、不假装覆盖。
- **收口定义**：① 两条目标路径全走 async 驱动；② 每段 A1+A2（+A3）；③ 慢盘数字留档；④ vitest / e2e / soak 三绿；⑤ 残余写进代码注释与台账。
- **残余形态（D4）**：单章解析、单次 `readChapterDir` 内的单文件、开库 PRAGMA、清单单文件整读——单次毫秒~十毫秒级，记账不遮。

## 八、风险与备记

- **worker 超时语义变化**：sync rebuild 无超时；worker 默认 120s（env 可调），超时 → 降级返回（树 fail-open `rebuildFailed`、单章 envelope）。可见降级胜过挂死，认这条口径。
- **效应让出的落地风险**：唯一新机制；同步驱动零行为变化兜底、async 侧有等价测试。落地不顺的退路 = rebuild 留残余（如实记账），不硬啃。
- **单章链 worker 化后的 TTL**：TTL 上移主线程承接（实施首步核实取舍）。
- **让出粒度取值**：25 档起步，常量导出、测试锚不脆。
- **并发面**：树聚合与状态检测并发 rebuild 由单飞合并（白赚，无新增锁面；worker 自开连接 + 既有 busy_timeout）。
- **真网络盘不可 CI 断言**：机制锁死 + 人工证据，如实记账。
