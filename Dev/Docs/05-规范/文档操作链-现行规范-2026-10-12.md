# 文档操作链（现行规范）

- 日期：2026-10-12
- 角色：**现行规范**（`05-规范/`）——文档操作链正本（范围/分工/评审/篇幅/新档/流转/归档/记档/校验）；项目根 `CLAUDE.md`「入口」只留本档指针
- 范围：辖 Dev/Docs 治理文档；根 `README.md` 编辑不在本链，其篇幅纪律见第三节（机器门 check:counts / check:docs 恒跑）
- 关联：`Dev/Docs/README.md`（目录/计数）、`00-总览与实施路线-2026-08-15.md`（顺序/决策/开放项）

## 一、分工

- `Dev/Docs/README.md` 只记目录 + 计数；总览只记开放任务 + 现行口径 + 待拍板（已收口不入）。
- 纪律条在正本 `CLAUDE.md`，文档操作链规则与细则落本档；其他文档只留指针。

## 二、评审

- 报告落 `01-评审/`；完成≠收口——P1/P2 修复+回归通过才收口，收口后上一轮入 Archive（扁平）；未收口不归档。

## 三、篇幅纪律

- 索引面（Dev/Docs README / 总览）只写结论 + 指针，不挂批号、日期、沿革。
- 介绍面（根 `README.md`）只对外介绍、禁项目进展，仅留 check:counts 口径数字。
- 机器门 `npm run check:docs`（辖索引面与介绍面；无体积上限——「不塞废话」是对编辑者的行文要求，不是给文档套字节天花板）。治理正本同守「不塞废话」，无体积锁、不入本门。

## 四、新档

- 命名 `主题-类型[-状态]-YYYY-MM-DD.md` → 入 `01-评审 / 02-执行 / 03-设计 / 04-调研 / 05-规范` → 同步 `Dev/Docs/README.md` 计数 + 总览地图（顺序/决策表如需）。
- 评审档名含执行模型：`主题-评审-<执行模型>-YYYY-MM-DD.md`，头部记「执行模型」行；只约束新档，旧档不追改。

## 五、流转

- 开工/完成改总览状态行；完成时决策待拍板→已拍板、回改方案，归位 `02-执行`（可开工）/ `03-设计`（暂缓）/ `05-规范`（现行规范），留验收证据。

## 六、归档/精简

- 只归已收口/失效档（未收口、未拍板、唯一计划、现行规范不归）；同步总览地图 + README 计数。
- 删档直删不 zip；删前核验 git 复原锚（锚树在位、与工作树零差异）并将锚号入 commit message；档内未了结事项先立开放项再删。

## 七、记档

- 总览行 = 一句结论 + 指针（报告/commit），明细随 commit message；已收口行随批移出，行全文 = git 复原锚；README 不设变更记录节。

## 八、校验

- 文件树与索引一致、链接 0 断链、计数一致；移位随批改指，不留悬空。
