# 文档操作链（现行规范）

- 定位：Dev/Docs 文档链的**规则正本**——槽位/命名/定位行/活账/评审与流转/归档/篇幅/门与边界/决策记录分界/升级。槽位与篇数正本 = `README.md`，未了结事项正本 = `00-活账.md`（本档不复制它们）。
- 不属于本档：单件事项的进度与状态（住活账）；跨主题可检索的决策理由（住 `.agents/notes/`，批 D 落地）。
- 模型来源：`project-harness`（链、门、篇幅）与 `agent-notes`（决策记录）两 skill；判据全文随副本住 `.agents/skills/`，本档只写本仓落地口径。

## 一、槽位与「不属于这里」

| 槽位 | 职责 | 不属于这里 |
|---|---|---|
| 索引（`README.md`） | 全链导航：每个槽位一行，写清职责与当前篇数 | 任何正文内容 |
| 活账（`00-活账.md`） | 未了结事项的唯一清单；现行口径看板 | 已完成的历史、过程叙述 |
| `01-评审/` | 对方案或交付的评审结论与验收判定 | 实施进度、设计理由 |
| `02-执行/` | 批次计划与交付记录：做了哪几批、各自结论、证据指针 | 设计理由（链到设计档） |
| `03-设计/` | 方案、取舍、被否决的替代方案 | 逐日实施记录、计划 |
| `04-调研/` | 外部事实、现状盘点、可行性结论 | 决策本身（住设计档） |
| `05-规范/` | 长期有效的操作规范 | 一次性流程、批次记录 |
| `Archive/` | 冻结的历史，只读 | 还可能改动的东西 |

## 二、命名

- 四段：`主题-类型[-限定]-YYYY-MM-DD.md`。主题 = 这件事的名字（不是文体名）；类型 = 所在槽位；限定可选（同主题多版本、署名评审者）；日期 = **立档日**——补写旧事也用今天，它标记文档自己的时间线，不是事件发生的时间线。文件名可排序、可解析。
- 类型词闭合（新档）：设计 → `03-设计/`；执行 → `02-执行/`；评审 → `01-评审/`；调研 → `04-调研/`；规范 → `05-规范/`。
- 评审档加限定段：`主题-评审-<执行模型>-YYYY-MM-DD.md`，头部记「执行模型」行。
- 历史名映射（旧档不改名）：`实施方案` / `执行方案` = 执行；`现行规范` = 规范；`报告` / `专项审查` = 评审。
- 同型同日多份：用主题内的序词区分（二轮 / 三轮），不靠限定段。
- 一档一事：主题换了就立新档并链回旧档；不在一份档里追加不相关的第二件事——追加会让日期、限定、结论一起失真。

## 三、定位行

- 每份链档开头一行定位：本档是什么、不属于本档的是什么、被排除的部分在谁那里。这一行是链的自证——读的人不必先猜它在链里的位置。
- 只约束新档；旧档随触碰补（历史正文不改写）。

## 四、活账

- 一行一条，**一句结论 + 指针**（路径或 commit 号），不写「详见相关文档」；状态只写当前阶段或阻塞原因，不写进度百分比。
- 加行：立设计/执行/评审/调研/规范档时同步加；归档前档内还活着的条件与待办先提成行再归；评审「有条件通过」的条件、「退回」的理由逐条入账。
- 摘行：了结即从活账删除，**不留「已完成」标记**——那会让活账失去「看一眼就知道还欠什么」的作用；归档时同步摘行；每次收口前清账，条目要么完成、要么明确放弃（写明理由）。
- 已收口行全文 = git 复原锚：行随批移出，锚写进 commit message。

## 五、评审与流转

- 评审必须给三出口之一：**通过 / 有条件通过 / 退回**；空缺等于没评。
- 完成 ≠ 收口：P1/P2 修复 + 回归通过才收口；未收口不归档。
- 设计档 ↔ 执行档：设计档 = 决策面（问题 / 现状 / 口径拍板 / 方案 / 被否决的替代 / 验收判据 / 风险），不纳入计划、只做展示；执行档 = 施工面（批序 / 每批靶点 / 验收判据 / 门命令 / 执行记录回填），只做落点展开、不复制设计论证；口径冲突以设计档为准。施工面能在设计档内收全 → 不另立；多批或需文件级落点展开 → 另立执行档。
- 状态单点：开工与完成只改活账对应行；槽位档内不写状态行。设计档同主题只保留一份在改，评审档同主题每轮一份是正常的。

## 六、归档

- 准入：只归已收口或已失效的档；未收口、未拍板、唯一计划、在用规范不归。
- 三关：① 核验内容与历史一致——对 git 复原锚（锚树在位、与工作树零差异），「正在冻的就是当时那份」；② 档内还活着的条件与待办先提成活账行再归，否则冻结会把它们一起冻住；③ 归档动作留痕——锚号入 commit message，档首加「📦 归档记」行。
- 同步：`README.md` 篇数 + 活账摘行；移位随批改全部入链，不留悬空。
- 冻结：移进归档即不再修改（含错别字）；要改就移回来改完再冻。原地直删不打包（git 即存档，压缩包是第二份副本）；需要引用时链接指进归档目录；归档内的出链允许过期。

## 七、篇幅

- 索引面（`README.md` / `00-活账.md`）只写结论 + 指针，不挂批号、日期、沿革。
- 介绍面（根 `README.md`）只对外介绍、禁项目进展，仅留门依赖的稳定口径数字。
- 机器门 `npm run check:docs` 辖上述两面（形态判据：单行长度 + 禁语 + 括号日期标注），不设文件体积上限——「不塞废话」是对编辑者的行文要求，不是给文档套字节天花板。
- 治理正本 `AGENTS.md` 不入本门，篇幅以自律为准。
- 词数预算（skill 的 `doc-budgets`）**不适用于本仓**：其口径是空格分词，对中文档等于「一段算一词」，拦得住数量级膨胀、拦不住行文变水；本仓细口径仍是上条单行长度。

## 八、门与诚实边界

- 机器门只辖：文件树 ↔ 索引一致、篇数一致、槽位顶层档被索引提及（声明面 = `scripts/harness/doc-index.manifest.json`）。
- **无门**：命名四段、定位行、活账文法、归档三关、评审三出口、篇幅节的行文要求——靠评审与自律生效，不假装有门。
- 新增门必须演示一次红：写一条会触发它的输入，跑红、修绿；没红过的门等于装饰。
- 扫描面（哪些目录与文件进门）是**仓库数据**，写进 manifest，不写死在脚本常量里。

## 九、链档与决策记录的分界

- 链档管**过程与交付**：这批做了什么、怎么评的、证据在哪。
- 决策记录管**跨主题、三个月后还会被检索的决定**——形态选择、负面保证、所有权边界、不做某事的理由；住 `.agents/notes/{proposed,implemented,rejected}/{feature,bug-fix,simplification,architecture,process,testing}/yyyy-mm-dd-topic.md`，格式与生命周期由 `agent-notes` skill 拥有。
- 判据：有人想推翻这个决定时，需不需要看到当初的理由？需要 → 立决策记录；不需要 → 留设计档或 commit message。
- 一个决定只有一个 owner：同一机制已有记录就原地更新；真推翻才新写，并互相链接。

## 十、升级

- skill 副本住 `.agents/skills/`（随仓版本化；本仓只是存放与加载方，不作者面）。上游更新后整体替换副本，再跑 `bootstrap --force` 刷新 `scripts/harness/` 下的校验器副本——manifest 里的申报不受影响，要重播才用 `--reset-manifests`。
- 刷新批要对照上游 diff 更新本档与 `AGENTS.md` 的指针句；装的是哪一版，读 `scripts/harness/version.json`。
