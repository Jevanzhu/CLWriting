## 批次 1：后端质量

### 1-1 P2-BE-4：foreshadow 扫描性能优化

**文件**：`src/document/foreshadow.ts:208-241`

**问题**：`scanForeshadowTrails` 对每伏笔 × 每章 × 每关联词做 `indexOf`，复杂度 O(F × C × K × L)。大书（200 章 × 50 伏笔 × 5 关联词 × 200KB/章）≈ 10M 字符扫描，实测可感知延迟。

**方案**：预建全文倒排索引（一次扫描，多伏笔复用）。

```
改动前：for f in foreshadows → for ch in chapters → for kw → indexOf
改动后：
  ① 收集所有唯一关键词 → Set<keyword>
  ② 一次遍历全书章节 → 对每章 text.indexOf(kw) 全部关键词
     → 生成 Map<章号, Map<kw, 位置[]>>
  ③ 每伏笔从索引查命中（O(1) 查表，无重复扫描）
```

**复杂度**：O(C × K_unique × L) → K_unique ≤ K × F，但全文只扫一次。

**改动范围**：`foreshadow.ts` 内部重构，对外签名不变。

**验证**：现有 `foreshadow.test.ts` 回归通过 + 新增大书性能测试（250 章 × 30 伏笔，断言 < 500ms）。

### 1-2 P2-BE-7：prepare() SRP 拆分

**文件**：`src/process/prepare.ts:83-351`（269 行单体函数）

**问题**：`prepare()` 同时负责：近况段构建、文风段构建、前章正文结尾段、RAG 召回段、预算裁剪降档、清单序列化——6 个职责混在一个函数里，改动一处需读全文。

**方案**：提取子函数，`prepare()` 变为编排层。

```
prepare()
  ├── buildRecentSection()      // 近况段
  ├── buildStyleSections()      // 文风铁律 + 样章 + 禁词/手法
  ├── buildPrevChapterSection() // 前章正文结尾段
  ├── buildRagSection()         // RAG 召回段
  ├── applyBudgetTrim()         // 预算裁剪 + 降档标记
  └── serializeSections()       // 拼接 → text
```

**改动范围**：纯提取，逻辑零改动。每个子函数 30-60 行，`prepare()` 降到 ~40 行编排。

**验证**：`prepare.test.ts` 全量回归（已有 15 个测试覆盖各段 + 降档 + 边界）。

### 4-5 P2-TST-6：环境敏感性能断言加固

**文件**：`test/document/tree-perf.test.ts`（3 处 `performance.now()` 断言）

**问题**：
- `expect(dt).toBeLessThan(1000)` — CI 慢机可能超
- `expect(dt).toBeLessThan(5)` — 缓存命中，CI 几乎必过但本地偶尔挂

**方案**：
- 首次构建：保留 `< 1000ms` 但加注释「CI 环境阈值宽松，本地目标 < 200ms」
- 缓存命中：改为断言 `dt < 首次构建 dt × 0.01`（相对断言，不受机器影响）
- 或改为只 log 不断言（性能测试非功能门禁）
