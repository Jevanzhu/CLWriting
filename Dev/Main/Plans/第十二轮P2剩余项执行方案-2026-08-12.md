## 批次 1：快赢（45min）

### 1-1 P2-FE-2：useChatTier 切书重置（30min）

**文件**：`src/studio/web-next/src/composables/useChatTier.ts:12`

**问题**：`_instance` 是模块级变量，切书时 `refresh()` 先清 `tierLoading` 再异步拉取，响应回来前 `models` 仍持有旧书列表。用户切书后在模型下拉框短暂看到旧书模型。

**方案**：`refresh()` 开头立即清空 `models`：

```typescript
async function refresh(): Promise<void> {
  models.value = []        // ← 新增：立即清空，避免旧书列表闪烁
  tierLoading.value = true
  // ... 异步拉取
}
```

**改动范围**：1 行新增。

**验证**：`composables.test.ts` 现有用例回归。

### 1-2 P2-FE-7：ChatPanel 滚动节流（15min）

**文件**：`src/studio/web-next/src/components/panels/ChatPanel.vue:64-67`

**问题**：`watch` 监听 `chat.messages.at(-1)?.content`，流式 `chat_text` 事件每次追加文字都触发 `scrollToBottom`（可能每秒数十次），大量消息时滚动卡顿。

**方案**：`scrollToBottom` 加 `requestAnimationFrame` 节流——同帧内多次调用只执行一次：

```typescript
let scrollRaf = 0
function scrollToBottom(): void {
  if (scrollRaf) return
  scrollRaf = requestAnimationFrame(() => {
    scrollRaf = 0
    const el = scrollContainer.value
    if (el) el.scrollTop = el.scrollHeight
  })
}
```

**改动范围**：`scrollToBottom` 函数体改写，~10 行。

**验证**：`chat-panel.test.ts` 回归 + 手测流式对话流畅度。

**方案**：提取 `parseHealProgress` / `parseWorkbenchEvent` 等 type guard 函数：

```typescript
function isHealPhaseEvent(ev: unknown): ev is { type: 'self_heal_phase'; phase: string; attempt?: number } {
  if (typeof ev !== 'object' || ev === null) return false
  const e = ev as Record<string, unknown>
  return e.type === 'self_heal_phase' && typeof e.phase === 'string'
}
```

**改动范围**：`workbench.ts` dispatch 内 9 处 `as` 替换为 type guard；新增 ~40 行 guard 函数。

### 3-2 P2-BE-4：state.ts enter() manifest 双读（30min）

**文件**：`src/state/state.ts:559-561`

**问题**：`enter()` 先调 `detectState(bookRoot, config)`（内部 `readManifest`），再调 `buildRecap(bookRoot, config, detected)`（内部再 `readManifest`）。同一调用链读两次。

**方案**：`detectState` 返回值携带 manifest，`buildRecap` 复用：

```typescript
export function enter(bookRoot: string): EnterResult {
  const { config } = cfgResult
  const manifest = readManifest(join(bookRoot, '项目', '文档清单.jsonl'))
  const detected = detectState(bookRoot, config, manifest)  // ← 传入
  const route = routeState(detected)
  const recap = buildRecap(bookRoot, config, detected, manifest) // ← 传入
  return { recap, detected, route, kind: config.kind ?? 'long' }
}
```

**风险**：`detectState` / `buildRecap` / `readRecapSnapshot` 已在其他位置独立调用，签名加可选参数 `manifest?` 保持向后兼容。

**验证**：`state.test.ts` 全量回归。

### 3-4 P2-BE-6：splitSentences DRY 统一（30min）

**文件**：9 处 `body.split(/[。！？\n]/)` 分散在：
- `src/check/count.ts`（本轮已提取 `splitSentences`）
- `src/metrics/style.ts`
- `src/learn/index.ts`（少了 `\n`）
- `src/document/foreshadow.ts`
- 其他

**问题**：口径不一致——`learn/index.ts` 的分句少了 `\n`，可能漏检跨行。

**方案**：将 `splitSentences` 提取到共享位置（如 `format/sentences.ts`），全局替换：

```typescript
// format/sentences.ts
export function splitSentences(body: string, includeColon = false): string[] {
  const re = includeColon ? /[。！？；\n]/ : /[。！？\n]/
  return body.split(re).map((s) => s.trim()).filter((s) => s.length > 0)
}
```

**改动范围**：新增 1 文件 + 9 处 import 替换。

**验证**：全量单测回归（分句口径变化可能影响 learn/count 等）。

## 批次 4：功能增强（4h+）

### 4-1 batch_size 自动连写编排

**文件**：
- `src/studio/server/api/stream.ts` — auto-write 端点
- `src/ai/orchestrate/self-heal.ts` — 自愈闭环
- `src/studio/web-next/src/components/ui/SettingsAi.vue` — UI

**现状**：
- `batch_size` 配置可存（UI + book.yaml）
- auto-write 端点接受单章 `{ chapter }`，处理一章闭环即返回
- 无多章循环编排

**方案**：

```
① 前端 autoWrite 改为可传 batch_size：
   POST /auto-write { chapter, batchSize? }
   batchSize > 1 → 前端循环调 autoWrite(chapter), autoWrite(chapter+1), ...

② 或后端编排（更优，减少 HTTP 往返）：
   POST /auto-write { chapter, batchSize }
   → self-heal 第一章 → pass 后自动推进 chapter+1 → ... → 全部完成或中途 escalate
   → SSE 回流每章进度（self_heal_phase 附 chapter 字段）
```

**推荐方案②**：后端循环编排，SSE 带章号区分。中途任一章 escalate 则停止，保留已完成章节。

**改动范围**：
- `self-heal.ts`：`runSelfHeal` 支持 `{ chapters: number[] }` 参数，循环调 `orchestrate`
- `stream.ts`：auto-write 端点解析 `batchSize`，展开为 `chapters` 数组
- SSE 事件加 `chapter` 字段
- 前端 WorkbenchView 展示连写进度（已完成 N/M 章）

**验证**：
- 单测：`self-heal.test.ts` 加多章场景
- e2e：`auto-write.spec.ts` 加 batchSize=2 场景
