### 5.1 P2（3 条，全部主审亲验成立）

**R50-A-1 [P2] win session-end 触发后取消关机 → 应用僵尸态：close flush 链永久失效 + server 死亡无重启**
- 位置：`src/desktop/main.ts:208/776/845/855`；`src/desktop/server-manager.ts:310`
- 证据与亲验：`sessionEnding` 全文件仅 3 处（声明/读/写 true）**无复位路径**；close 拦截器 `if (sessionEnding || appTearingDown) return` 在置旗后永久放行直关——跳过渲染层 `__clwFlushBeforeClose`；server 侧主动停机后 `shutdownStarted` 挡住 `scheduleRestart`，而全库 `serverManager.start` 唯一调用点是 bootstrap（`main.ts:728`），renderer 无任何重启链路。
- 影响：win 用户在 OS 关机画面点「取消」后——① 此后手动关窗未保存编辑**静默丢失**（「编辑永不静默丢失」红线窄缺口，与 ec23d753 重评-1 修复的 close/quit 链同族的不对称残留）；② UI 全部 API 永久失败成僵尸窗（重启应用可恢复）。
- 建议：session-end 后延迟观察（如 5s）进程仍存活则复位 `sessionEnding` 并允许 server 重拉；补取消关机回归测试。
- 定级依据：涉数据丢失红线但触发为「win + 关机后取消」窄组合且可重启恢复，P2 恰当（不到 P1）。

**R50-D2-1 [P2] 书改名迁移误报灰显键用旧冒号格式，现行 `\u0000` 键零迁移（功能失效）**
- 位置：写侧 `src/studio/web-next/src/stores/check.ts:17`（`clw-fp:${name}\u0000${docId}`）vs 迁移侧 `composables/useShelf.ts:31-32`（仍拼 `clw-fp:${oldName}:` 旧前缀，注释还声称「同构」）
- 证据与亲验：R49-27 把分隔符 `:` 改 `\u0000` 时漏改迁移分支——现行键永不匹配旧前缀，循环零命中：改名后旧名键滞留、新名侧灰显丢失，旧名重建书继承滞留灰显（正是该迁移要防的跨书串显）。测试 `r46-rename-keyed-state-migrate.test.ts:39` 因钉死同样旧格式而绿，掩盖断裂。
- 建议：迁移分支改 `\u0000` 拼前缀（或从 check.ts 导出 `fpBookPrefix` 单源），同步改 r46 测试键格式。

**R50-F-1 [P2] harvest-corpus 的 imagery 误报率统计 checkId 失配，统计面恒空**
- 位置：`scripts/harvest-corpus.ts:162`（判 `checkId === 'imagery'`）vs 生产侧 `src/check/count.ts:491`（产出 `checkId: 'imagery-overuse'`，全库无任何检查器产出裸 `'imagery'`）
- 证据与亲验：判定永假 → `imageryStats` 永不累加，「误报率统计.md」恒输出「无 imagery 命中样本」。该统计是 B3 前置决策输入（「>30% 列入剔除候选」），失效后 imagery 种子表实证剔除机制静默空转，且「无样本」误导作者以为语料无命中（实际有）。现有测试只锚定文件存在不锚定内容，门禁绿不代表该分支正确。
