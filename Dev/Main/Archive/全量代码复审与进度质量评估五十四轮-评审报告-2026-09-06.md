## 五、发现明细

### 5.1 P2×3（全部主审亲读源码定档成立）

**R54-A-1｜关窗/退出 flush 超时静默销毁零留痕**｜`src/desktop/main.ts:945-948`（close 链）/ `1618-1621`（quit 链）｜P2
`Promise.race([flushRendererBeforeClose(win), setTimeout(CLOSE_FLUSH_BUDGET_MS)])` 超时或渲染层异常得 `res === null`，与「非编辑页无钩子（无害）」不可区分——两链均直接 `destroy()`/继续退出，**零日志零确认**。对照同文件 session-end 链（R53-A-1 引入，`main.ts:1012-1013`）超时有「flush 未落定」log 留痕，三链不对称可证非设计意图。保存链 >4s（慢盘/server 退避窗）时自动保存节拍内的最后键入静默丢失且无诊断线索。修复面小：`res===null` 补 `log.warn`（区分超时/无钩子），产品口径可再决定是否按 failed 弹确认。置信度高（代码行为确定）。

**R54-A-2｜切库链主进程同步 IO 挂死面**｜`src/desktop/main.ts:1128`（`desktop:switch-library` handler）→ `426-436`（canSwitchLibraryDir：statSync + findWorkDir 同步爬祖先 + findGitAncestor）+ `455-473`（warnIfCaseSensitive → probeCaseSensitive writeFileSync 探针）｜P2
IPC handler 在主进程同步执行目录 stat/爬祖先/写探针；recent 列表残留失联网络卷时一点切换即冻结三窗 UI 数秒（「挂载点在服务器无响应」态）。R47-9 同族（readStore 面）已修，本入口未覆盖——同族第三处。修复建议：探测面异步化（fs/promises + 超时包裹）或入口先做可达性预探。置信度高（路径确定）、影响中。

**R54-B-1｜journal 崩溃恢复扫描整段静默吞错**｜`src/state/state.ts:312-314`｜P2
`catch { /* journal 扫描异常不阻断进门 */ }` 空体零留痕，包裹整个 crashedWrite 检查 + move-pending 自愈循环——循环内任一意外异常（readdirSync EACCES 等）使整轮崩溃恢复检查静默归零，作者对上次崩溃丢字零感知且无诊断线索。与全仓「降级留痕」纪律相悖（同函数其他降级分支均有 warn；R53-D-2 刚为该面补过如实报文，本缝是其在观测侧的孪生缺口）。修复面一行：`catch (e) { log.warn('state', 'journal 扫描异常，崩溃恢复检查降级跳过', e) }`。置信度高。

### 5.2 主审降档 1 条（P2 候选 → P3）

**R54-A-3｜session-end flush 与停机指令并发竞速**｜`src/desktop/main.ts:1005-1024`（flush IIFE）与 `1034`（serverManager.shutdown）同拍发出｜P3（降档）
child 收停机指令后 graceful-shutdown 立即 `server.close()+closeIdleConnections()`，渲染层保存 fetch 若靠新建/闲置 keep-alive 连接存在被拒/被杀窄窗。**降档理由**：R53-A-1 注释显式声明「并行尽力而为，不等待不拖停机」的设计取舍（串行化会把停机窗拉至 flush 2s + shutdown 3.5s ≈5.5s 级，关机窗口有限）；触发窗窄、语义已留痕。登记观察；如要收紧可改「flush 首回执后再下发停机」。置信度中。
