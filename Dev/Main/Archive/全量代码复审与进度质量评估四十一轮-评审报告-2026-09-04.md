### 3.1 P2（×3）

**R41-1〔n/a〕待建空书库在最近列表成永久死条目（switch-library 守卫与 bootstrap 语义分叉）** — C 域，主审亲验成立

- 证据：`src/desktop/main.ts` 四段链路守卫口径不一致——
  - `isLibraryDir(dir)`（:281-284）= `findWorkDir(dir) !== null && samePath(found, resolve(dir))`，要求目录**自身含 `.clwriting/`**；
  - `pickLibrary`（:322-364）「在此新建」分支返回**空待建目录**（不含 .clwriting，建第一本书时才自动建结构）；
  - `bootstrap`（:533-560）接受**任意现存目录**（`statSync().isDirectory()` 即可，含空待建目录）；
  - `switch-library` IPC（:695-720）却用 `!isLibraryDir(path)` 拒绝 → 「目录无效或不是书库」。
- 触发场景：作者「在此新建」→ 空书库入 recent → 因故退出（未建第一本书前）→ 从最近列表（Welcome.vue / Library.vue 的 switchLibrary）点回 → 恒被拒。该条目既打不开也自愈不了（recent 侧无失效清理机制对该形态生效），成**永久死条目**；只能再走一遍完整选择流程绕过。
- 定级依据：主路径功能性障碍（书库切换），跨平台（win/mac 同形态）；非数据损坏故 P2。
- 修复建议：switch-library 守卫对齐 bootstrap 接受面——目录存在即可放行，另保一道「不能是另一书库的子目录」防线（findWorkDir 祖先命中即拒绝，防误把书内目录挂成书库根）。补回归：空目录经 switch-library 可切换；书库子目录被拒。

**R41-2〔win〕树/清单 join 键无大小写折叠（外部纯大小写改名后定稿身份漂移）** — D 域，主审亲验成立

- 证据：`src/document/tree.ts:143-145` `entryByPath.set(e.path, e)` 与 `:174-175` `entryByPath.get(n.path)` 均为**精确字符串** join（无 relPathKey/NFC 归一）；`src/state/state.ts:569-582` `finalizedStems.add(e.path)` / `.has(rel)` 同为精确匹配。已有原语 `relPathKey()`（`src/fs/safe-path.ts:122-125`，posix 分隔归一 + win32 casefold）在**这些 join 点未使用**（R38-14 只收编了 registered!==relPath 比较面与 wiringFileLockKey）。
- 触发场景：win 上用户在资源管理器把 `第1章.md` 改成 `第1A.md`→`第1a.md`（纯大小写改名，Explorer 经两步完成）或直接改大小写 → 树扫描重建 entryByPath 键为盘上新拼写，而清单/定稿侧比较按旧拼写 → docId 落 legacyId 兜底、**定稿章显示回草稿**、findUnfinishedChapter 永久误判「未完成」。mac 默认卷同理受 R41-13（posix 折叠缺失）覆盖。
- 定级依据：外部操作常态可触发 + 身份漂移用户可见 + 永久性；win 主发行面。
- 修复建议：join 键统一 `relPathKey(toNfcName(p))`（win32 折叠 + NFC 归一双防线；toNfcName 系平台规范化批已建原语、零消费——本条同时收编 R41-12）；state.ts finalized 比较面同口径。补回归：纯大小写改名后定稿身份保持。

**R41-3〔n/a〕导出批注剥离启发式误伤含 `#%` 的 URL（正文静默截断）** — E 域，主审亲验成立

- 证据：`src/export/index.ts:115-119`：
  ```ts
  const i = line.indexOf('#%')
  const isMarker = i !== -1 && (line.slice(0, i).trim() === '' || !/\s/.test(line[i - 1]!))
  ```
  「紧贴形态」判定为「`#` 前不是空白」——但 URL 片段 `https://zh.example.org/wiki/#%E5%88%86%E7%B1%BB` 的 `#` 前是 `/`（非空白）→ 判为行内批注 → **从 `#%` 起整段剥除**。已用真实 exportBook 复现（正文行尾带 wiki 链接的章导出后链接消失）。
- 触发场景：正文含任何百分号编码锚点的 URL（wiki/文档链接常态形态 `#%E5…`/`#%20…`）→ 导出稿静默丢内容，无告警。
- 定级依据：导出物正确性缺陷，静默数据损失面；与 IR-5/R40-40 围栏族同域但独立（这是 isMarker 判定面不是围栏闭合面）。
- 修复建议：紧贴形态收紧为「`#` 前是 CJK 字符」（行内批注真实形态是中文正文紧贴 `#批注#`；`/`、字母、数字等 ASCII 一律放行）。补回归：URL 含 `#%XX` 片段原样导出；真批注仍剥。
