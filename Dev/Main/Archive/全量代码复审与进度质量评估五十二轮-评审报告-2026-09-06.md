## 五、问题清单（P2×3 + P3×2，全部主审亲验成立）

### R52-A-1 [P2] pickLibrary「在此新建」分支缺 findWorkDir 祖先检查——嵌套书库防线单侧缺失

- **位置**：`src/desktop/main.ts:501-517`（choice.response===0「在此新建」分支）
- **证据**：该分支有 findGitAncestor + warnIfCaseSensitive，但缺 `canSwitchLibraryDir`（`src/desktop/main.ts:422-432`）在位的祖先检查——`const found = findWorkDir(dir); if (found !== null && !samePath(found, resolve(dir))) return false`。
- **问题**：在既有书库的子目录里「在此新建」会造出嵌套书库：内层 `.clwriting/` 抢占 workDir 判定，双 server 端口/锁根/task-gate 单进程单锁契约冲突（e2e global-setup 即有该契约告警留痕）。切库侧防线在位、新建侧缺失，防线单侧。
- **修法**（批 1）：新建分支复用同款检查，命中祖先书库时阻断并指引改选库根之外目录；配回归测试（子目录新建被拒 + 库外新建放行两臂）。

### R52-E-1 [P2] check 链 rebuild 先于 epochFp0——陈旧红值可乘头窗投毒缓存

- **位置**：`src/check/run.ts:480`（`const rebuilt = rebuild(bookRoot, cachePath)`）先于 `:517`（`epochFp0 = computeTreeIssuesGlobalFp(...)`）
- **证据**：rebuild 内部扫源文件 stat 与 epochFp0 计算之间存在头窗——期间源文件被改写时，stale-db 的红值以**新 epoch** 落入缓存（缓存指纹自洽，末检不再失效它）；既有终检（`src/check/run.ts:716-722`）只覆盖 epochFp0 **之后**的漂移，头窗内变更全部漏防。
- **问题**：数据正确性级——作者改稿后跑机检，可能拿到改稿前的陈旧红值且此后被缓存固化（后续同树命中缓存不再重算）。触发需头窗内并发写（窗口毫秒级、本地单用户场景概率低），故 P2 不升 P1。
- **修法**（批 1）：`epochFp0` 计算提前到 `rebuild` 之前——终检窗口随即覆盖「fp0 → 检查全程」，头窗内任何变更使 fpEnd≠fp0、缓存写入按既有失效路径丢弃。纯语句重排 + 一条「rebuild 前改稿 → 缓存不投毒」回归。

### R52-E-2 [P2] 机检阈值配置面断裂——repeat/句长/意象/字数容差五键作者不可调

- **位置**：`src/check/runner.ts:184`（`sections.push(checkRepeat(body))` 无 config）；`STRICT_SHORT_CHECK_IDS`（`src/check/runner.ts:357-381`）缺 `'repeat'`/`'sentence-length'`/`'imagery-overuse'` 三项
- **证据链**：book.yaml `checks` 段解析只认 `imagery_words`/`leak_keywords` 两键（`src/format/yaml.ts:451-472`）；`short` 段仅透传 `body_part_threshold`/`simile_threshold`；`GlobalBookDefaults`（`src/format/global-defaults.ts`，15 键）无任何机检阈值；前端 `SettingsAnalysis.vue` AI 机检卡只暴露 `defaultShortStrict` 一项。
- **问题**：repeat（复读率）/句长上限/高频意象/字数容差四类检查的阈值全部硬编码在引擎内，书级/全局两级配置链对其不可达——严格短篇模式想提升上述三项的强度也无门（提升名单漏登）。与项目「默认值显式 resolve、链路参数逐层可调」的守则相悖。
- **修法**（批 1，四面接线）：① book.yaml `checks` 段扩 5 键（`repeat_threshold`/`repeat_chars_threshold`/`max_sentence_len`/`imagery_threshold`/`word_count_tolerance`，解析+序列化+补丁白名单 CONFIG_PATCH_LEAVES 同步）；② runner 各检查透传 config；③ `GlobalBookDefaults` 增对应全局托底键 + `applyGlobalDefaults` 合并；④ `SettingsAnalysis.vue` 增输入位。配 round-trip + 生效链回归。

### R52-I-1 [P3] onSpawn/onAutoWrite 成功 toast 缺 await 后书名复检（同文件兄弟函数纪律不一致）

- **位置**：`src/studio/web-next/src/views/WorkbenchView.vue:194-195`（onSpawn）、`:236-238`（onAutoWrite）
- **证据**：两处 `await spawnRole(...)`/`await autoWrite(...)` 之后直接 `ui.toast('已开始生成'/'…已开始全自动写稿')`；而同函数 **catch 分支**与 onInterrupt/onOutline 均有 `if (props.bookName !== book) return`（R70-10 纪律）。
- **问题**：POST 在途期间切书，A 书的成功 toast 弹在 B 书工作台。纯 UI 误导（请求本身按入口捕获的 book 发出，无数据损害）。
- **修法**（批 2）：两处 await 后各补一行书名复检。

### R52-I-2 [P3] 切书 watch 清残留漏 `err` 与 `state`——错误条跨书残留 + 旧书状态卡短暂残留

- **证据**：切书 watch 只清 `prompt`/`draftSaved`（RB-FE-P2-4），`err.value` 无任何清除路径（仅下次动作覆写）、`state.value`（含 nextChapter）保留旧书值直至新书 getState 返回。
