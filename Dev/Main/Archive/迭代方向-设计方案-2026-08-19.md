## 第〇节 设计总则（红线，全方向通用）

1. **零 token 确定性优先**：凡能用纯函数 + 文件比对解决的（A1 缓存、B 语料、A4 日志），不引入 AI 调用；AI 调用仅限 C1/C2 摘要生成与既有链路。
2. **文件即真相**：所有新产物（章摘要/卷摘要/语料候选）落书内目录为 md/jsonl，作者可手改，程序产物可被手改覆盖且不报错。
3. **模型可见 ⟺ 已记录**（CLAUDE.md 既有守则）：摘要注入 prompt 必须走 visibleInjections 登记，纳入 verifyVisibleRecorded 治理测试口径。
4. **加性扩展**：providers.json 加 pricing、book.yaml 加预算键、chunks 表加 norm 列——读侧缺省行为全部不变，存量数据零迁移或一次性惰性回填。
5. **账本永走精准读取不走 RAG**（materials.ts:12 既有红线）——本方案不改召回消费面，A3 只优化召回内部实现。
6. **缓存只是加速**：A1/A3 一切缓存语义必须与全量重算逐字节等价，golden 对照测试守门。
7. **默认值显式 resolve**（CLAUDE.md 既有守则）：新增链路参数（K'、预算口径、价格缺省）逐层显式 resolve，保证重放可精确重建。

## 第二节 方向 A：架构成色

### A1 树红点增量缓存

**现状**（方向方案 §二已证）：`collectTreeIssues`（`src/check/run.ts:175-250`）每次请求逐章同步整读；前端每次树加载都拉（`stores/tree.ts:111`）。

**设计**：

- index.db 新表（P1-①）：

```sql
CREATE TABLE IF NOT EXISTS tree_issues_cache (
  rel_path    TEXT PRIMARY KEY,   -- 相对书根的章路径
  mtime_ms    INTEGER NOT NULL,
  size        INTEGER NOT NULL,
  verdict_fp  TEXT,               -- 项目/分析/<docId>.json 的 (mtime,size)；NULL=无信封
  report_json TEXT NOT NULL       -- {reds, yellows, rejected} 序列化，与全量重算同构
);
```

- `collectTreeIssues` 流程改造：循环内每章先 stat 正文文件 + stat 分析信封 → 三元组全命中读 `report_json` 直接聚合；任一 miss 走现行 `checkWithDb` 并回写缓存。`BatchCheckContext`（CC-P1-3）三项预扫保留不变。
- 失效口径：挂靠 `invalidateTreeIndex` 既有失效点（`src/document/tree.ts:272-295`），结构性变更（改名/移动/删章）时整表清空——与 probe 缓存同生共死，不新增第二套失效逻辑。
- verdict 联动：驳回裁决写信封（`api/review.ts:192-228`）后信封 mtime 变，verdict_fp 自动失效，无需专门通知。

**边界与不做**：不改机检本体（count.ts 零改动）；不做跨进程失效通知（单实例锁既有前提）。

**验收**：①700 章 mock 书，二次请求文件整读次数 = 变更章数（tree-issues-scan-count.test.ts 口径扩展）；②随机组合（改 3 章正文 + 驳回 1 章 verdict + 移动 1 章）结果与无缓存全量重算**逐字节一致**（golden 对照）。

### A2 worker 化（批 9，P3 闸后）

**设计**：`src/studio/server/labor/` 新增 worker host——单 worker 串行 job 队列（串行规避 SQLite 写锁竞争），job 类型 `{type: 'collectTreeIssues' | 'detectState' | 'rebuild', bookRoot, cachePath, config}` → 回 JSON。服务层调用点包 Promise，请求处理器真 async。

- worker 入口加入 tsup 构建清单（electron-builder files 已含 dist/**，打包零新增配置）；
- 事件库单例（`events/store.ts:114`）留主线程，worker 内不开事件库连接——隔离边界 = 短生命周期 DatabaseSync；
- 降级：worker 启动失败 / 超时 → 回落现行同步路径并 log.warn（fail-closed 到现状行为）；
- 库 API（state.ts / run.ts / rebuild.ts）签名不动，现有直调单测零改动。

### A3 RAG 惰性指纹校验 + 预存范数

**设计**（`src/rag/`）：

- `chunks` 表加列 `norm REAL`（`ALTER TABLE … ADD COLUMN`，schema 版本号递增；存量回填 = 打开库时发现 NULL 批量就地计算写回，一次性）；`buildIndex` 写入时同步计算。
- `cosineSimilarity` 退化为「预存范数的点积」：`dot(q, c) / (qNorm * c.norm)`。
- `recall()` 倒序校验（P4）：全量点积排序 → 取 top-K'=20 候选 → 仅对候选章集合做指纹校验（`validateIndexedChapterFingerprints` 改为按章子集）→ 过期剔除、顺位递补至 top-5。
- ANN 明确不做（方向方案 §二 A3 论证）；scale 测试 2 秒界值保持为跳闸。

**验收**：scale 测试新增断言「单次召回正文文件读 ≤ K'」；召回结果与现行实现 top-5 一致（同向量集对照）；norm 缺列迁移幂等。

### A4 结构化日志通道 + 迁移失败可见化

**设计**：新模块 `src/log/`：

- `log.error/warn/info(tag, msg, err?)` → JSONL 追加 `userData/logs/app-YYYYMMDD.jsonl`，行格式 `{ts, level, tag, msg, err:{name, message, stack?}}`；
- 写入走进程内串行队列（appendFile 排队，不 await 调用方）；启动时清理 >7 天文件；
- dev 态（CLW_DEV_UI / 非 pack）同时镜像 console；
- grep 驱动替换 src 下 50 处 `console.error/warn`（37+13，探查清单在案），逐处保留原 tag；
- **边界**：业务观测仍走事件库，日志只承载进程诊断——两通道不合流。

迁移失败横幅：`migrateBookSession` 失败（`events/store.ts:399`）与启动链迁移失败统一收集为 `startupNotices`（内存 + log 落痕）→ `GET /api/startup-notices` → 前端 App 级一次性横幅（「事件库迁移失败，旧库保留于 <路径>，可找回」）。**不做**重试自动化——数据保全前提下人工介入优先。

## 第三节 方向 B：真实语料回归库

### B1 采集：误报按钮 + 事件

- `CheckPanel.vue` 红黄项行内加「误报」次级动作（图标按钮 + 一次确认，防误触）；
- `POST /api/books/:name/documents/:docId/check-false-positive`，body `{checkId, chapter, excerpt}`——excerpt = 命中区间 ±50 字上下文（服务端从正文切，不信客户端传来任意长文本，上限 200 字）；
- 事件库新增类型 `check/false-positive`（`src/events/types.ts` 白名单 + 载荷形状 `{checkId, chapter, excerpt}`）；workspace 会话（ws-）承载，非 surface；
- 同章同 checkId 重复标记幂等（最近一次为准，查询侧去重）。

### B2 自举脚本：存量书幸存者判定

`scripts/harvest-corpus.ts <bookRoot>`（确定性、零 token）：

- 数据源 = `.版本/` 章快照（AI 稿版本档案，`git/ai-track.ts` 文件档案路径）+ 定稿正文 + 现行机检；
- 对每章各版快照跑机检，按 checkId 对齐命中区间：**区间在定稿幸存 ⇒ 误报候选；被改写消失 ⇒ 命中候选**（author/signal 同款 diff 判定技术，`author-signal.ts:26` 先例）；
- 产出 `工作区/语料候选/误报候选.md` + `命中候选.md`（checkId / 章号 / 摘录 / 判定依据 / 版本对照），**候选制**——作者勾选后 `npm run corpus:commit` 固化为仓库用例 `test/corpus/checks/<checkId>.json`（P5-①），形如 `[{excerpt, expect:'fire'|'silent'}]`。

### B3 回归门：golden-master

- `test/check/corpus.test.ts` 遍历 `test/corpus/checks/*.json`，每条摘录过当前检查器断言 expect；
- 空目录时 skip（新书/未自举不影响 CI）；入库即生效，词表/阈值改动复活误报 = 红 CI；
- 词表进化（B4 前置）：自举脚本顺带产出 `误报率统计`（imagery-seed 21 条为分母），超 30% 的种子短语列入候选剔除清单——改 `imagery-seed.ts` 仍走人工提交 + 回归门守门。

### B4 信息差词表派生（P6-①）

- 布线账本 md front matter 新增可选键 `leak_keywords: [..]`（加性；`布线/*/账本.md`）；
- `runner.ts:152` 供给链插入一级：`input.leakKeywords ?? config.checks?.leak_keywords ?? deriveLeakKeywords(布线目录) ?? []`——派生即扫描账本 front matter 收集键值（复用账本读取既有解析），不新增缓存；
- 未声明任何键时维持现状静默跳过（X-P2-22 语义不变）。

## 第四节 方向 C：超长篇上下文管理

### C1 章摘要生成器（P7-①）

- 新任务键 `summary-chapter`（`src/ai/tasks` 注册；runTask 编排，四路记账自动覆盖）；
- **挂点一（定稿即生成）**：finalize 管线定稿闸通过后 best-effort 调用——失败不阻断定稿，log.warn + 留待自愈；产物 `定稿/摘要/章摘要/<章号>-<标题>.md`，front matter `{chapter, generatedAt, model, sourceHash}`（sourceHash 绑定定稿正文，正文后改则摘要视为过期）；
- **挂点二（按需自愈）**：`prepare` 发现近章摘要缺失（自动写章链路）时现场补生成，计入 calls_per_chapter 记账（既有预算闸口径）；
- prompt 预算 = `summary_chapter_max`（yaml 键已在，终于有消费者）；输出要求三行内：情节推进 / 账本变动 / 章尾钩子；
- **红线**：摘要注入备料走 visibleInjections 登记（第〇节 3）。

### C2 卷摘要按需生成

- `prepare` rank-3 段需要 `定稿/摘要/卷摘要/N.md` 而缺失时，从该卷已有**章摘要链**生成（任务键 `summary-volume`；输入 = N × summary_chapter_max 字，成本可控）；卷边界按大纲卷纲编号判定；
- 章摘要不全的卷不强行生成（log 留痕 + 该段留空降级），逼着先补章摘要——不引入「摘要的摘要」二阶误差。

### C3 细纲闭环

- `api/outline.ts` 细纲 prompt 增段 `## 当前卷进展`（≤800 字，来源 = 当前卷摘要，缺失则整段省略并在 promptMeta 留痕）——摘要金字塔同时服务规划层。

### C4 token 系数实测校准（P8-①）

- `scripts/calibrate-tokens.ts`：读事件库 `llm/call`（promptMeta.chars + usage.input 成对，types.ts:207），按 model 线性拟合 chars→tokens 系数，输出报告（样本量 / 拟合度 / 建议值）；
- `estimateTokens`（prepare.ts:99）改为按模型查表 + 0.6 兜底；系数表为 src 内常量并注明测定日期——**不做成运行时配置**（校准是低频动作，配置化徒增链路参数）。
