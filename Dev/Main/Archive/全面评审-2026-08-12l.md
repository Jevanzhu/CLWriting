## 四、安全审查

> 4 路 Agent 安全专项 + 主线交叉验证

### P1（应修复）

#### P1-SEC-1：analysisPath + listVersions/readVersion 的 docId 缺路径校验

- **文件**：
  - `src/document/analysis.ts:33-34` — `analysisPath(bookRoot, docId)` 直接 `join(bookRoot, '项目', '分析', '${docId}.json')`
  - `src/document/version.ts:131` — `listVersions(versionsDir, docId)` 直接 `join(versionsDir, docId)` + `readdirSync`
  - `src/document/version.ts:149` — `readVersion(versionsDir, docId, id)` 直接 `join(versionsDir, docId, '${id}.md')`
- **问题**：`docId` 从 `文档清单.jsonl` 的 manifest 条目读取，未经路径校验。对比 k 轮已修复的 `finalize.ts`（改用 `safeManifestPath`）和 `snapshots.ts:157`（docId 白名单），这三处内核函数缺乏同样的防御。
- **攻击链**：manifest 篡改（`"id":"../../etc/evil"`）→ `analysisPath` 构造越界路径 → `writeAnalysis` 向 bookRoot 外写 JSON 文件；`listVersions` 对任意目录做 `readdirSync`。
- **信任级别**：需本地文件篡改能力（与 k 轮 P1-SEC-1/2 同级别）。
- **修复建议**：在三个函数入口增加 docId 净化：

```typescript
function safeDocId(docId: string): boolean {
  return !docId.includes('\0') && !docId.includes('/') && !docId.includes('\\') && !docId.includes('..')
}
```

## 五、后端架构与代码质量

> ~25K 行 TS，19 个模块 · 评估：★★★★☆（4/5）

### P1

#### P1-ARCH-1：`ai/ ↔ process/` 循环依赖

- **文件**：`src/ai/orchestrate/self-heal.ts:25` + `src/process/draft-pipeline.ts:19`
- **依赖链**：
  ```
  ai/orchestrate/self-heal.ts → process/draft-pipeline.ts (buildDraftPrompt, saveDraft)
  process/draft-pipeline.ts   → ai/author-signal.ts (recordAuthorSignal)
  ```
- **影响**：ESM live bindings 使此循环运行时不崩溃（函数都是顶层声明），但违反分层原则。任一方在模块顶层添加初始化逻辑可能触发 TDZ。
- **修复建议**：`draft-pipeline.ts` 中 `recordAuthorSignal` 改为回调注入（`saveDraft` 接收可选 `onSave`），消除 `process → ai` 值依赖。

#### P1-ROBUST-1：`readForeshadows` 读操作触发迁移写副作用

- **文件**：`src/document/foreshadow.ts:123-125`
- **问题**：`readForeshadows` 是「读」函数，但内部调用 `migrateLegacyForeshadows(bookRoot)`，后者执行 `rmSync(oldPath)`。读操作产生写副作用。
- **影响**：任何调用 `readForeshadows` 的路径（API 端点、prepare.ts 伏笔提醒）都触发迁移。迁移仅执行一次（旧文件不存在后跳过），但首次中断有数据丢失风险。
- **修复建议**：将迁移移到 install 阶段，`readForeshadows` 只做读。
