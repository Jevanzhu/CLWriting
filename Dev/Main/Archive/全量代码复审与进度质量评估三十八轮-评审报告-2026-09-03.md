## 四、P2 详述（亲验证据）

### 4.1 R38-1：事件库迁移回滚链可拆掉自家 R71-25 防线

迁移流程（`migrateBookEventsStore`，书改名触发）：墓碑预写 → 逐文件 `renameSync` 搬移（:1109）→ 改会话钥匙 → 失败时逆序 `renameSync` 回滚（:1127）→ **无条件** `rmSync(oldDb + MIGRATED_EXT)` 撤墓碑（:1138）。

失败窗构造（win）：杀软/索引器瞬时锁住 `.db`/`-wal`（SQLite 文件是 AV 高频目标）→ 搬移第 N 个文件 rename 抛 EPERM → 进入回滚 → **同一瞬时锁未释放**，回滚 rename 同样失败（仅 log.error 继续）→ 撤墓碑照常执行 → 旧路径 `.db` 与 `.migrated` 双缺 → 迟来首开按「正常缺库」重建空库，旧 hash 下对话史/审计视图清零（数据滞留 newDb 成孤儿）。这正是 R71-25 墓碑机制要防的场景，被「回滚失败仍撤碑」的后门拆掉。修复：搬移与回滚均走 `renameWithRetry`（3×50ms 退避）；回滚存在失败项时**保留墓碑**（fail-closed：碑 + 半回滚态并存只影响下次迁移重试，不影响旧库打开判定面）。

### 4.2 R38-2：导出覆盖「归档不删」哲学的同名漏网

`exportBook` 清旧逻辑：`old !== mergedFileName` 才 `archiveOldExport`（:304）——**当前同名产物被跳过**，随后 `atomicWriteStream` 直接覆盖（:412）；投稿视图同款（:504 `old === submissionName) continue` → `atomicWriteFile` 覆盖）。分章目录侧 R67-1 已把「覆盖手改稿」定性为不可挽回并整目录归档，合并稿/投稿视图是漏网同族。修复：覆盖同名产物前先 `archiveOldExport`（其内部已带 renameWithRetry + 失败 warning 降级，语义现成）。

### 4.3 R38-3：mac 签名配置与上游语义错位

上游链路亲核（node_modules/app-builder-lib）：`macPackager.js:296-297`——`qualifier === null` → `handleNullIdentity()` → log "skipped macOS code signing" → **return false，签名整体跳过**；`findSigningIdentity` 中 `qualifier === "-"` → `new IdentityClass("-")` → 走 doSign **真 ad-hoc 密封**。实包验证（dist-electron/mac-arm64/CLWriting.app）：`codesign -dv` 显示 `flags=0x20002(adhoc, linker-signed)`、`Sealed Resources=none`——这只是链接器残留，bundle 整体未密封；`spctl -a` 拒绝。electron-builder.yml:18 注释宣称「identity: null = ad-hoc 签名」与上游语义相悖。修复：`identity: null` → `identity: "-"`（无证书环境本地构建必成、行为确定，与作者意图完全兼容），注释同步改写；根 README「macOS 版使用须知」措辞随之更准确（ad-hoc 密封后「已损坏」提示面收窄，右键打开指引继续有效）。
