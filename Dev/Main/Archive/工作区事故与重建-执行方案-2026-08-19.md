## 五、适配原则（本方案的底线）

1. **基线是现在的 HEAD，不是事发前的工作区**——所有改动以当前文件为底本落笔，禁止盲贴旧 diff。
2. 测试重建以**等价或更强覆盖**为准（允许结构不同，不允许覆盖缩水）。
3. README 数字、徽章文案等「数值/文案」类内容一律按重建后实况重算，不照抄历史值。
4. 每步落笔前 `git status` 确认无并发操作（本机仍有多会话并行作业的现实）。

## 六、防再发措施

1. **评审/核验类子任务一律只读**：任务书显式写明「工作区有未提交改动；只允许 `git show/diff/log`，禁止 checkout/restore/reset/stash/clean 任何写状态命令」；能用只读代理类型就不用全权限类型。
2. **对照多版本用 `git show`/`git diff`，永不 materialize**：需要工作副本对比时用 `git worktree add` 到独立目录。
3. **未提交的重要改动先落锚**：跨会话作业时，开工即 `git stash` 或 WIP commit，改完再整理——本次若有一枚 WIP commit，损失为零。
4. **大面积危险命令清单**（对人对代理同权）：`git checkout <ref> -- .`、`git restore .`、`git reset --hard`、`git clean -fd`、带 `-- .` 的任何历史检出。
