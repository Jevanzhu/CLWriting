## 二、设计要点

- **隐藏用 v-show（Ribbon/TabBar/StatusBar）/ v-if（ViewHeader/EditorDocHead/page-title）**：外壳组件不卸载，与既有「折叠不卸载」口径一致；EditorDocHead 是标题编辑入口，卸载后重挂由 watch 恢复 titleModel，无状态丢失。
- **拖拽条**：macOS 无边框窗依赖标题区拖拽；Ribbon/TabBar 隐藏后全窗无 drag 区，补 28px 透明条占 ws-main 顶（flex 内自然撑位，不遮内容）。交通灯为系统绘制，无内容重叠。
- **收窄纯 CSS**：`.editor-focus .doc-page` 覆写 max-width，不写 prefs——退出即恢复用户 pageWidth，符合「不记忆」拍板。
- **Esc 让渡**：`overlayOpen`（palette/confirm/settings/export/shelf）优先——各弹层 Esc 归自身处理，专注退出不抢键。

## 五、修订批（同日：真全屏 + 纸张放大 + 打字机修复）

- 背景：作者实物验收提出三项——①只隐藏 UI 不是真专注，**要全屏**；②720px 收窄实物太窄，**编辑纸张放大**；③**打字机模式没生效**。
- 打字机根因：首版 `typewriterExt` 在 `updateListener` 内直接 `u.view.dispatch`——CM6 铁律「更新进行中禁 dispatch」，抛错且被 CM 的 listener try/catch 吞成 console.error，**静默失效**（输入时永远不居中）。修复：微任务推迟到本轮 update 完成后 dispatch（取当下光标，不映射旧位置）+ `.cm-content` 底部 45vh 滚动余量（末行也能居中）；实现收编 `editor/typewriter.ts` 单源（CmHost 与测试共用）。
- 全屏链路：`workspace.setFocus(on)`（toggleFocus 单源收敛）→ `shared/fullscreen.ts` 桥 → Electron 走 IPC `desktop:set-fullscreen`（主进程 `win.setFullScreen`——HTML5 Fullscreen API 在菜单加速键路径无用户手势会被拒，主进程无此限制）→ preload 另暴露 `onFullScreenChange`，主进程转发 `enter/leave-full-screen` → WorkspaceShell 反向同步（系统手势退全屏 → 连带退出专注；进全屏不反向开专注——全屏 ≠ 专注）。浏览器/dev 降级 HTML5 Fullscreen API，happy-dom 全 no-op。
- 纸张放大（拍板修订：废弃 §一「进入时自动收窄 720px」）：`.editor-focus .doc-page { max-width: min(calc(var(--page-width, 1020px) + 160px), 88vw) }`——用户页宽 +160（默认 1180），88vw 封顶防窄窗溢出；仍纯 CSS 覆写不动偏好。
- 附带：useHotkeys 对 `defaultPrevented` 键让渡（CM 搜索面板 Esc 已被编辑器层消费，关面板不再连带退专注）；composables-low.test.ts 修复 mountHotkeys 监听跨用例泄漏（旧监听器先跑 preventDefault 会吞新用例事件，属既有基建债被让渡守卫暴露）；vitest.config.ts 钉 `@codemirror/state|view` 别名到 web-next 嵌套 node_modules（真实 CM 扩展回归测试得以运行）+ web-next tsconfig paths 同步。
