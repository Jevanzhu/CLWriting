## 四、P2 发现（×6，全部主评审亲验属实）

### A-1（P2）Responses 协议线缺 R73-1 用量估算兜底——网关不回 usage 时记账恒 0
- 位置：`src/ai/provider/responses-adapter.ts:339`、`:348`
- 亲验：339/348 行 `const ev = emitDone(toUsage(r.usage), …)`；`toUsage(null)`（190-196 行）返回 `{inputTokens: 0, outputTokens: 0}` 且无 `estimated` 标记。对照 anthropic-adapter.ts:318-325 与 openai-adapter.ts:418-427 均已按 R73-1 用 `estimateInputTokens/estimateOutputTokens` 折算并标 `estimated: true`——三协议矩阵三缺一。
- 影响：openai-responses 端点完成不回 usage 时 tokens/cost 记 0，预算闸对该类端点永不生效、成本报表系统性偏低。
- 修法：completed/incomplete 无 usage 时与另两适配器对齐构造估算 usage + `estimated: true`。

### C-1（P2）exportBook 信封契约两处裸穿——目录准备/旧产物清点在 try 外
- 位置：`src/export/index.ts:224`（`mkdirSync(exportDir, {recursive:true})`）、`:246`（`readdirSync(exportDir)` 清旧循环；循环体内 archiveOldExport 自带 try，但 readdir 本身在外）
- 亲验：主信封 try 起于 316 行；224/246 位于其外。
- 影响：工作区只读/权限异常（EROFS/EACCES）或目录被并发删除时裸异常——worker 形态变 500 丢 chapterCount/warnings，违背 R67-10/R70-4 确立的 `{ok:false}` 信封契约。
- 修法：mkdir 与清旧并入既有 try 或本地收编为 `{ok:false, error:'导出写入失败：…'}`（R70-4 同款）。

### D-1（P2）互斥矩阵单向缺口——orchestrationBusyFor 不查 isSpawnRunning
- 位置：`src/studio/server/api/task-gate.ts:140-145`；受影响端点 outline.ts:58 / analysis.ts:128 等 / onboard.ts:83 / lead-updates.ts:31
- 亲验：函数体三查 isSelfHealRunning/isChatRunning/hasBackgroundTasks，无 isSpawnRunning；反向（任务在途→拒 spawn）由 stream.ts heldTaskGatesFor 覆盖；rewrite.ts:87-88（R70-3）单独补过 spawn 检查且注释自认「全库互斥矩阵其余各面均纳入 spawn」——反证唯此面漏。
- 影响：手动写稿（分钟级）在途时生成细纲/账本草稿照常放行，覆盖写与写稿并发 → 后续章拿到混合态上下文（双费 + 机检误报红），正是 R67-13 修复注释要防的场景。
- 修法：函数内补 `if (isSpawnRunning(bookName)) return '本书正在手动写稿…'`（import 先例：chat/self-heal 同为 ai 层向下引用）。

### D-2（P2）outline / lead-updates 覆盖写无留底——作者手改静默丢失（R71-9 同型遗漏）
- 位置：`src/studio/server/api/outline.ts:96`（atomicWriteFile 细纲.md 无 snapshotBeforeOverwrite）；落盘点 `src/process/lead-update-draft.ts:125`（账本推进.md 同）
- 亲验：onboard.ts:141-146 有 R71-9 快照留底先例（复用 draft 侧 snapshotBeforeOverwrite，fail-open）；且 `files.ts:38` `WORKDIR_EDITABLE = {'工作区/细纲.md','工作区/账本推进.md'}` 两文件恰是作者可经 PUT /file 手改的白名单文件，/file 与 outline 闸互不相查。
- 影响：outline 生成（分钟级）窗口内作者保存手改细纲 → 完成后覆盖 → 手改丢失且无恢复链。
- 修法：outline 落盘前对齐 onboard.ts:141-146 调 snapshotBeforeOverwrite（'outline-overwrite'）；lead-updates 共享函数或端点侧同款。

### F-1（P2）ci.yml 自动触发全摘——整套 CI 门禁当前仅手动可达
- 位置：`.github/workflows/ci.yml:3-8`（`on:` 仅 `workflow_dispatch:`）
- 亲验：注释自认「2026-08-28 两步收窄……push/PR 自动触发全部摘除，CI 只走 workflow_dispatch 手动跑……频推期结束后恢复 push 腿」。
- 影响：10+ 道门（typecheck/coverage 阈值/counts/knowledge/packaging/e2e）在合入路径零自动执行；频推期结束后无恢复锚（无到期提醒/issue）。本链历史多次命中「门名存实亡」判例，此为其反向变体。
- 修法：至少恢复 `pull_request` 腿；或在总览登记带日期恢复项 + dispatch 跑时打印「手动模式已 N 天」提示。（此项与总览已登记的「CI 自动触发暂关敞口」同一事项，本轮升 P2 供拍板。）

### F-2（P2）win 腿 Electron 冒烟断言弱于 mac——只判存活不验启动链
- 位置：`.github/workflows/desktop.yml:156-172`（win pwsh 块仅 `HasExited` 判定）；mac 腿 128-153 行为三重判（存活 + `[CLW_SMOKE] ready` 标记 + 无 renderer-crash）
- 亲验：两段对照属实；标记为 ASCII 结构化 stdout，win 用 `Start-Process -RedirectStandardOutput` 即可同等捕获，弱化无技术必要。R73-53 已论证「进程存活≠启动链走完」。
- 影响：win 是 2026-08-28 新启用的发布目标（NSIS exe），其打包态唯一自动化验证弱于 mac。
- 修法：win 冒烟对齐 mac 口径（重定向 stdout + grep ready/renderer-crash）。
