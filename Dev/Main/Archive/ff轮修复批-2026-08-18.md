## 一、批 0（立即）：CI 门恢复——P1-2 修复 + 推送

**问题**（ff-P1-2，亲验）：`test/export/export.test.ts:302-319`（X-P2-4 用例）fixture 用 `'长'.repeat(120)` 作章标题，`writeLongChapter` 以标题直接构造源文件名（`写作/正文/1-<标题>.md`）→ 单段 ≈362 字节，超 ext4 255 **字节**上限 → ubuntu 腿 fixture 阶段即 ENAMETOOLONG（macOS APFS 按 255 字符判，本地恒绿）。origin/dev CI 自 2026-08-15 连红 5 次；本地领先 12 提交未推送，dd 清偿 / ee 修复 / Responses 批从未被 CI 验证。

**修法**：

1. fixture 改混合码位标题：`'长'.repeat(60) + 'a'.repeat(60)`——仍是 120 码位（>80 触发截断、断言语义不变），但源文件名字节 = 2+240+3 = 245B ≤ 255B，Linux 可移植。既有断言（截后 86 码位 / 内容标题完整）不动。
2. 新增字节上限断言：`Buffer.byteLength(names[0]) <= 255`，把可移植性锁进测试。
3. **FF-F3 生产加固（建议顺批）**：`src/export/index.ts:95` 按 80 码位截断对 astral 字符最坏 80×4=320B 仍超 ext4——截断追加字节感知回退（超 ~240B 时在 UTF-8 序列边界安全缩短，不切多字节中间），新增 emoji 标题用例（4B×80 → 截后 ≤240B）。

**动作序列**：本地全量回归（HEAD 基线 245 文件/2257 用例）→ 提交 → **推送 12 提交** → `gh run watch` 盯 origin/dev 首次全绿，特别验证 ubuntu·24 腿覆盖率门（dd 轮接线后从未在 origin 绿过）。

## 二、批 1（P1-1）：批量定稿防吃书闸单源化（含 P2-5 顺带）——半天量级

**问题**（亲验结构）：兑现侧闸 `finalGateBlockers`（`src/document/finalize.ts:144-156`）读账本声明只走 `readChapterLeadUpdates`（`src/check/lead-updates.ts:33-36`，**只读主文件** `工作区/账本推进.md`）；回写侧 `applyLeadUpdates`（`src/document/lead-finalize.ts:36-47`）读「主文件（`readLeadUpdateChapterTag` 章号标签匹配）+ 本章归档 `.账本推进暂存/第N章.md`」**双源**。自动连写场景：细纲推进到 N+1（声明侧空）+ 第 N 章账本已归档（闸读不到）→ 归档里未声明条目（幻觉/越权）绕闸静默入账履历。反向：主文件载别章条目若证据碰巧命中被检章正文，闸误拦。

**修法**（四步，闸与回写数据源对称）：

1. `src/check/lead-updates.ts` 新增导出 `readChapterUpdatesForChapter(bookRoot, chapterNo): ChapterLeadUpdate[]`——「某章的账本声明」**唯一真相源**：主文件（标签匹配本章或无标签旧格式）+ 本章归档合并。
2. `LEAD_UPDATES_ARCHIVE_DIR` 常量归一：现 `lead-finalize.ts:26` 与 `process/lead-update-draft.ts:28` 两份重复定义，收拢到 check/lead-updates.ts，两处改 import。
3. `finalGateBlockers` 兑现侧换用该函数（`leadEvidenceMatchesBody` 过滤 + `leadClosureItems` 比对逻辑不动）。双向效果：归档未声明条目 →「做了没声明」红 → LEAD_GATE 阻断；主文件别章条目不再进入本章闸 → 误拦消除。
4. `applyLeadUpdates` 双源读取换用同一函数（P1-1 根因闭合）；**顺带 P2-5**：`findLeadFile` 每条 update 全目录重扫六类账本（`lead-finalize.ts:57-59`）→ 每次调用先单扫一次建 `Map<编号, {filePath, lead}>` 全体复用，批量定稿 N×M 放大消除。

**顺序保证**：finalize 中闸（:74-79）先于回写（:105-115），闸拦截则回写不执行——「越权拒绝回写报 LEAD_GATE」由该顺序天然成立，**不在 applyLeadUpdates 内加第二套校验**（FF-F2：避免口径分叉）。闸整体 fail-open（自故障不锁死作者）维持 ee 轮既定哲学不改。

**回归用例**（≥3 新增）：

- ① 探针场景固化（ff 分域复现过的旁路）：细纲推进到第 2 章（声明侧空）+ 第 1 章归档含未声明 `悬念-002 递进`（证据在第 1 章正文命中）→ finalize 第 1 章 → **LEAD_GATE 阻断、履历不入账**；
- ② 误拦消除：主文件载第 2 章标签条目、定稿第 1 章 → 放行（旧代码误拦的反例）；
- ③ 正向不回归：归档声明+兑现 → 履历入账 + 归档清理；ee 轮既有 5 用例（ee-P1-3/4）仍绿。

**评估项（不承诺本批）**：self-heal「机检 pass 后生成账本草稿 → 复跑一次 check」收口动作；`check/run.ts:133/217` 机检侧是否同样切章级单源（batch 路径已显式传参、报告路径主文件读取，需批量流语义分析后定）。
