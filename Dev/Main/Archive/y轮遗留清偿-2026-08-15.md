## 一、G1 分支 UI（regenerate + 分支切换）

### 现状（锚点已核实）

| 能力 | 后端 | 前端 |
|---|---|---|
| 重新生成 | `POST /api/books/:name/chat/regenerate`（`src/studio/server/api/stream.ts:353`，要求 parentSeq + branchId，走 sendChatMessage 队列） | **零调用** |
| 分支重建/列举/切换 | `buildBranchTree` / `listBranches`（`src/events/branch-tree.ts:52/81`）/ `selectBranch`(:124) / `selectBranchTo`(:155) 纯函数就绪 | **零调用，且无 HTTP 端点暴露** |

前端落点：`src/studio/web-next/src/api/chat.ts`（api client）、`src/studio/web-next/src/stores/chat.ts`（295 行）、`src/studio/web-next/src/components/panels/ChatPanel.vue`（683 行）。

### 实施要点

1. **后端两件**（模式照抄 chat-history.ts：纯函数视图 + defineRoute 薄接线；E2 增量纪律——新路由必须 defineRoute）：
   - `GET /api/books/:name/chat/branches`（`chat.branches`）→ `{ branches: BranchInfo[], activeBranchId }`——`openSessionStore` → `listEvents` → `buildBranchTree` + `listBranches`，与 history 端点同源同生命周期（try/finally close）；
   - 历史视图带分支维度：`chat.history` 扩展可选 `?branch=<branchId>`（或并列新视图）——先 `selectBranch(events, branchId)` 再投影，并附每条消息的 seq（parentSeq 的来源）。
2. **chat store**：消息模型加 `seq?` / `branchId?`；新增 `activeBranchId` 状态与 `switchBranch`（拉分支视图替换 messages，代数守卫沿用 seedHistory 惯例：空/非 running/await 后二次校验）；新增 `regenerate(parentSeq)`——调 regenerate 端点后由现有 SSE 流接管（assistant 占位复用现有 push 路径）。
3. **ChatPanel**：assistant 消息 hover/尾随操作「重新生成」（对话进行中禁用，409/queued 语义透出）；同一 parentSeq 变体组 >1 时显示切换器（◀ 2/3 ▶，调 switchBranch）；分支列表入口可后置（切换器先满足主路径）。
4. **回归锚**：`selectBranch` 线性兜底（branch-tree.ts:142-147）对「无 branchId 事件」的保留语义——旧线性书切换/刷新不得丢消息，固化为单测；三视图 `:key="bookName"`（Y-P2-3）同口径适用于分支视图刷新。

### 验收

- 单测：branches 端点视图（多分支/线性书/空库三态）+ store switchBranch/regenerate（含竞态守卫）；
- 组件测或手测路径：发起对话 → 重新生成 → ◀▶ 切换 → 刷新恢复，默认分支正确；
- 无独立 chat e2e spec（现状），不强制新增——若 UI 面复杂可补 `chat-branch.spec.ts`。

### 收口记录（2026-08-16）

**交付**：`api/chat-branches.ts`（新）+ `chat-history.ts`（`?branch=` + seqs + branchId）+ `server/index.ts` 注册；`events/chat-bridge.ts`（toolResultEvent 扩 branchId）+ `orchestrate/chat.ts`（regenerate 回合 tool-result/收尾 assistant 补 branchFor 入组）；`branch-tree.ts` selectBranch 线性兜底改为保留 root 前后全部无分支事件；web-next：`api/chat.ts` + `stores/chat.ts`（seq/activeBranchId/branches/switchBranch/regenerate/防重入/竞态守卫）+ `ChatPanel.vue`（重新生成按钮 + ◀ i/n ▶ 切换器）。

**关键实现决策**：① history 默认视图 = `selectBranch()` 默认分支（最新变体组+祖先链+线性）——修复「全量流把各变体堆叠」；② 实施中发现并修复：分支后普通续聊（无 branchId、seq>rootSeq）会被旧线性兜底丢出视图（刷新即丢消息）→ 兜底改为全量保留线性事件（兼清 y 轮 Y-P2-7 子项「selectBranch 线性兜底丢弃」的丢消息面）；③ 每次重新生成由前端生成新 branchId（变体组语义）。

**回归**：216 文件 / 1930 单测全绿（+31：branches 9 + 编排 2 + store 19 + branch-tree 1）；e2e 35 过 + 2 门控跳过（基线不变）；`tsc` + `vue-tsc` 0 错；`check:counts` 通过（README 1899→1930 / 215→216）。

**已知余留（不阻塞，后续批处理）**：compaction/end（压缩存档/失败遮蔽载体）不带分支元数据，极端情况下分支视图缺存档节点；tool/call 审计事件不入组（分支重放缺工具调用参数审计，无投影影响）；`messageCount` 按组内全部事件计数（带工具的重新生成计 3+，仅展示口径）；切换器导航首尾循环（非端点禁用）；regenBook 残留书名（无害，仅防重入内部态消费）。

### 收口记录（2026-08-16）

readJson 定义实际在 `src/studio/server/http.ts`（非 io.ts）。**交付**：① 超限分支不等 `end` 当场 reject 413 并**排空收口**（removeAllListeners + resume 丢弃剩余数据）——集成时发现同步 `req.destroy()` 会抢在 413 响应刷出前掐断 socket（客户端收到 ECONNRESET 而非 413），排空方案既防悬挂连接占 FD 又不吞错误响应（既有 `api-token.test.ts` 413 用例回归绿锚定）；② static.ts 命中文件 + SPA fallback 两处 200 写头点补 Cache-Control——判定 `路径.startsWith('/assets/')` → `public, max-age=31536000, immutable`，其余 `no-cache`（URL 层路径恒 `/` 分隔，穿越路径天然不命中走保守分支）；③ preload.ts onNavigate/onMenuAction 具名 handler + 返回退订函数，`web-next/src/desktop.d.ts` 签名同步 `=> () => void`。+2 测试文件 4 用例（超限立即 413 不依赖 end / assets immutable / index.html·favicon·SPA fallback no-cache）。**余留**：前端调用方尚未消费退订函数（返回函数为兼容性新增，useNativeMenu 等未接）。
