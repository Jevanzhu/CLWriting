### 5.1 P2（10 条，全部主评审亲验属实）

**R76-1（C 域）元数据 PATCH 双路径游离于保存协议之外，跨进程并发可整篇丢正文。**
`src/document/service.ts:507-545`（updateChapterMeta）、`src/document/service.ts:640-695`（updateDocMeta）。两路径均为 `readDoc/readFileSync → patchFlatFm → atomicWriteFile(fm+旧正文)`，全程**不取 `<journal>.save.lock`、不写 journal pending、不做 revision 基线校验、不留快照**（代码注释自认「本路径无快照留底」，service.ts:519-520）；对照 executeSave 在 `service.ts:295` 取跨进程 save 锁（5s fail-closed）。API 层（documents.ts PATCH）亦无锁兜底。失败场景：GUI（dev:app）与 dev:api 双进程同书——进程 A executeSave 落盘新正文 C2（journal settled、快照是 C2 前的旧版），进程 B 恰在此间 PATCH meta（B 读到旧正文 C1，写回 fm+C1 后于 A 落地）→ 终态 = 新 fm + 旧正文，**C2 永久不可恢复**。窗口为 B 的 read→write 毫秒级，同进程因 JS 单线程同步执行不触发，纯跨进程问题；项目明确支持双进程形态（R75-5 busyGate 即为此场景）。修法方向：两路径同样包 save 锁（5s fail-closed）即可闭合，无需 journal。〔主评审亲验：两路径源码逐行核实无锁；executeSave 对照〕

**R76-2（C 域）快照安全网覆盖面窄于 README 宣称：非章节文档零快照 + 章节同 origin 5 分钟节流。**
`src/document/service.ts:394-399`（maybeSnapshot 的 reason 判定：仅 restore/external-merge 覆盖前必留 + 章节文档〔且 expectedRevision 非空〕首改留底）、`src/document/version.ts`（同 origin 5 分钟节流）。README 宣称「每次保存前自动留快照」「章节历史面板里能恢复任意一版」——实现为「restore/merge 覆盖前必留 + 章节首改（节流采样）」，**设定/大纲/布线/关系线等非章节文档的普通保存完全不留快照**（journal pending 只记新内容，settled+compact 后旧内容零副本）；节流窗口内的中间版本同样不可恢复（「任意一版」实为「节流采样点」）。属注释写明的有意设计，但与产品宣称直接冲突。修法方向：改宣称或给非章节文档至少保留最近 N 版。〔主评审亲验：maybeSnapshot 判定链亲读，与 R75-3 diff 注释「maybeSnapshot 只留底章」互证〕

**R76-3（B 域）checkNewNames 句读守卫被上游清洗中和成死代码，混排行短对白系统性误报「新专名候选」。**
`src/check/count.ts:231,259,262`——`punctRe`（含全部句读）在 259 行 `q.replace(punctRe,'')` 先把句读剥净，262 行 `spanPunctRe.test(name)` 恒 false，注释宣称的「含句读的片段是对白内容」守卫失效。三条豁免（冒号引语/attribution-only/说话归属）只覆盖「整行是对白」形态，**动作+对白混排行（网文最高频行式）全部穿透**。主评审 tsx 实测复现：`他低声道：「别动。」然后按住她的肩。` → `新专名候选「别动」`；`她喊着「快走，掩护」头也不回地冲了出去。` → `「快走掩护」`。后果：每章数十条伪候选刷屏三审报告，真新名被淹没。修法方向：守卫改在剥引号后的原文上判句读（或豁免口径扩到混排行）。〔实测复现记档〕

**R76-4（B 域）parseBannedWordsLine 引号词抽取窗口 {2,24} 外的禁词静默失明。**
`src/format/style-entry.ts:225,246-258` + `src/check/count.ts:81-89`——单字引号词不中 `{2,24}` 分支，落入兜底清洗后**带引号整行落词表**，`checkBannedWords` 用 `body.includes('「地」')` 永不命中（正文不带引号书写时），且因「解析成功」不进 unparsedBannedEntries（R73-15 失明提示不触发）。主评审 tsx 实测：`「地」` → `["「地」"]`；`禁用「了」开头的句式` → `["禁用「了」开头的句式"]`（整行成词，同因失明）；25+ 字长引号句 → `[]`（该侧有 unparsed 黄项兜底）。失败场景：作者写单字禁词（网文禁「了」开头类真实规则）——红闸对该条目静默失效、零提示，与「报红自动打回」宣称冲突。修法方向：窗口外侧剥引号后仍入词表（或长度下限放宽至 1、超长入 unparsed）。〔实测复现记档〕

**R76-5（A 域）备料补漏 AI 调用不受编排级中断传播。**
